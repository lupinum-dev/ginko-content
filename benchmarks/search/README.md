# Search engine benchmark

This benchmark compares MiniSearch and Orama against search records generated by
Ginko itself. It measures relevance, serialized index and browser runtime size,
initial indexing and restoration time, engine-core p95 query time, Ginko
end-to-end p95 (including lookup and excerpt shaping), approximate retained heap,
and locale isolation.

Run the complete reproducible benchmark from the repository root:

```bash
pnpm benchmark:search
```

The command builds the package, the documentation site, and the localized
playground before benchmarking their generated search artifacts. It reads the
emitted JSON index when present; otherwise it resolves Nuxt's configured
`buildDir` and derives records from the generated content snapshot with Ginko's
production record-shaping functions. Locale filtering happens inside each
adapter so the harness cannot hide an engine's locale behavior. Machine-specific
JSON and Markdown reports are written to `.benchmarks/search/`, which is ignored
by git. Golden queries live in `golden-queries.json` and should only contain
queries with a defensible expected destination in the generated corpus.

Timing and heap numbers are comparative signals, not release gates. Relevance
and locale isolation are correctness signals. A backend is not admitted merely
because it wins a microbenchmark: it must materially improve the current product
without adding another permanent engine or a second search-result contract.
