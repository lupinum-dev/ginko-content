# Ginko Content 1.0 readiness: findings register

The execution plan is [README.md](README.md). This file is the evidence register; each finding's closing step is in the README's "Finding coverage" table.

Single list of everything found during the 1.0 audit. Base: `origin/main` at
`a3e8ef1` (v1.0.0-beta.10). Owner of this list: Opus. Codex reports are merged
here only after a check against the code.

Tags: **B** = 1.0 blocker, **F** = cheap fix before 1.0, **L** = after 1.0,
**D** = needs a decision by Matthias. Status: open / confirmed / fixed / dropped.

## 1.0 release criteria (proposed)

1. **API**: every public export has a written reason, one way per job, consistent names; the API report is frozen.
2. **Real use**: the demos and the 3 consumers (ginko-cms, ginko-editor, ginko-docs) run on the packed RC without workarounds or deep imports.
3. **Architecture**: one source of truth per concept; no port leftovers; `internals/migrations.md` empty or each entry has a removal date.
4. **Budgets** measured and enforced in CI: client JS per demo, build time per N documents, query latency, search index size.
5. **Search**: a fixed query set returns the expected top results; keyboard and a11y work; latency is good on the live site.
6. **Live**: every public feature claim is shown by a deployed demo and passes a browser check (desktop and mobile), production builds included.
7. **Docs**: quickstart works from zero in under 10 minutes; every export is documented; migration guide from the betas.
8. **CI**: PR feedback in under ~10 minutes; every test names the bug it catches; no flaky tests.
9. **Stability promise**: written semver + deprecation policy; supported Nuxt/Vue/Node ranges tested.
10. **Security**: audit clean; CodeQL and dependency policy pass.

## Findings

### A. Architecture and API

| ID | Tag | Finding | Evidence |
|---|---|---|---|
| A-01 | D | **Two extension contracts for one job.** `ContentDataSource` (`./data-source`) is the author-facing contract: framework-free context, abort signal + deadline, bounded results, cache hints. `bindContentProvider` (455 lines) adapts it to `ContentProvider` (`./provider`), the H3-event contract the module calls. ginko-cms writes a `ContentDataSource` and binds it (`packages/cms/src/nuxt-provider.ts`, `nuxt-provider/data-source.ts` on `codex/cms-overnight-integration`). Both are public, each with its own cache-hint type, error factory and contract kit. **Recommendation:** `ContentDataSource` becomes the only public extension contract; the module binds it itself (users register a data source, not a provider); `ContentProvider`, `bindContentProvider`, `testing/provider-contract` and `testing/provider-fixture` become internal; one cache-hint type and one error factory remain. Removes 2–3 entry points. | `src/public/{provider,data-source,provider-binder}.ts`; ginko-cms usage |

| A-08 | D | **Two ways to name a collection**: an imported handle (`useContentPage(pages)`, documented on main) and a string name (`useContentPage('pages')`, introduced by unmerged `feat/kit-v2`). Importing the handle into a component ships the config module, Zod and every schema to the browser. 1.0 should have one recommended way; names for app code look right, handles maybe only in server/config code. | `feat/kit-v2` commit `79375f7` message and docs diff |
| A-09 | F | **Every catch-all page needs `definePageMeta({ key: route => route.path })`** boilerplate, and every page re-implements the 404 branch. Check whether `useContentPage` can own route-change reactivity so the key is not needed; consider a documented helper for the 404 policy. | README quick start, `docs/.../1.quickstart.md` |
| A-10 | D | **Language switch in a shared header needs an expert pattern**: `layout: false` + manual `<NuxtLayout>` + passing the page result as a prop + `useContentLocalePath(..., { fallback: useSwitchLocalePath() })`; the docs warn against global state. i18n is a core promise, so the common case must be one line. Option: on page resolve, feed the alternates to `@nuxtjs/i18n` through its official `useSetI18nParams` (SSR-safe), so the standard `useSwitchLocalePath()` works in any header and `useContentLocalePath` becomes an advanced escape hatch. | `docs/content/docs/5.reference/5.composables.md` "Put language links in a shared header" |
| A-11 | D | **Page boilerplate per catch-all route** is ~6 lines (`definePageMeta` key, `status === 'error'` rethrow, `status === 'not-found'` → `createError(..., fatal: true)`), repeated in every app and every docs example. Policy-free is a stated goal, but the default most sites want is "404 on not-found, rethrow on error". Option: `useContentPage('docs')` throws those by default, `{ notFound: 'return' }` opts out. Decide together with A-09. | same page, quickstart |
| A-12 | D | **Default-on features**: `i18n`, `sitemap` and `agent` (routes, link headers, negotiation middleware) are on by default. | A-13 | F | `componentPolicy` is typed `PortableComponentPolicyV1` in the module reference although V2 exists; 1.0 should document only the current version and drop V1 names from public types if no persisted data needs them (check ginko-cms stored data first). | same table; G-02 |
| A-14 | D | **Heading-ID scheme surprises authors.** A leading digit gets an `_` prefix (`## 1. Create the deployment` → `#_1-create-the-deployment`; HTML5 ids may start with a digit, GitHub gives `#1-create-the-deployment`), and level-3+ headings are prefixed with the parent heading's id. Authors write GitHub-style anchors, so links break: ginko-kit has 3 broken anchors from exactly this. Anchors are a public URL contract, so 1.0 must settle the scheme. The open, uncommitted `feat/unicode-heading-anchors` work rewrites this file (`heading-id.ts`, +93/−14). Recommendation: GitHub-compatible slugs (Unicode letters kept, no `_` prefix, flat with `-1` dedupe). | `core/markdown/heading-id.ts:16-26,65`; `.audit/consumers/ginko-kit-heading-evidence.json` |
