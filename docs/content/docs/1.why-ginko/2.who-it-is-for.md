---
title: Who Ginko Is For
description: Ginko fits small-to-medium Nuxt content sites maintained in files and Git by developers or technical authors.
---

Ginko fits teams that want content to behave like part of the codebase: versioned, reviewed, validated, and deployed through the same workflow.

## Good project fits

Ginko is centered on:

- documentation sites;
- blogs and changelogs;
- marketing sites with substantial structured Markdown;
- multilingual guides and references;
- content-heavy Nuxt applications with a few hundred documents;
- projects that prefer static or server-rendered output without content infrastructure.

The filesystem provider should remain reasonable around 2,000 Markdown documents, depending on document size, locale count, search mode, and deployment target. This is a product center of gravity, not a hard parser limit.

## Good team fits

Ginko works best when:

- developers or technical authors edit files in an IDE;
- Git provides history, review, and rollback;
- branches provide draft environments;
- content changes can follow the deployment pipeline;
- the team wants schemas and application code to evolve together.

Non-technical authors can still work through Git-backed tools, but Ginko core does not ship a browser editor or workflow UI.

## Good technical fits

Choose Ginko when the application needs several of these together:

- typed frontmatter with Zod;
- route-aware page loading;
- Markdown and MDC rendering;
- navigation and previous/next links;
- MiniSearch or Pagefind;
- first-class locale fallback and translated slugs;
- sitemap and prerender integration;
- an external-provider path that preserves the application API.

## Fit checklist

Ginko is likely a good choice when all of these statements are true:

1. Nuxt 4 is the application framework.
2. Files are an acceptable default content source.
3. The project values operational simplicity over database-scale querying.
4. Content routes should be explicit and typed.
5. Browser editing is optional or belongs to another product.

If one of those assumptions is false, read [When not to use Ginko](/docs/why-ginko/when-not-to-use-ginko) before adopting it.
