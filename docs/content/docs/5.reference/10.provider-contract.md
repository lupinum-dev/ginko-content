---
title: Provider Contract
description: Implement the server-side content provider contract.
---

Providers are server adapters behind Ginko's public content APIs. The
filesystem provider is the default; remote systems implement the same raw
document and route-fact boundary.

## Register a provider

```ts [content.config.ts]
export default defineContentConfig({
  provider: 'custom',
  providers: {
    custom: '@acme/content-provider'
  },
  collections: { docs }
})
```

## Implement the contract

```ts [server/provider.ts]
import type {
  ContentProvider,
  ProviderDocumentInput
} from '@lupinum/ginko-content/provider'

export default {
  name: 'custom',
  capabilities: {
    query: {
      operators: ['$eq', '$in'],
      pagination: ['offset']
    }
  },
  async query(event, query) {
    switch (query.plan.mode) {
      case 'count':
        return { result: await countDocuments(query) }
      case 'first':
        return { result: await loadFirstDocument(query) }
      case 'all': {
        const page = await loadDocuments(query)
        return {
          result: page.items,
          skip: query.plan.paging?.mode === 'offset'
            ? query.plan.paging.skip
            : query.plan.skip,
          limit: query.plan.limit ?? 100,
          total: page.total
        }
      }
    }
  }
} satisfies ContentProvider
```

Only `query` is required. Navigation, surroundings, provider-owned search,
site data, and route enumeration are enabled by implementing the corresponding
method. There are no operation capability booleans.

## Return raw documents

Query rows use `ProviderDocumentInput`:

```ts
const row: ProviderDocumentInput = {
  collection: 'docs',
  canonicalKey: 'docs:intro',
  locale: 'de',
  contentPath: '/dokumentation/einstieg',
  routeVariants: [
    { locale: 'en', contentPath: '/docs/intro' },
    { locale: 'de', contentPath: '/dokumentation/einstieg' }
  ],
  body: { type: 'root', children: [] },
  title: 'Einstieg'
}
```

`contentPath` includes the collection's locale-specific mount and excludes the
Nuxt locale prefix. It must be a leading-slash, site-relative pathname;
absolute URLs, query strings, fragments, backslashes, and traversal segments
are rejected. Core derives `route`, `resolution`, public paths, and alternates.
For a collection-scoped query, every row's `collection` must match
`query.collection`. Return only `routeVariants` visible for the current request. When
the query plan contains `variantSelector`, return its first matching candidate
in order; that successful route match is what lets core label the current
fallback route without guessing. Do not return projected path metadata from
the provider. Multi-locale `routeVariants` require an explicit, locale-agnostic
`canonicalKey`, and the entry for the row's `locale` must match its
`contentPath`. Core rejects provider-authored `path`, `variants`,
`localePaths`, `unprefixedPath`, `dir`, `resolved`, `route`, and `resolution`
metadata.

`normalizeProviderDocument()` fills derivable identity fields. Its output is
also valid provider query input: the derived `path` is accepted only when it
exactly equals normalized `contentPath`. Structured JSON, YAML, and CSV bodies
must be JSON-pure; Markdown bodies must be a root Markdown AST or `null`.

## Return raw route facts

Navigation, surroundings, search, and route enumeration share one route fact:

```ts
const route = {
  collection: 'docs',
  canonicalKey: 'docs:intro',
  locale: 'de',
  contentPath: '/dokumentation/einstieg'
}
```

Navigation returns `{ title, route, children? }`. Surroundings returns an array
of `{ title, route } | null`. Provider search returns
`{ title, excerpt?, score, route }`. `routes()` may add `draft` and `sitemap`
metadata; Ginko applies include/exclude, visibility, and URL policy afterward.
Any additional selected fields on navigation, surroundings, search, or route
records must also be JSON-pure.

## Query capabilities and visibility

Provider and conformance tooling can lower a programmatic query with
`toContentProviderQuery(input)`. Its `ContentProviderQueryInput` type is
exported from `@lupinum/ginko-content/provider`; application reads should use
the higher-level `one`, `many`, and `paginate` APIs instead. The lowerer rejects
unknown keys and malformed filter, selector, terminal, and paging shapes before
creating the provider wire envelope.

Provider queries use wire version 3. There is no v2 negotiation or compatibility
dispatch, and `$nin` is a native comparison operator. Every advertised operator
and pagination mode must be executable. `offset`
permits skip and exact totals; `cursor` returns an opaque cursor page without a
synthetic total. Count requires `offset`. Logical filter nodes are v3 wire
structure that every provider interprets rather than separately advertised
capabilities.

Providers also execute ordered `plan.sort` clauses and the `first` terminal
mode; providers advertising offset pagination execute `count`. When no sort is
present, result order is provider-defined. Specify a sort whenever pagination
or presentation needs deterministic order. Projection is an optional provider
pushdown: return the raw identity fields required for validation, and core will
apply the public `select` shape after validation.

Offset responses must echo the requested `skip` and `limit` exactly. A smaller
offset limit would make the next page skip unseen documents. Cursor responses
may return fewer rows because `pageInfo.endCursor` remains the continuation
authority.

`ContentProviderQuery` does not carry the filesystem provider's preview policy.
A third-party provider owns published-versus-preview selection and can derive
its authenticated preview context from the `H3Event` passed to `query()`.
Apply that policy consistently to list, first, and count execution; Ginko does
not fetch every provider row and filter unpublished query results afterward.

## Site data

`siteData()` returns `{ data, updatedAt? }`. `data` is required and must be a
JSON value or `null`; omit absent `updatedAt` metadata rather than returning
`null`. The request remains the sole source of truth for `key` and `locale`.
Ginko validates timestamps and JSON purity before returning a response whose
identity is derived from that request. The lower-level data-source contract
still echoes key and locale so the binder can validate a remote boundary.

## Cache hints

Use `withContentCache()` around any operation result:

```ts
return withContentCache(result, {
  tags: [`collection:${collection}`],
  maxAge: 300,
  swr: 60
})
```

The wrapper cannot collide with content fields named `data` or `cache`.
Publish events send tags and paths to the configured `ContentCacheAdapter`.
Providers report dependencies; they do not own a second invalidation hook.

## Provider-owned search

Set `content.search.engine: 'provider'` and implement `search()`.

## Conformance

Use `runProviderContractSuite()` from
`@lupinum/ginko-content/testing/provider-contract`. Supply one query probe per
advertised operator and pagination mode, plus result-asserting probes for sort,
`first`, each mandatory `and`, `or`, and `not` filter node, and `count` when the
provider advertises offset pagination. The suite also validates canonical query
envelopes and raw documents, `routes()` facts, and optional method presence.

Maintainers changing this contract should also follow the repository checklist
in `packages/content/docs/PROVIDER_CONTRACT.md`.
