title: Module options
description: The `content` key in `nuxt.config.ts`.
---

Most schema and document-shape configuration lives in `content.config.ts`. The `content` key in `nuxt.config.ts` controls runtime behavior, navigation, i18n wiring, sitemap integration, and markdown parsing options.

## Shape

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/ginko-content'],
  content: {
    // options here
  }
})
```

## Options

| Option | Type | Purpose |
|---|---|---|
| `api.baseURL` | `string` | Base URL for the content API |
| `watch` | `false \| { ws }` | Control content watching in dev |
| `sources` | `Record<string, MountOptions>` | Add filesystem or remote content mounts |
| `ignores` | `string[]` | Exclude files from parsing and watching |
| `markdown` | `object` | Ordered Comark plugin configuration plus anchor-link behavior |
| `links` | `Record<string, Record<string, { route: string }>>` | Writer-facing markdown quick links to Nuxt route names |
| `navigation` | `false \| { fields: string[] }` | Enable navigation and expose extra nav fields |
| `i18n` | `boolean \| object` | Locale-aware content behavior |
| `search` | `false \| object` | MiniSearch, Pagefind, or provider-owned search configuration |
| `validation` | `'report' \| 'error'` | Persist authored-link findings, optionally failing the build before snapshot publication |
| `sitemap` | `boolean \| object` | Content sitemap source registration, filtering, and optional build assertions |
| `agent` | `false \| object` | Agent-readable markdown routes, link headers, negotiation middleware, and prerendering |
| `preview` | `false \| { token: string }` | Filesystem-provider draft/partial visibility token; see [Preview](#preview) |
| `revalidate` | `false \| { token: string }` | Enable authenticated CMS cache revalidation |
| `cache` | `false \| string` | Server-side cache adapter module specifier |
| `respectPathCase` | `boolean` | Keep uppercase characters in generated paths |

## navigation.fields

Expose extra frontmatter fields on navigation nodes:

```ts
content: {
  navigation: {
    fields: ['badge', 'icon']
  }
}
```

## markdown

Markdown behavior stays in `nuxt.config.ts`:

```ts
content: {
  markdown: {
    plugins: [
      'toc',
      ['highlight', { theme: 'github-dark' }],
      'summary'
    ],
    tags: {
      code: 'ProseCodeInline',
      img: 'ProseImg',
      pre: 'ProsePre'
    },
    image: 'auto',
    anchorLinks: {
      depth: 4,
      exclude: [1]
    }
  }
}
```

`markdown.plugins` is ordered. Ginko resolves built-in Comark plugins in the order you declare them.

`markdown.image` controls the default Markdown image renderer:

| Value | Behavior |
|---|---|
| `'auto'` | Use `<NuxtImg>` when Nuxt Image is available, otherwise render `<img>` |
| `'img'` | Always render native `<img>` |
| `'nuxt-image'` | Render `<NuxtImg>` |

Removed MDC-era options are not supported:

- `content.highlight`
- `content.markdown.mdc`
- `content.markdown.remarkPlugins`
- `content.markdown.rehypePlugins`
- `content.markdown.toc`

Use `content.config.ts` for collections and content-model configuration.

## links

Use `content.links` for markdown links to app-owned routes:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  i18n: {
    customRoutes: 'config',
    pages: {
      pricing: {
        en: '/pricing',
        de: '/preise'
      }
    }
  },
  content: {
    links: {
      main: {
        pricing: { route: 'pricing' }
      }
    }
  }
})
```

Authors can write:

```md
[Pricing]($main.pricing)
```

`route` is a Nuxt route name passed to Nuxt I18n's `localePath()` resolver.
Keep translated paths in `i18n.pages`; do not duplicate `/pricing` and
`/preise` in `content.links`.

## i18n

Use `content.i18n` for runtime locale behavior:

```ts
content: {
  i18n: {
    defaultLocale: 'en',
    locales: ['en', 'fr'],
    fallback: {
      fr: ['en']
    },
    translatedSlugs: true,
    strictTranslatedSlugs: true
  },
}
```

`translatedSlugs` is opt-in. `strictTranslatedSlugs` escalates translated-slug warnings, such as missing numeric prefixes, into validation errors for CI.

Set `content.i18n: true` to detect locales from Nuxt I18n and `content.config.ts`.

## search

Use `content.search` to configure the built-in search index:

```ts
content: {
  search: {
    engine: 'minisearch',
    apiBaseURL: '/api/_content/search',
    ignoredTags: ['script', 'style', 'pre'],
    filterQuery: { draft: false, partial: false },
    collections: ['docs'],
    extraFields: ['tags'],
    minisearch: {
      fields: ['title', 'content', 'headings', 'tags'],
      storeFields: ['path', 'title', 'excerpt', 'anchor', 'locale', 'tags'],
      boost: { title: 4, headings: 2, tags: 3, content: 1 },
      fuzzy: 0.2,
      prefix: true
    }
  }
}
```

Search is disabled by default. Set `content.search: {}` to enable the MiniSearch
backend, or choose another engine explicitly.

| Field | Type | Purpose |
|---|---|---|
| `engine` | `'minisearch' \| 'pagefind' \| 'provider'` | Search backend used by `useContentSearch()`. Defaults to `'minisearch'`. |
| `apiBaseURL` | `string` | Base route for the built-in search API. Defaults to `${content.api.baseURL}/search`. |
| `ignoredTags` | `string[]` | HTML tags skipped when content is flattened into search text. Defaults to `['script', 'style', 'pre']`. |
| `filterQuery` | `QueryWhere` | Query `where` predicate applied before records are indexed. Defaults to `{ partial: false }`; draft visibility follows the shared environment/preview policy. |
| `collections` | `string[]` | Collections included in the index. When omitted, route-backed public collections are indexed and data-only collections are excluded. |
| `extraFields` | `string[]` | Extra document fields copied into each search record, for example `tags` or `category`. |
| `minisearch.fields` | `string[]` | Fields indexed by MiniSearch. Defaults to `['title', 'content', 'headings']`. |
| `minisearch.storeFields` | `string[]` | Fields returned with each search result. Defaults to `['path', 'title', 'excerpt', 'anchor', 'locale']`. |
| `minisearch.boost` | `Record<string, number>` | Per-field relevance weights. Defaults to `{ title: 4, headings: 2, content: 1 }`. |
| `minisearch.fuzzy` | `number \| boolean` | MiniSearch fuzzy matching setting. Defaults to `0.2`. |
| `minisearch.prefix` | `boolean` | Enable prefix matching. Defaults to `true`. |

When indexing frontmatter fields, include the same field in `extraFields` and `minisearch.fields`. Add it to `minisearch.storeFields` only when search results need to expose that field to the UI.

Use [Choose a search backend](/docs/guides/discovery/choosing-search) to decide between MiniSearch, Pagefind, provider-owned search, and an external search service.

## validation

Ginko validates filesystem-authored links during the build from the canonical
content graph, projected locale routes, Nuxt's resolved page records, configured
quick links, heading IDs, and mounted asset provenance. External providers own
validation of their authored content.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    validation: 'error'
  }
})
```

The default, `'report'`, writes `<buildDir>/content-cache/validation.json` but
does not fail the build. `'error'` writes the same report, then fails before an
invalid content snapshot can be published. After a build, run
`npx ginko-content validate [root]` to inspect the build-owned report in CI.
The report is derived and rebuildable; it is not another content source of truth.

## Preview

`content.preview` configures a server-side token that gates draft/partial visibility for the **filesystem provider**:

```ts
content: {
  preview: {
    token: process.env.GINKO_CONTENT_PREVIEW_TOKEN
  }
}
```

| Field | Type | Behavior |
|---|---|---|
| `token` | `string` | Shared secret. A request only unlocks preview visibility when it presents this exact token. |

Without a configured token, `content.preview` has no effect. With one configured, a request counts as "preview" when it sends the token as a `previewToken` query parameter, an `x-nuxt-content-preview` header, or a `previewToken` cookie.

Draft and partial visibility rules:

- In `nuxt dev`, drafts and partials are always visible — no token needed.
- Outside `nuxt dev`, drafts and partials stay hidden from `many()`/navigation/sitemap unless the current request is a matching preview request.

This is a development/staging convenience, not a general production preview feature: the filesystem provider only ever reads what is already in the deployed `content/` directory, so `content.preview` cannot reveal content that has not been committed and deployed. See [Drafts and partials](/docs/guides/authoring/drafts-and-partials) for the query-side walkthrough. A workflow that previews genuinely unpublished CMS content is the responsibility of the CMS provider you configure, not the filesystem provider.

## agent

Use `content.agent` to control the Nuxt route plumbing for agent-readable markdown and LLM surfaces declared in `content.config.ts`:

```ts
content: {
  agent: {
    routes: true,
    linkHeaders: true,
    markdownNegotiation: true,
    prerender: true
  }
}
```

Set `content.agent: false` to disable Ginko's agent route handlers and middleware.

| Field | Default | Behavior |
|---|---|---|
| `routes` | `true` | Registers `/raw/**.md`, `/llms.txt`, localized `/:locale/llms.txt`, and full LLM routes. |
| `linkHeaders` | `true` | Adds agent `Link` headers and content-signal headers to eligible SSR responses. |
| `markdownNegotiation` | `true` | Lets dynamic SSR/hybrid routes return `text/markdown` when the request sends `Accept: text/markdown`. |
| `prerender` | `true` | Adds agent markdown and LLM routes to Nitro prerender output when an agent site config exists. |

Same-URL `Accept: text/markdown` negotiation is an SSR/hybrid middleware behavior. It is not a pure static hosting guarantee for already-prerendered HTML files, because a static host can serve `index.html` directly without running Nitro middleware. Static deployments should link to the explicit generated markdown routes instead: `/raw/**.md`, `/:route/index.md`, `/llms.txt`, and `/llms-full.txt`.

### Consumer actions for agent-readable pages

Buttons such as “Copy Markdown” or “Open in Chat” belong in the consumer. Use the
browser-safe path helper and the generated route instead of rebuilding locale or
raw-path rules in a component:

```ts
import { agentRawPathForRoute } from '@lupinum/ginko-content/agent-paths'

const copyMarkdown = async (route: string) => {
  const markdown = await $fetch<string>(agentRawPathForRoute(route))
  await navigator.clipboard.writeText(markdown)
}
```

An “Open in Chat” action can reuse the same URL or copied text, but the vendor
URL, prompt, consent, and analytics stay in the app. Ginko does not ship model
calls, credentials, or chat-provider SDKs.

## sitemap

Use `content.sitemap` with `@nuxtjs/sitemap` to let Ginko register its sitemap source with Nuxt SEO:

```ts
export default defineNuxtConfig({
  modules: ['@nuxtjs/sitemap', '@lupinum/ginko-content'],
  content: {
    sitemap: true
  }
})
```

Or narrow it explicitly:

```ts
content: {
  sitemap: {
    include: ['docs', 'posts'],
    exclude: ['internal']
  }
}
```

Drafts are excluded from sitemap in production by default.

For localized apps, keep static Nuxt page slugs in Nuxt I18n `i18n.pages` and
content document URLs in Ginko. Do not duplicate either set in `sitemap.urls` or
app-owned prerender arrays. See [Sitemap and prerender](/docs/guides/routing-and-seo/sitemap-and-prerender)
for the full ownership model.

Nuxt Sitemap may emit different files depending on the sitemap mode. Single-sitemap apps normally write `.output/public/sitemap.xml`. i18n multi-sitemap apps write `.output/public/sitemap_index.xml` plus child XML files under `.output/public/__sitemap__/`. Under a Node/Nitro preview, `/sitemap.xml` can redirect to the index. Under plain static hosting there is no Node redirect, so submit `/sitemap_index.xml` directly or configure the host redirect explicitly. Do not copy `sitemap_index.xml` to `sitemap.xml`; that hides the actual deployment contract.

You can also turn sitemap output into a release gate:

```ts
content: {
  sitemap: {
    include: ['docs', 'posts'],
    assert: {
      enabled: true,
      mode: 'generate',
      requiredCollections: ['docs', 'posts']
    }
  }
}
```

`content.sitemap.assert` runs after Nuxt Sitemap finishes writing the final XML files. It can fail `build` or `generate` when:

- a sitemap is empty
- a sitemap has fewer than `minUrlsPerSitemap` URLs
- a sitemap is missing images when `requireImages` is enabled
- required collections stop contributing routes

Available assertion fields:

| Field | Type | Purpose |
|---|---|---|
| `enabled` | `boolean` | Turn sitemap assertions on |
| `mode` | `'generate' \| 'build' \| 'both'` | Choose which output path should fail on bad sitemap artifacts |
| `allowEmpty` | `boolean` | Allow empty sitemap XMLs globally |
| `minUrlsPerSitemap` | `number` | Minimum `<url>` count per sitemap |
| `requireImages` | `boolean` | Require at least one `<image:image>` entry |
| `requiredCollections` | `string[]` | Require specific collections to contribute sitemap routes |
| `sitemaps` | `Record<string, ...>` | Override the global rules for one sitemap such as `en-US` or `de-DE` |

## CMS cache

Use `content.revalidate` and `content.cache` when a CMS or custom provider needs to invalidate published routes.

```ts
content: {
  cache: '~/server/content-cache',
  revalidate: {
    token: process.env.GINKO_CONTENT_REVALIDATE_TOKEN!
  }
}
```

`revalidate.token` is required. Without a token, Ginko does not register `/api/_content/revalidate`.

`cache` points to a server module that exports a `ContentCacheAdapter` as its default export, `contentCacheAdapter`, or `cacheAdapter`.

```ts [server/content-cache.ts]
import { setHeader } from 'h3'
import {
  contentCacheHeaders,
  type ContentCacheAdapter
} from '#content/server'

export default {
  name: 'app-cache',
  apply(event, hint) {
    const headers = contentCacheHeaders(hint)
    for (const [name, value] of headers) {
      setHeader(event, name, value)
    }
  },
  async invalidate(input) {
    // Purge CDN, ISR, Redis route cache, or another host cache.
  }
} satisfies ContentCacheAdapter
```

See [Cache and invalidate provider content](/docs/guides/providers/caching-and-invalidation) for the full contract.
