---
title: Errors
description: Every error Ginko raises across the query, provider, preview, and revalidate boundaries.
---

Ginko errors share one shape at the HTTP and provider boundaries: `statusCode`,
`statusMessage` holding the machine code, a human `message`, and `data` starting
with the same `code`. Internal causes stay on a non-enumerable `cause`, so logs
keep them while JSON serializers never leak them.

## Provider error codes

Provider and boundary errors use `ContentProviderErrorCode`. The code travels in
`statusMessage` and `data.code`.

| Code | HTTP | Meaning |
|---|---|---|
| `unknown_provider` | 500 | Configured provider name resolved to nothing |
| `unknown_collection` | 400 | Query named a collection that is not configured |
| `unsupported_provider_operation` | 400 | Provider lacks the optional method (for example navigation) |
| `unsupported_query_operator` | 400 | Plan used an operator outside `capabilities.query.operators` |
| `unsupported_query_shape` | 400 | Plan shape the provider did not advertise (pagination mode, count) |
| `provider_query_not_json_pure` | 500 | Query envelope failed the JSON-purity gate before dispatch |
| `data_collection_route_access` | 400 | Route access to a data collection |
| `data_collection_search_access` | 400 | Search access to a data collection |
| `data_collection_sitemap_access` | 400 | Sitemap access to a data collection |
| `missing_locale_route` | 404 | No route mount for the requested locale |
| `provider_config_missing` | 500 | Provider registration incomplete |
| `provider_module_missing` | 500 | Provider module could not be loaded |
| `provider_module_invalid` | 500 | Provider module failed contract validation |
| `provider_result_invalid` | 500 | Provider returned an envelope that failed validation |
| `unsupported_provider_search_index` | 400 | Search index operation not supported by the provider |
| `unsupported_provider_search` | 400 | Search not supported by the provider |
| `unsupported_provider_site_data` | 400 | Site data not supported by the provider |
| `unsupported_provider_prerender` | 400 | Prerender enumeration not supported by the provider |
| `unsupported_filesystem_preview` | 400 | Preview requested against the filesystem provider |

## HTTP request errors

The public query endpoints reject malformed transport payloads with
`invalid_content_query_request` (400). `data.path` names the offending location
(`$.collection`, `$.where[0].draft`, and so on) and `data.reason` explains the
violation. Payloads beyond the byte or structural budgets fail the same way.

A missing document is not an error: `one()` resolves `null` and `many()`
resolves `[]`. On static hosts, an SPA-shell fallback response is converted to
a real `404` `createError`, so the same miss behavior applies after prerender.

## Preview and revalidate

| Situation | HTTP | Code |
|---|---|---|
| Preview token sent by query string | 400 | `invalid_preview_transport` |
| Invalid or expired preview token | 401 | `invalid_preview_token` |
| Revalidate signature mismatch | 401 | (signature failure) |
| Revalidate payload too large | 413 | — |
| Revalidate body malformed | 400 | — |

## Catching errors in application code

Match on `statusCode`, never on message text:

```ts
try {
  await one(docs, { by: { ref: 'guide:intro' } })
} catch (error) {
  if ((error as { statusCode?: number }).statusCode === 404) {
    // handle miss
  }
}
```

Query verbs already resolve documented misses to `null`, `[]`, or `0`; the
remaining throws are configuration or provider faults that should surface.
`data.code` gives handlers a stable discriminator when several fault classes
share one status code.
