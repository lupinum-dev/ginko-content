---
title: Document Envelope
description: Reference for the identity, route, locale, and resolution fields attached to every localized query result.
---

Every localized document returned by the unified query API carries one route and resolution envelope.

## Shape

```ts
type LocalizedContentDocument<T = ParsedContentMeta> = Omit<T, 'path' | 'resolved'> & {
  locale: string
  route: ContentDocumentRoute
  resolution: ContentDocumentResolution
  stem?: string
  extension?: string
  resolvedRefs?: Record<string, string>
}

interface ContentDocumentRoute {
  requestedPath?: string
  resolvedPath: string
  alternates: ContentAlternate[]
}

interface ContentDocumentResolution {
  requested: {
    locale?: string
  }
  resolved: {
    locale: string
  }
  usedFallback: boolean
}

type ContentAlternate =
  | {
      locale: string
      path: string
      source: 'variant'
    }
  | {
      locale: string
      path: string
      source: 'fallback'
      resolvedLocale: string
    }
```

`T` supplies normalized identity, schema fields, and parsed body data. The
localized envelope removes the internal `path` and `resolved` carriers and
adds the public route and resolution facts.

## Identity fields

| Field | Contract |
| --- | --- |
| `id` | Public document identifier supplied by the normalized content contract |
| `collection` | Canonical collection name |
| `canonicalKey` | Opaque locale-agnostic join key; never parse or render as a URL |
| `file` | Optional `ContentFileMeta` provenance object when a backing file exists; not a public route |
| `locale` | Convenience copy of `resolution.resolved.locale` |

## Route fields

| Field | Contract |
| --- | --- |
| `route.requestedPath` | Selector path used for resolution when the call supplied one |
| `route.resolvedPath` | Canonical public path for links and navigation |
| `route.alternates` | Concrete locale variants plus the labeled fallback route used by this resolution, when applicable |

Use `route.resolvedPath` in `<NuxtLink>` and `navigateTo`.

## Resolution fields

`resolution.requested.locale` records the requested locale when one existed. `resolution.resolved.locale` records the variant actually returned. `resolution.usedFallback` states whether they differ because fallback was used.

## Alternates

A `source: 'variant'` entry points to a concrete translation returned by the provider. A `source: 'fallback'` entry records the requested route that this query actually resolved to content owned by `resolvedLocale`. Ginko does not guess fallback URLs for other missing locales from one document's facts; whole-collection surfaces such as sitemaps use the canonical route index for that work.

The distinction lets language switchers decide whether to show, label, or suppress fallback destinations.

## Projection

`select` narrows authored and parsed fields, but Ginko preserves identity, `route`, and `resolution`. Application code can still identify and link a projected result.

## Removed shapes

The current envelope has no top-level `path`, `variants`, `localePaths`, or `resolved` object. Migration code must not add compatibility aliases.
