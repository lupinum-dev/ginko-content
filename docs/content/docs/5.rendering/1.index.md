Ginko keeps rendering deliberately small: fetch a document, pass it to `<ContentRenderer>`, and build the rest of the page with ordinary Vue components.

## The usual page shape

```vue [pages/docs/[...slug\\].vue]
<script setup lang="ts">
import { docs } from '~/content.config'

const { page } = await useContentPage(docs)
</script>

<template>
  <ContentRenderer v-if="page" :value="page" />
</template>
```

That pattern keeps page loading, not-found handling, localized route state, and rendering explicit. No hidden document fetch happens behind the component tree.

## What the runtime ships

- [`ContentRenderer`](/docs/rendering/content-renderer) renders a parsed document body.
- `useContentPage()` resolves the current route-backed document.
- `useContentTree()` returns the sidebar/menu tree.
- Surround links come from `useContentNeighbors()`.

## What this docs site does

This site uses the runtime primitives directly and renders its own sidebar and prev/next cards. That is the intended Ginko shape: the module gives you content data, not a prescriptive docs theme.
