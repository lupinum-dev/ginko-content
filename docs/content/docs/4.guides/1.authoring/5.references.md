---
title: Content References
description: Model relationships with authored refs and collection-aware schemas, then populate or query those relationships through the unified API.
---

Use content references when one document depends on another document's identity rather than its current public route.

## Define target and source collections

```ts [content.config.ts]
import {
  defineCollection,
  defineContentConfig,
  reference
} from '@lupinum/ginko-content/config'
import { z } from 'zod'

export const authors = defineCollection({
  type: 'data',
  source: 'authors/*.yml',
  schema: z.object({
    name: z.string(),
    bio: z.string().optional()
  })
})

export const posts = defineCollection({
  type: 'page',
  source: 'blog/*.md',
  route: '/blog',
  schema: z.object({
    title: z.string(),
    author: reference('authors'),
    related: z.array(reference('posts')).default([])
  })
})

export default defineContentConfig({
  collections: { authors, posts }
})
```

## Author stable refs

```yml [content/authors/jane.yml]
ref: author:jane
name: Jane Doe
bio: Maintains the documentation.
```

```md [content/blog/first-post.md]
---
title: First post
ref: post:first
author: author:jane
related:
  - post:second
---

# First post
```

Use `ref` for human-authored identity. Do not copy `canonicalKey` values into frontmatter.

## Populate a relation

```ts
import { one } from '@lupinum/ginko-content/client'
import { posts } from '~/content.config'

const post = await one(posts, {
  where: { ref: { $eq: 'post:first' } },
  populate: {
    author: true
  }
})
```

Populate only the relationships the view needs. Large recursive population is harder to cache, query, and reason about.

## Query backlinks

Use `backlinks` when the application needs documents that refer to a target:

```ts
import { backlinks } from '@lupinum/ginko-content/client'
import { authors, posts } from '~/content.config'

const authoredPosts = await backlinks(authors, {
  by: { ref: 'author:jane' },
  from: posts,
  sort: { title: 'asc' }
})
```

## Verify

Run validation with a missing target ref and confirm the relationship fails before rendering. Restore the target and verify populated and backlink results use public document envelopes.

## Failure modes

- Referencing a translated route instead of stable identity.
- Reusing one `ref` for different documents.
- Leaving one locale variant with a conflicting `ref`.
- Populating an unbounded graph for a list page.
