Use Markdown for document structure and frontmatter for fields the application must query, validate, or render outside the body.

## Prerequisites

- A page collection from [Installation](/docs/get-started/installation)
- A catch-all route using `useContentPage`

# Write Markdown

## Define authored fields

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@lupinum/ginko-content/config'
import { z } from 'zod'

export const pages = defineCollection({
  type: 'page',
  source: '**/*.md',
  schema: z.object({
    title: z.string(),
    description: z.string().optional(),
    publishedAt: z.string().optional(),
    tags: z.array(z.string()).default([])
  })
})

export default defineContentConfig({ collections: { pages } })
```

Built-in document fields and schema fields meet in one typed result. Do not duplicate the title or route in a separate application registry.

## Headings and table of contents

Ginko creates heading IDs during Markdown processing and exposes table-of-contents data on the document. Keep headings descriptive and stable because inbound links may target their anchors.

Configure depth through the Markdown `toc` plugin when the defaults do not match the site:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    markdown: {
      plugins: [
        ['toc', { depth: 3, searchDepth: 3 }]
      ]
    }
  }
})
```

## Links and images

Use root-relative URLs for known application routes and normal relative paths for colocated public assets. Ginko can validate authored content links when link validation is enabled; it does not guess redirects for renamed pages.

## Verify

Render the page, follow every link, and confirm schema failures stop invalid content during development or build according to the configured validation mode.

## Failure modes

- A schema field is missing or has the wrong type.
- A heading rename breaks an external anchor.
- A relative link resolves against a different nested route than expected.
- Queryable data is buried in body text instead of frontmatter.
