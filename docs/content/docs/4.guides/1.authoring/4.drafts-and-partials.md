---
title: Drafts and Partials
description: Keep unfinished pages and reusable source fragments out of public navigation, search, sitemap, and production queries.
---

Use drafts for unfinished route-backed documents and partials for reusable content that must never become a public route.

## Draft a page

```md [content/blog/upcoming-release.md]
---
title: Upcoming release
draft: true
---

# Upcoming release
```

Drafts are visible during development. The filesystem provider serves a sealed
snapshot in production, so drafts remain hidden and authenticated filesystem
preview requests fail as unsupported. Use a provider-owned preview workflow
when production requests must read unpublished content.

## Create a partial

Prefix the filename with `_`:

```txt
content/
  guides/
    installation.md
    _shared-requirements.md
```

A partial can be parsed and used by content tooling, but it does not receive a public route or navigation entry.

## Preview unpublished content

Ordinary draft files already appear in `nuxt dev`, while partials remain
structural non-routes. `content.preview` protects request-scoped reads from a
preview-storage overlay; it is not a draft-visibility switch. Production
filesystem preview is intentionally unsupported because the provider can only
serve its immutable build snapshot. Configure an external provider that owns
authentication and published-versus-preview selection when production preview
is required.

## Hide a published page from navigation

Use `navigation: false` when the page should remain routable but should not appear in the generated navigation tree:

```md
---
title: Direct-link reference
navigation: false
---
```

This is not a draft. Search and sitemap policy may still include it.

## Verify

Test development and production builds separately. Confirm drafts are visible
in development, absent from production filesystem queries and generated
routes, and that an authenticated production filesystem preview request fails
with `unsupported_filesystem_preview`. Test provider-owned preview separately
when configured.

## Failure modes

- Treating preview as a CMS publishing mechanism.
- Using `navigation: false` to hide sensitive content.
- Expecting the production filesystem provider to reveal a deployed draft.
- Naming a real page with `_` and expecting a route.
