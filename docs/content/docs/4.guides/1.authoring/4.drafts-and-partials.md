---
title: Drafts and Partials
description: Keep unfinished pages and reusable source fragments out of public navigation, search, sitemap, and production queries.
---

Use drafts for unfinished route-backed documents and partials for reusable content that must never become a public route.

## Draft a page

```md [content/blog/upcoming-release.md]
---
title: Upcoming release
draft: true
---

# Upcoming release
```

Drafts are visible during development. Outside development they remain hidden from normal lists, navigation, search, sitemap, and route discovery unless a valid preview request enables them.

## Create a partial

Prefix the filename with `_`:

```txt
content/
  guides/
    installation.md
    _shared-requirements.md
```

A partial can be parsed and used by content tooling, but it does not receive a public route or navigation entry.

## Configure filesystem preview

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    preview: {
      token: process.env.GINKO_CONTENT_PREVIEW_TOKEN
    }
  }
})
```

The token gates visibility for draft and partial files already present in the deployed content directory. It does not fetch unpublished CMS content or bypass a deployment.

## Hide a published page from navigation

Use `navigation: false` when the page should remain routable but should not appear in the generated navigation tree:

```md
---
title: Direct-link reference
navigation: false
---
```

This is not a draft. Search and sitemap policy may still include it.

## Verify

Test development and production builds separately. Confirm drafts and partials do not appear in public queries or generated routes, and confirm preview works only with the configured token.

## Failure modes

- Treating preview as a CMS publishing mechanism.
- Using `navigation: false` to hide sensitive content.
- Deploying a draft file and assuming the route cannot be accessed under any preview configuration.
- Naming a real page with `_` and expecting a route.
