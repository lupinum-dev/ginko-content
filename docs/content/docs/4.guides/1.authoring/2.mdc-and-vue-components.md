---
title: MDC and Vue Components
description: Use Vue components, props, and slots inside Markdown while keeping content portable and renderable through ContentRenderer.
---

Use MDC when a document needs a Vue component, structured props, or named slots. Keep ordinary prose as Markdown.

## Prerequisites

- A page rendered with `<ContentRenderer>`
- A Vue component registered through Nuxt component discovery

## Create a component

```vue [app/components/Callout.vue]
<script setup lang="ts">
defineProps<{
  title: string
  tone?: 'info' | 'warning'
}>()
</script>

<template>
  <aside :data-tone="tone || 'info'">
    <strong>{{ title }}</strong>
    <div><slot /></div>
  </aside>
</template>
```

## Use the component in Markdown

```mdc [content/guide.md]
# Guide

::callout{title="Before you deploy" tone="warning"}
Run the production build and test a direct nested route.
::
```

MDC maps the kebab-case tag to the Vue component and passes declared attributes as props. Content inside the block becomes the default slot.

## Named slots

```vue [app/components/FeaturePanel.vue]
<template>
  <section>
    <header><slot name="title" /></header>
    <div><slot /></div>
  </section>
</template>
```

```mdc [content/features.md]
::feature-panel
#title
Typed content

#default
Collections keep authored fields attached to query results.
::
```

## Component policy

When content must remain portable across CMS or agent tooling, declare an explicit component policy. The policy names allowed components, props, slots, and media behavior. It prevents arbitrary application components from becoming an undocumented content format.

## Verify

Render the document in development and in a production build. Confirm props have the expected types, slots render once, and the raw agent Markdown remains understandable without the visual component.

## Failure modes

- The component is outside Nuxt's component directories.
- The MDC tag does not match the registered component name.
- A prop is encoded as text when the component expects JSON.
- A custom component contains the only explanation of important content.
- Portable content uses a component absent from the declared policy.
