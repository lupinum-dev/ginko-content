---
title: Data collections and references
description: Model records like authors and team members that have no page, and link documents together with stable refs.
---

Some content is a record, not a page: an author, a team member, a product. A data collection stores those as `.yml` files you can query, but none of them get a URL.

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@lupinum/ginko-content/config'
import { z } from 'zod'

export const team = defineCollection({
  type: 'data',
  source: 'team/*.yml',
  schema: z.object({
    name: z.string(),
    role: z.string(),
    order: z.number(),
    avatar: z.string().optional()
  })
})

export default defineContentConfig({ collections: { team } })
```

```yml [content/team/jane.yml]
ref: team:jane
name: Jane Doe
role: Documentation engineer
order: 1
avatar: /images/team/jane.jpg
```

Each record is queryable, but `type: 'data'` collections get no route and stay out of the sitemap.

## Render records from a page

Query the collection with `many` and loop over the results in a normal page:

```vue [app/pages/team.vue]
<script setup lang="ts">
import { many } from '@lupinum/ginko-content/client'
import { team } from '~/content.config'

const { data: members } = await useAsyncData('team', () =>
  many(team, {
    sort: { order: 'asc' },
    select: ['name', 'role', 'order', 'avatar']
  })
)
</script>

<template>
  <ul>
    <li v-for="member in members" :key="member.canonicalKey">
      <img v-if="member.avatar" :src="member.avatar" alt="">
      <strong>{{ member.name }}</strong>
      <span>{{ member.role }}</span>
    </li>
  </ul>
</template>
```

## Pick a format

- `yaml` for compact, hand-authored records.
- `json` for machine-generated data.
- `csv` for flat tables with stable columns.
- `markdown` when a record needs a body.

Whatever the format, every record enters the same schema.

## Link one document to another

Give each record a `ref` in its frontmatter. That is the stable, human-authored name other documents point at. Declare the relation in the schema with `reference()`:

```ts [content.config.ts]
import { defineCollection, defineContentConfig, reference } from '@lupinum/ginko-content/config'
import { z } from 'zod'

export const authors = defineCollection({
  type: 'data',
  source: 'authors/*.yml',
  schema: z.object({
    name: z.string(),
    bio: z.string().optional()
  })
})

export const posts = defineCollection({
  type: 'page',
  source: 'blog/*.md',
  route: '/blog',
  schema: z.object({
    title: z.string(),
    author: reference('authors'),
    related: z.array(reference('posts')).default([])
  })
})

export default defineContentConfig({ collections: { authors, posts } })
```

```md [content/blog/first-post.md]
---
title: First post
ref: post:first
author: author:jane
related:
  - post:second
---
```

> **Point at the `ref`, never at `canonicalKey`.** Ginko generates `canonicalKey` from your files; a ref you write by hand stays stable even when routes change. Copying a `canonicalKey` into frontmatter breaks the moment Ginko rebuilds it.

## Load and reverse a relation

Use `populate` to load the linked document alongside the source:

```ts
const post = await one(posts, {
  where: { ref: { $eq: 'post:first' } },
  populate: {
    author: true
  }
})
```

Populate only what the view needs. To go the other way and find every document pointing at a target, use `backlinks`:

```ts
const authoredPosts = await backlinks(authors, {
  by: { ref: 'author:jane' },
  from: posts,
  sort: { title: 'asc' }
})
```
