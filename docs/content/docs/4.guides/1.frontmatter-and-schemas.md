---
title: Frontmatter and schemas
description: Author Markdown with typed frontmatter and validate it at the collection so pages never receive bad data.
---

Write frontmatter at the top of a Markdown file, then describe those fields once in `content.config.ts`. Every query gets the types for free.

```md [content/blog/hello.md]
---
title: Hello
description: A first post.
publishedAt: 2026-07-14
tags:
  - authoring
featured: false
---

# Hello

Use headings for structure and frontmatter for data.
```

```ts [content.config.ts]
import { defineCollection, defineContentConfig, fields } from '@lupinum/ginko-content/config'
import { z } from 'zod'

export const posts = defineCollection({
  type: 'page',
  source: 'blog/**/*.md',
  route: '/blog',
  schema: z.object({
    title: fields.text().required(),
    description: fields.text().required(),
    publishedAt: fields.date().required(),
    tags: fields.array(fields.text()),
    featured: fields.boolean()
  })
})

export default defineContentConfig({ collections: { posts } })
```

The `posts` handle carries these types through `one`, `many`, `useContentPage`, and server operations. Import the handle instead of passing a string name so a query result knows its own shape.

## Use fields or plain zod

The `fields.*` helpers return zod schemas with extra metadata, so the same schema can drive CMS forms later. Reach for them first. Plain zod still works as a fallback when you don't need that:

```ts [content.config.ts]
publishedAt: z.iso.datetime()
```

Every helper chains `.label()`, `.help()`, `.localized()`, and `.required()`.

> **Keep dates as strings.** `fields.date()` outputs a normalized `YYYY-MM-DD` string and `fields.datetime()` a normalized UTC ISO 8601 string, both safe to sort and compare with `$gt`/`$lt`. A schema that produces a `Date` instance (`z.date()`, `z.coerce.date()`) fails ingest on purpose, with an error pointing you back at `fields.date()`.

## Set defaults in the schema

Put a field's default in the schema, not in `post.tags || []` scattered across components:

```ts [content.config.ts]
tags: fields.array(fields.text()).default([]) // empty array when omitted
```

Skip the default when leaving a field out means something different from an explicit value.

## Fail the build on bad data

Set validation to `error` so a document that breaks its schema stops the build that introduced it:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    validation: 'error'
  }
})
```

The default mode writes a report and keeps building.

## Change table-of-contents depth

Ginko builds heading IDs and table-of-contents data during Markdown processing. Adjust the depth through the `toc` plugin:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    markdown: {
      plugins: [
        ['toc', { depth: 3, searchDepth: 3 }]
      ]
    }
  }
})
```
