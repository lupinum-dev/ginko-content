---
title: Add Previous and Next Links
description: Load neighboring content with the same collection order and route model used by the current page.
---

Use the `surround` option on `useContentPage` when a route page needs previous and next links.

## Load surroundings

```vue [app/pages/docs/[...slug].vue]
<script setup lang="ts">
import { docs } from '~/content.config'

const { page, previous, next } = await useContentPage(docs, {
  surround: {
    select: ['description']
  }
})
</script>

<template>
  <article v-if="page">
    <ContentRenderer :value="page" />

    <nav aria-label="Adjacent pages" class="grid sm:grid-cols-2">
      <NuxtLink v-if="previous" :to="previous.path">
        <span>Previous</span>
        <strong>{{ previous.title }}</strong>
        <small>{{ previous.description }}</small>
      </NuxtLink>

      <NuxtLink v-if="next" :to="next.path">
        <span>Next</span>
        <strong>{{ next.title }}</strong>
        <small>{{ next.description }}</small>
      </NuxtLink>
    </nav>
  </article>
</template>
```

Enabling surroundings performs an additional documented read. Select only metadata the component renders.

## Query surroundings outside a page

Use the pure `surround` operation when the target document is not the current route:

```ts
import { surround } from '@lupinum/ginko-content/client'
import { docs } from '~/content.config'

const neighbors = await surround(docs, {
  by: { ref: 'guide:installation' },
  select: ['description']
})
```

## Ordering

Surroundings follow collection ordering. For filesystem pages this normally comes from numeric prefixes or explicit navigation order. Do not calculate neighbors from the currently rendered sidebar array; that would duplicate provider behavior and locale resolution.

## Verify

Test the first, middle, and last document. The first has no previous entry; the last has no next entry. Confirm links remain correct in localized routes.

## Failure modes

- Rendering a link when the neighbor is `null`.
- Sorting a separate list differently from the collection order.
- Selecting the full body for link cards.
- Using opaque canonical keys as URLs.
