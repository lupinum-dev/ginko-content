---
title: Choose a Search Backend
description: Select MiniSearch, Pagefind, provider-owned search, or an external service from corpus size, deployment shape, and product requirements.
---

Start with MiniSearch. Move only when a measured payload, deployment constraint, or search requirement justifies another backend.

## Decision table

| Requirement | Choose |
| --- | --- |
| Small-to-medium content site with portable static or SSR output | MiniSearch |
| Larger generated site that benefits from shard loading | Pagefind |
| Active provider already owns indexed content | Provider-owned search |
| Hosted ranking, analytics, typo tuning, or very large corpus | External search service |

## MiniSearch

MiniSearch produces a generated JSON index and uses `useContentSearch` in the client. It has the fewest moving parts and is the default recommendation.

Its trade-off is payload size. Measure the compressed index and the time to first useful result.

## Pagefind

Pagefind indexes generated HTML into static shards. It avoids loading one full JSON corpus, but its index represents the last generated site.

Its trade-off is build coupling. Runtime content cannot appear until the site and index are regenerated.

## Provider-owned search

Configure `engine: 'provider'` when an external content provider already owns search. The provider returns normalized search hits and raw route facts; Ginko applies public path policy.

Its trade-off is provider responsibility. Search availability, indexing, ranking, authorization, and invalidation belong to that integration.

## External service

Use Algolia, Meilisearch, Typesense, or another service when search is a product surface with hosted indexing, analytics, synonyms, facets, or large-scale ranking requirements.

An external search UI may sit outside `useContentSearch`. Keep result routes aligned with Ginko's public content paths.

## Do not add a second index casually

Running MiniSearch and another backend side by side creates two derived datasets and two failure modes. Keep one production search authority unless a migration or explicit fallback requires both.

## Verify the decision

- Record corpus size and generated index size.
- Test first search on a cold browser session.
- Test static deployment without a live API.
- Test locale scope.
- Test how newly published content reaches the index.
- Test route changes and deleted documents.
