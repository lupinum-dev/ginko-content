---
title: Use Pagefind
description: Generate a sharded static search index for content sites that have outgrown a single MiniSearch payload.
---

Use Pagefind when the site is statically generated and a sharded on-demand index is a better fit than one JSON search payload.

## Configure Pagefind

Pagefind is an optional peer dependency. Install it in applications that enable
the Pagefind search engine:

```bash
pnpm add pagefind
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    search: {
      engine: 'pagefind'
    }
  }
})
```

The application-facing composable does not change:

```ts
import { useContentSearch } from '@lupinum/ginko-content/client'

const search = await useContentSearch({
  locale: computed(() => 'en'),
  limit: 10
})
```

Ginko normalizes Pagefind hits into the same result shape used by MiniSearch and provider-owned search.

## Generate the site

```bash
pnpm generate
```

Pagefind assets are generated from the static output. Deploy the complete output directory, including the `pagefind/` assets.

## Locale behavior

Ginko keeps locale search scope explicit. Pass the active locale to `useContentSearch` so the UI queries the correct index and does not mix languages unexpectedly.

## When Pagefind fits

Choose Pagefind when:

- the site is statically generated;
- the MiniSearch payload is too large;
- search can operate over built HTML;
- shard loading is preferable to a single initial index;
- content updates already trigger a site generation.

Do not choose Pagefind for runtime provider content that changes independently from the generated site.

## Verify

Serve the generated output through HTTP and search for text from multiple pages and headings. Confirm Pagefind assets return 200 responses and the deployment preserves their paths.

## Failure modes

- Running only `nuxt build` when the Pagefind pipeline expects generated output.
- Deploying HTML without the `pagefind/` directory.
- Expecting newly published runtime content to appear before regeneration.
- Building a Pagefind-specific UI instead of consuming normalized results.
