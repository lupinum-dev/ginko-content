---
title: Translated slugs
description: Give each language its own words in the URL while Ginko keeps the translations connected.
---

Turn this on when public paths must use different words in each language. If only the locale prefix changes, keep shared slugs. They are the default and simpler.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/ginko-content', '@nuxtjs/i18n'],
  i18n: {
    defaultLocale: 'en',
    locales: ['en', 'de'],
    strategy: 'prefix_except_default'
  },
  content: {
    i18n: {
      translatedSlugs: true,
      fallback: {
        de: ['en']
      }
    }
  }
})
```

Nuxt I18n owns `locales` and `defaultLocale`. Under `content.i18n` you set only the fallback and `translatedSlugs`.

## Give each language its own folder and file names

Name the folders and files in each language's own words. A shared numeric prefix chain is what joins the equivalents across locales.

```txt
content/
  en/docs/
    1.documentation/
      1.getting-started.md
      2.installation.md
  de/docs/
    1.dokumentation/
      1.erste-schritte.md
      2.installation.md
```

The chain does the matching:

- `1/1` joins `getting-started` and `erste-schritte`.
- `1/2` joins both installation pages.

The translated names become each language's URL. The numbers never appear in the URL.

> **Changing a numeric prefix changes which translations belong together, not just the order.** Renaming `1.getting-started.md` to `3.getting-started.md` breaks its link to `1.erste-schritte.md`. To reorder pages, use navigation metadata instead of renumbering the files.

## Switch languages

Always link through `page.route.alternates`. Ginko rebuilds these from your files, so you never translate slugs or swap path segments in the browser.

```vue
<NuxtLink
  v-for="alternate in page.route.alternates"
  :key="alternate.locale"
  :to="alternate.path"
>
  {{ alternate.locale }}
</NuxtLink>
```

Set `strictTranslatedSlugs` to turn slug warnings into build errors in CI.
