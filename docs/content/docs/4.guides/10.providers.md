---
title: Connect an external source
description: Replace the filesystem with a CMS or database provider while your pages keep calling the same content API.
---

Register a provider by name and point it at a module:

```ts [content.config.ts]
import { defineContentConfig } from '@lupinum/ginko-content/config'
import { docs } from './content.collections'

export default defineContentConfig({
  provider: 'acme',
  providers: {
    acme: '~/server/providers/acme'
  },
  collections: { docs }
})
```

Your pages do not change. They keep calling `useContentPage`, `one`, `many`, and `navigation` with the same collection handles. Only the server-side source swaps.

## Stay on the filesystem first

Markdown plus Git handles most sites. Switch to a provider when a concrete requirement forces it:

- a CMS or database is the real source of your content;
- editors publish without redeploying the app;
- access control at runtime changes which documents a request can see;
- several apps read one published content source.

If none of these is true yet, keep the filesystem provider.

## Implement the minimum contract

Only `query` is required. Handle the three plan modes Ginko asks for:

```ts [server/providers/acme.ts]
import type { ContentProvider } from '@lupinum/ginko-content/provider'

export default {
  name: 'acme',
  capabilities: {
    query: {
      operators: ['$eq', '$in'],
      pagination: ['offset']
    }
  },
  async query(event, query) {
    switch (query.plan.mode) {
      case 'count':
        return { result: await countDocuments(query) }
      case 'first':
        return { result: await loadFirstDocument(query) }
      case 'all': {
        const page = await loadDocuments(query)
        return {
          result: page.items,
          skip: query.plan.paging?.mode === 'offset'
            ? query.plan.paging.skip
            : query.plan.skip,
          limit: query.plan.limit ?? 100,
          total: page.total
        }
      }
    }
  }
} satisfies ContentProvider
```

Return raw documents. Ginko builds public URLs and resolution metadata from them:

```ts
const document = {
  collection: 'docs',
  canonicalKey: 'docs:getting-started',
  locale: 'de',
  contentPath: '/dokumentation/einstieg',
  routeVariants: [
    { locale: 'en', contentPath: '/docs/getting-started' },
    { locale: 'de', contentPath: '/dokumentation/einstieg' }
  ],
  title: 'Einstieg',
  body: {
    type: 'root',
    children: []
  }
}
```

Two things keep this correct. `contentPath` is a site-relative path without the Nuxt locale prefix, so return that and let Ginko project the public URL. And only list the operators and pagination modes your code actually runs, because Ginko trusts what you advertise.

> **Advertise only what you execute.** If `capabilities.query.operators` names an operator your code does not run with the documented semantics, queries using it silently return wrong rows. The same goes for each pagination mode.

## Add more when the source owns it

`navigation`, `surroundings`, `search`, `siteData`, and `routes` are optional. Implementing the method turns the feature on, so add one only when your source genuinely owns that behavior. An empty method that returns nothing still advertises the feature.

## Prove every capability

Run the official suite against your provider:

```ts [test/provider.test.ts]
import { runProviderContractSuite } from '@lupinum/ginko-content/testing/provider-contract'

runProviderContractSuite({
  name: 'acme',
  expectedProviderName: 'acme',
  loadProvider: async () => provider,
  createEvent: () => createTestEvent(),
  expectedCapabilities: provider.capabilities,
  operatorProbes: {
    $eq: equalityProbe,
    $in: membershipProbe
  },
  logicalProbes: {
    and: andProbe,
    or: orProbe,
    not: notProbe
  },
  sortProbe,
  terminalProbes: {
    first: firstProbe,
    count: countProbe
  },
  paginationProbes: {
    offset: offsetProbe
  }
})
```

Every advertised operator and pagination mode needs its own probe. Each probe must assert a discriminating result, not just run without error, because returning cleanly proves nothing about semantics.
