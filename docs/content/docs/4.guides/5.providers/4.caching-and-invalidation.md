---
title: Cache and Invalidate Provider Content
description: Attach dependency hints to provider results, apply them through one cache adapter, and invalidate exact tags and paths after publishing.
---

Provider caching has three owners: the provider reports dependencies, Ginko collects request hints, and the cache adapter applies platform behavior.

## Configure caching and revalidation

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    cache: '~/server/content-cache',
    revalidate: {
      token: process.env.GINKO_CONTENT_REVALIDATE_TOKEN
    }
  }
})
```

Without a token, Ginko does not register the built-in revalidation endpoint.

## Return cache hints

```ts [server/providers/acme.ts]
import {
  withContentCache,
  type ContentProvider
} from '@lupinum/ginko-content/server'

export default {
  name: 'acme',
  capabilities: {
    query: {
      operators: ['$eq'],
      pagination: ['offset']
    }
  },
  async query(event, query) {
    const result = await executeQuery(query)

    return withContentCache(result, {
      tags: [`collection:${query.collection}`],
      maxAge: 300,
      swr: 60
    })
  }
} satisfies ContentProvider
```

Use stable dependency tags:

- `entry:{collection}:{id}` for one source entry;
- `collection:{collection}` for lists;
- `route:{path}` for a rendered route;
- `nav:{collection}:{locale}` for navigation;
- `search:{locale}` for search;
- `sitemap` for sitemap output.

## Implement the adapter

```ts [server/content-cache.ts]
import { setHeader } from 'h3'
import {
  contentCacheHeaders,
  type ContentCacheAdapter
} from '@lupinum/ginko-content/server'

export default {
  name: 'application-cache',
  apply(event, hint) {
    for (const [name, value] of contentCacheHeaders(hint)) {
      setHeader(event, name, value)
    }
  },
  async invalidate(input) {
    await purgePlatformCache(input)
  }
} satisfies ContentCacheAdapter
```

## Send signed invalidation

Production delivery uses HMAC-SHA256 over:

```txt
<timestamp>.<event id>.<raw request body>
```

Send the event ID, timestamp, signature, and JSON body containing exact `tags` and `paths`. When a route changes, include both old and new public paths.

Token-only delivery is reserved for explicitly enabled local or trusted setups.

## Prefer safe over-invalidation

Stale published content is worse than an extra purge. Invalidate collection, navigation, search, and sitemap aggregates first. Tighten dependency tracking only when the provider can prove complete relationships.

## Verify

Test valid and invalid signatures, replay/idempotency behavior, preview cache suppression, tag merging, shortest cache lifetimes, old/new route invalidation, and provider/cache-adapter failure behavior.

## Failure modes

- Caching preview responses publicly.
- Using translated paths as stable entry IDs.
- Purging only the detail route after an entry changes list pages.
- Sending a token in place of signed production delivery.
- Maintaining separate invalidation logic in each page.
