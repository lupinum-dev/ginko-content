---
title: Build a Provider
description: Implement the minimum provider contract, return raw source facts, advertise executable capabilities, and run the official conformance suite.
---

A provider adapts one canonical content source to Ginko's normalized application contract. Start with `query`; add optional operations only when the source can support them correctly.

## Register the provider

```ts [content.config.ts]
import { defineContentConfig } from '@lupinum/ginko-content/config'
import { docs } from './content.collections'

export default defineContentConfig({
  provider: 'acme',
  providers: {
    acme: '~/server/providers/acme'
  },
  collections: { docs }
})
```

## Implement the minimum contract

```ts [server/providers/acme.ts]
import type { ContentProvider } from '@lupinum/ginko-content/provider'

export default {
  name: 'acme',
  capabilities: {
    query: {
      operators: ['$eq', '$in'],
      pagination: ['offset']
    }
  },
  async query(event, query) {
    const result = await loadDocuments(query)

    return {
      result: result.items,
      skip: query.plan.skip,
      limit: query.plan.limit,
      total: result.total
    }
  }
} satisfies ContentProvider
```

Only advertise operators and pagination modes the implementation executes with the documented semantics.

## Return raw documents

```ts
const document = {
  collection: 'docs',
  canonicalKey: 'docs:getting-started',
  locale: 'de',
  contentPath: '/dokumentation/einstieg',
  routeVariants: [
    { locale: 'en', contentPath: '/docs/getting-started' },
    { locale: 'de', contentPath: '/dokumentation/einstieg' }
  ],
  title: 'Einstieg',
  body: {
    type: 'root',
    children: []
  }
}
```

`contentPath` excludes the Nuxt locale prefix. Ginko derives public routes and resolution metadata. Do not return a second set of projected application URLs.

## Add optional operations deliberately

Implement `navigation`, `surroundings`, `search`, `siteData`, `routes`, or `invalidate` only when the provider owns the necessary source behavior. Optional method presence enables the corresponding operation; there are no duplicate capability booleans.

## Run conformance tests

```ts [test/provider.test.ts]
import { runProviderContractSuite } from '@lupinum/ginko-content/testing/provider-contract'

runProviderContractSuite({
  name: 'acme',
  expectedProviderName: 'acme',
  loadProvider: async () => provider,
  createEvent: () => createTestEvent(),
  expectedCapabilities: provider.capabilities,
  operatorProbes: {
    $eq: equalityProbe,
    $in: membershipProbe
  },
  paginationProbes: {
    offset: offsetProbe
  }
})
```

Use the complete fixture helpers and signatures documented by the installed package. Every advertised capability needs an executable probe.

## Verify

Test list, first, count, visibility, locale routes, unsupported operators, provider errors, and every optional method the provider implements.

## Failure modes

- Returning application-projected route metadata from the provider.
- Advertising an operator that only partially works.
- Reading preview cookies inside provider logic.
- Branching on provider names in page components.
- Implementing empty optional methods that falsely enable features.
