---
title: Build a Documentation Site
description: Combine a mounted docs collection, catch-all page, sidebar navigation, surroundings, search, and sitemap output.
---

A documentation site should derive its page, sidebar, previous/next links, search, and sitemap from one docs collection.

## Define the collection

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@lupinum/ginko-content/config'
import { z } from 'zod'

export const docs = defineCollection({
  type: 'page',
  source: 'docs/**/*.md',
  route: '/docs',
  schema: z.object({
    title: z.string(),
    description: z.string(),
    icon: z.string().optional()
  })
})

export default defineContentConfig({ collections: { docs } })
```

## Organize content

```txt
content/docs/
  1.get-started/
    1.index.md
    2.installation.md
  2.guides/
    1.index.md
  3.reference/
    1.index.md
```

Numeric prefixes control navigation order without changing public paths.

## Render docs routes

```vue [app/pages/docs/[...slug].vue]
<script setup lang="ts">
import { createError, useSeoMeta } from '#imports'
import { docs } from '~/content.config'

const { page, previous, next } = await useContentPage(docs, {
  surround: { select: ['description'] }
})

if (import.meta.server && !page.value) {
  throw createError({ statusCode: 404, statusMessage: 'Document not found' })
}

useSeoMeta({
  title: () => page.value?.title,
  description: () => page.value?.description
})
</script>

<template>
  <article v-if="page">
    <ContentRenderer :value="page" />

    <nav aria-label="Adjacent documentation">
      <NuxtLink v-if="previous" :to="previous.path">
        {{ previous.title }}
      </NuxtLink>
      <NuxtLink v-if="next" :to="next.path">
        {{ next.title }}
      </NuxtLink>
    </nav>
  </article>
</template>
```

## Add the sidebar and search

Use `navigation(docs)` for the sidebar and `useContentSearch({ collection: docs })` for the search interface. Both consume the same route facts as the page resolver.

## Add sitemap output

Install `@nuxtjs/sitemap`, enable `content.sitemap`, and let Ginko register the content source. Do not reconstruct docs routes in the application sitemap config.

## Verify

- Direct-load a nested documentation route.
- Confirm sidebar and surroundings link to the same paths.
- Search for a nested heading.
- Inspect generated sitemap URLs.
- Confirm drafts and partials are absent from production output.

## Failure modes

- Mounting content at `/docs` without a matching Nuxt page route.
- Building the sidebar from a separate manual array.
- Rendering `page.body` instead of the full document.
- Enabling sitemap output without installing the XML owner.
