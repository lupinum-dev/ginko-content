---
title: Query Structured Data
description: Use data collections for YAML, JSON, or CSV records that need schemas and queries but do not own public content routes.
---

Use a data collection when records belong to the content model but are not pages by themselves.

## Define a data collection

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@lupinum/ginko-content/config'
import { z } from 'zod'

export const team = defineCollection({
  type: 'data',
  source: 'team/*.yml',
  schema: z.object({
    name: z.string(),
    role: z.string(),
    order: z.number(),
    avatar: z.string().optional()
  })
})

export default defineContentConfig({ collections: { team } })
```

## Author records

```yml [content/team/jane.yml]
ref: team:jane
name: Jane Doe
role: Documentation engineer
order: 1
avatar: /images/team/jane.jpg
```

## Query records

```vue [app/pages/team.vue]
<script setup lang="ts">
import { many } from '@lupinum/ginko-content/client'
import { team } from '~/content.config'

const { data: members } = await useAsyncData('team', () =>
  many(team, {
    sort: { order: 'asc' },
    select: ['name', 'role', 'order', 'avatar']
  })
)
</script>

<template>
  <ul>
    <li v-for="member in members" :key="member.canonicalKey">
      <img v-if="member.avatar" :src="member.avatar" alt="">
      <strong>{{ member.name }}</strong>
      <span>{{ member.role }}</span>
    </li>
  </ul>
</template>
```

Data collections are excluded from sitemap and public route discovery by default. A Nuxt page can render their records, but the records do not each receive content routes.

## Choose the source format

- Use YAML for compact human-authored records.
- Use JSON for machine-generated or interoperable data.
- Use CSV for flat tabular input with stable columns.
- Use Markdown when each record needs a rich body.

All formats should enter the same collection schema instead of creating format-specific application code.

## Verify

Confirm schema errors identify the source record, sort order is stable, and no record appears as a standalone sitemap or prerender route.

## Failure modes

- Using a page collection for records with no public route.
- Treating CSV strings as numbers without schema coercion or normalized input.
- Duplicating structured content in a TypeScript constant.
- Using route paths as data identities.
