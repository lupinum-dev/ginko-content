---
title: Configure Content Routes
description: Map collection content paths into Nuxt pages without maintaining a separate route table.
---

A page collection defines content routes, and a matching Nuxt page component renders them. Both parts are required.

## Mount a collection

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@lupinum/ginko-content/config'

export const changelog = defineCollection({
  type: 'page',
  source: 'changelog/*.md',
  route: '/changelog'
})

export default defineContentConfig({ collections: { changelog } })
```

`content/changelog/1.0.md` now has the content path `/changelog/1.0`.

## Add the Nuxt route

```vue [app/pages/changelog/[slug].vue]
<script setup lang="ts">
import { createError } from '#imports'
import { changelog } from '~/content.config'

const { page: release } = await useContentPage(changelog)

if (import.meta.server && !release.value) {
  throw createError({ statusCode: 404, statusMessage: 'Release not found' })
}
</script>

<template>
  <ContentRenderer v-if="release" :value="release" />
</template>
```

Ginko does not generate Vue page components. Nuxt still owns the application route and layout.

## Use locale-specific mounts

Localized collections can declare route mounts per locale when the collection prefix itself is translated. Keep route projection in collection configuration instead of branching in page components.

## Requested and resolved paths

The document route envelope can contain:

- `requestedPath`: the selector supplied by the request;
- `resolvedPath`: the canonical public path of the returned variant;
- `alternates`: locale-specific public paths.

Use `resolvedPath` for links. If the application wants canonical redirects, compare requested and resolved paths and call `navigateTo` explicitly.

## Verify

Direct-load every route shape, including collection index, single segment, nested catch-all, missing page, and localized prefix. Confirm generated navigation and sitemap use the same paths.

## Failure modes

- A collection contributes routes without a matching Nuxt page.
- A catch-all page targets the wrong collection.
- Components build links from file paths.
- Application redirects are assumed to happen automatically.
