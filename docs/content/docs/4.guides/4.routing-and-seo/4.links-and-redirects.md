---
title: Validate Links and Handle Redirects
description: Keep authored links aligned with collection routes and make canonical redirects an explicit application decision.
---

Use normalized public paths for links, validate authored destinations during builds, and handle route correction in the Nuxt page that owns the user experience.

## Link from queried content

Use `route.resolvedPath` from document results:

```vue
<NuxtLink :to="post.route.resolvedPath">
  {{ post.title }}
</NuxtLink>
```

Do not derive a URL from `canonicalKey`, source filename, or provider ID.

Navigation and search results already expose public `path` values appropriate for links.

## Author Markdown links

Use root-relative paths for known public routes:

```md
[Install Ginko](/docs/get-started/installation)
```

When locale-aware Markdown link processing is enabled, Ginko resolves content links through collection route policy. Links to application-owned pages remain application routes.

## Handle a canonical redirect

`useContentPage` does not redirect automatically. Compare the requested and resolved paths when the application wants URL correction:

```ts [app/pages/docs/[...slug].vue]
import { navigateTo } from '#imports'
import { docs } from '~/content.config'

const { page } = await useContentPage(docs, { fallback: true })

const requested = page.value?.route.requestedPath
const resolved = page.value?.route.resolvedPath

if (requested && resolved && requested !== resolved) {
  await navigateTo(resolved, { redirectCode: 301 })
}
```

Fallback does not always require a redirect. A site may intentionally show fallback content at the requested locale URL. That is a product decision made by the page.

## Preserve old public URLs

When a released route changes, add an explicit Nuxt or host redirect from the old public URL to the new one. Do not retain duplicate content files to simulate a redirect.

## Verify

Run link validation, follow links in a production preview, test route aliases, and confirm redirects preserve query strings and use the intended status code.

## Failure modes

- Parsing `canonicalKey` as a URL.
- Redirecting every locale fallback automatically.
- Keeping duplicate documents at old and new paths.
- Validating only internal content links while ignoring application routes.
