---
title: Routes, links, and redirects
description: How content paths become pages, how to link to them, and how to redirect old URLs explicitly.
---

A page collection turns content files into routes, and a matching Nuxt page component renders them. You need both parts.

## Mount a collection

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@lupinum/ginko-content/config'

export const changelog = defineCollection({
  type: 'page',
  source: 'changelog/*.md',
  route: '/changelog'
})

export default defineContentConfig({ collections: { changelog } })
```

`content/changelog/1.0.md` now has the content path `/changelog/1.0`.

## Add the Nuxt page

```vue [app/pages/changelog/[slug].vue]
<script setup lang="ts">
import { createError } from '#imports'
import { changelog } from '~/content.config'

const { page: release } = await useContentPage(changelog)

if (import.meta.server && !release.value) {
  throw createError({ statusCode: 404, statusMessage: 'Release not found' })
}
</script>

<template>
  <ContentRenderer v-if="release" :value="release" />
</template>
```

Ginko does not generate Vue components. Nuxt still owns the application route and layout. If a collection contributes routes with no page component to render them, those URLs 404.

When a collection prefix is itself translated, declare route mounts per locale in the collection config instead of branching in the page. See [content config](/docs/reference/content-config).

## Link to content

Link from a document with `route.resolvedPath` — the canonical public path Ginko computes for that variant:

```vue
<NuxtLink :to="post.route.resolvedPath">
  {{ post.title }}
</NuxtLink>
```

Navigation and search results already expose a public `path` you can pass straight to `<NuxtLink>`. Do not build URLs from `canonicalKey`, source filenames, or provider IDs; they are not routes.

In Markdown, write root-relative paths for app routes:

```md
[Get started](/docs/get-started/quickstart)
```

With locale-aware link processing enabled, Ginko resolves content links through your collection routes and can validate them at build time, so a broken destination fails the build instead of shipping.

## Redirect to the canonical URL

`useContentPage` does not redirect on its own. To send visitors to the canonical path, compare the requested and resolved paths and call `navigateTo`:

```ts [app/pages/changelog/[slug].vue]
import { navigateTo } from '#imports'
import { changelog } from '~/content.config'

const { page } = await useContentPage(changelog, { fallback: true })

const requested = page.value?.route.requestedPath
const resolved = page.value?.route.resolvedPath

if (requested && resolved && requested !== resolved) {
  await navigateTo(resolved, { redirectCode: 301 })
}
```

A locale fallback does not force a redirect. Showing fallback content at the requested URL is a valid choice, and the page decides.

## Move a published URL

When a live route changes, add a real Nuxt or host redirect from the old URL to the new one. Keeping a duplicate content file at the old path to fake a redirect leaves you with two pages to maintain.
