---
title: Vue components in Markdown
description: Put Vue components, props, and slots inside your Markdown content with MDC.
---

Write a Vue component, then drop it into Markdown as a `::tag` block. Here is a callout:

```vue [app/components/Callout.vue]
<script setup lang="ts">
defineProps<{
  title: string
  tone?: 'info' | 'warning'
}>()
</script>

<template>
  <aside :data-tone="tone || 'info'">
    <strong>{{ title }}</strong>
    <div><slot /></div>
  </aside>
</template>
```

```mdc [content/guide.md]
# Guide

::callout{title="Before you deploy" tone="warning"}
Run the production build and test a direct nested route.
::
```

The kebab-case tag maps to the component: `::callout` renders `Callout.vue`. Attributes in the `{}` become props, and the block content becomes the default slot.

## Fill named slots

For a component with named slots, open each one with `#slot-name`:

```vue [app/components/FeaturePanel.vue]
<template>
  <section>
    <header><slot name="title" /></header>
    <div><slot /></div>
  </section>
</template>
```

```mdc [content/features.md]
::feature-panel
#title
Typed content

#default
Collections keep authored fields attached to query results.
::
```

Two things keep this working. Put the component somewhere Nuxt discovers it, such as `app/components/`, or the tag renders as nothing. And write the block so it still reads as plain text: the words inside `::callout` should make sense even if the component never loads, so the same content stays useful in a CMS or a plain Markdown reader.
