---
title: Navigation
description: Build an ordered, locale-aware navigation tree from your folders, plus previous and next links.
---

`navigation()` turns a collection's folders and pages into an ordered tree. Query it once, key it by locale, and render it.

```vue [app/components/DocsNavigation.vue]
<script setup lang="ts">
import { navigation } from '@lupinum/ginko-content/client'
import { docs } from '~/content.config'

const { locale } = useI18n()

const { data: items } = await useAsyncData(
  () => `docs-navigation:${locale.value}`,
  () => navigation(docs, {
    locale: locale.value,
    select: ['description', 'icon', 'badge', 'sidebar']
  }),
  { watch: [locale] }
)
</script>

<template>
  <nav aria-label="Documentation">
    <ul>
      <li v-for="(item, index) in items" :key="item.path ?? `group:${index}`">
        <NuxtLink v-if="item.path" :to="item.path">{{ item.title }}</NuxtLink>
        <span v-else>{{ item.title }}</span>
        <DocsNavigationBranch v-if="item.children?.length" :items="item.children" />
      </li>
    </ul>
  </nav>
</template>
```

Each item carries `title` and `path`. Pass `select` to include extra fields your component renders.

> **Structural groups have children but no `path`.** Render a `<NuxtLink>` only when `item.path` exists, otherwise you link to nothing. The example above guards it.

## Name and order folders

Add a `.navigation.yml` beside a folder's pages to set its label, icon, and structural role.

```txt
content/docs/
  1.get-started/
    .navigation.yml
    1.index.md
    2.installation.md
  2.reference/
    1.index.md
```

```yml [content/docs/1.get-started/.navigation.yml]
title: Get Started
icon: i-lucide-rocket
sidebar: section
```

Numeric prefixes set order without appearing in labels or the page URL. `sidebar: section` and `sidebar: group` are markers a theme uses to split the tree into major areas or local groups. A folder's `index.md` frontmatter can supply the same fields when the folder has a landing page.

## Redirect to the first page

For a docs-root redirect or a "Get Started" button, resolve the first routable page of the tree.

```ts
import { navigation } from '@lupinum/ginko-content/client'
import { findFirstNavigationPage } from '@lupinum/ginko-content/navigation'

const items = await navigation(docs, { locale })
const docsEntry = findFirstNavigationPage(items)

if (docsEntry) await navigateTo(docsEntry.path)
```

To resolve one section's own page first, pass it as a one-item tree: `findFirstNavigationPage([section])`. To skip the section and search only inside it, pass its children: `findFirstNavigationPage(section?.children)`.

## Previous and next links

On a route page, set `surround` on `useContentPage` to get the neighbors in collection order.

```vue [app/pages/docs/[...slug].vue]
<script setup lang="ts">
import { docs } from '~/content.config'

const { page, previous, next } = await useContentPage(docs, {
  surround: {
    select: ['description']
  }
})
</script>

<template>
  <article v-if="page">
    <ContentRenderer :value="page" />

    <nav aria-label="Adjacent pages" class="grid sm:grid-cols-2">
      <NuxtLink v-if="previous" :to="previous.path">
        <span>Previous</span>
        <strong>{{ previous.title }}</strong>
        <small>{{ previous.description }}</small>
      </NuxtLink>

      <NuxtLink v-if="next" :to="next.path">
        <span>Next</span>
        <strong>{{ next.title }}</strong>
        <small>{{ next.description }}</small>
      </NuxtLink>
    </nav>
  </article>
</template>
```

For a document that is not the current route, call `surround()` directly and target it by reference.

```ts
import { surround } from '@lupinum/ginko-content/client'
import { docs } from '~/content.config'

const neighbors = await surround(docs, {
  by: { ref: 'guide:installation' },
  select: ['description']
})
```

`previous` and `next` are `null` at the first and last page, so render each link only when it exists. Neighbors follow the collection's own order from numeric prefixes and folder metadata. Never compute them from a hand-built sidebar array, which drifts from your files and skips locale resolution.

## What stays hidden

The tree respects the same visibility rules as everything else:

- `draft: true` hides a page in production.
- `navigation: false` keeps a page routable but drops it from the tree.
- A filename starting with `_` is a partial with no route.
- `collection` and `locale` options scope the whole tree.

In development and prerender, Ginko warns once when you `select` a field no schema knows, or when a `.navigation.yml` matches no folder in that locale. Production stays silent and never turns these into errors.
