title: Troubleshooting
description: Diagnose 404s, wrong URLs, empty navigation, search failures, locale fallback, validation errors, and provider limits.
---

## A page returns 404

Work down this list and stop at the first thing that is off:

1. The file matches the collection `source`.
2. The collection is `type: 'page'`.
3. The collection `route` matches the Nuxt page route.
4. The catch-all page imports the correct handle.
5. The document is not a partial or a production draft.
6. Your locale folders and the requested locale match the config.
7. `useContentPage` gets the fallback behavior you intended.

## A link uses the wrong URL

Render `document.route.resolvedPath` for document links, and the `path` field for navigation and search results. Do not render `canonicalKey`, `file`, or provider IDs as URLs.

Before you add redirect logic, inspect `route.requestedPath`, `route.resolvedPath`, and `route.alternates`.

## Navigation is empty

Check the handle, locale, source glob, and visibility fields. See whether every entry is a draft, a partial, or set to `navigation: false`. If the filesystem provider is not active, confirm your provider implements navigation.

## Search works in development but not production

- Preview the production output over HTTP, not the dev server.
- Confirm the MiniSearch or Pagefind assets shipped in the deploy.
- Move the search call outside `ClientOnly` when it needs SSR payload data.
- Confirm Pagefind ran against the generated HTML.
- Confirm the active locale has indexed content.
- For provider search, test the runtime endpoint and its credentials.

## Locale fallback is unexpected

Confirm Nuxt I18n and Ginko share the same locale codes and default locale. Inspect `resolution.requested`, `resolution.resolved`, and `usedFallback`. List queries do not mix fallback locales by default.

## Validation fails

Read the collection, source file, field path, and Zod issue together. Fix the authored value or the schema. Do not paper over invalid content inside a page component.

## A provider rejects a query

Compare the operators and pagination mode you requested against `provider.capabilities`. Unsupported behavior is meant to fail. Either narrow the query, or implement and test the missing capability in the provider.

## Agent Markdown is missing

Confirm `content.agent` routes are enabled, the content config declares an agent site, and the collection turns on agent Markdown. Static deploys must include the generated raw and LLM routes.

## Before you open an issue

Capture these so nobody has to guess:

- Ginko, Nuxt, Node, and package-manager versions;
- provider and deployment target;
- your minimal collection and module config;
- the exact route or query;
- development versus production behavior;
- the smallest content tree that reproduces it;
- the full error output.
