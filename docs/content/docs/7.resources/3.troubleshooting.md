---
title: Troubleshooting
description: Diagnose missing pages, incorrect routes, locale fallback, empty navigation, search failures, validation errors, and provider capability problems.
---

Start at the earliest failing boundary: source discovery, collection configuration, normalization, query, or rendering. Do not add frontend workarounds before identifying which boundary is wrong.

## A page returns 404

Check in order:

1. The file matches the collection `source`.
2. The collection is `type: 'page'`.
3. The collection `route` matches the Nuxt page route.
4. The catch-all page imports the correct handle.
5. The document is not a partial or hidden production draft.
6. Locale folders and requested locale match configuration.
7. `useContentPage` receives the intended fallback behavior.

## A link uses the wrong URL

Use `document.route.resolvedPath` for document links and navigation/search `path` for their normalized result types. Never render `canonicalKey`, `file`, or provider IDs as URLs.

Inspect `route.requestedPath`, `route.resolvedPath`, and `route.alternates` before adding redirect logic.

## Navigation is empty

Confirm the handle, locale, source glob, and visibility fields. Check whether every entry is a draft, partial, or `navigation: false`. Confirm the provider implements navigation when the filesystem provider is not active.

## Search works in development but not production

- Preview the production output through HTTP.
- Confirm MiniSearch or Pagefind assets were deployed.
- Confirm the search call runs outside `ClientOnly` when SSR payload data is required.
- Confirm Pagefind ran against generated HTML.
- Confirm the active locale has indexed content.
- For provider search, test the runtime endpoint and credentials.

## Locale fallback is unexpected

Confirm Nuxt I18n and Ginko share locale codes and default locale. Inspect `resolution.requested`, `resolution.resolved`, and `usedFallback`. Remember that list queries do not mix fallback locales by default.

## Validation fails

Read the collection, source file, field path, and Zod issue. Fix the authored value or schema. Do not coerce invalid content in a page component.

## A provider rejects a query

Compare requested operators and pagination mode with `provider.capabilities`. Unsupported behavior should fail. Either narrow the query or implement and test the missing capability in the provider.

## Agent Markdown is missing

Confirm `content.agent` routes are enabled, the content config declares an agent site, and the collection enables agent Markdown. Static deployments must include the generated raw and LLM routes.

## Escalation evidence

Before reporting a problem, capture:

- Ginko, Nuxt, Node, and package-manager versions;
- provider and deployment target;
- minimal collection and module config;
- exact route or query;
- development versus production behavior;
- the smallest reproducible content tree;
- full error output.
