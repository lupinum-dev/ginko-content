Repository examples verify distinct production integration boundaries. Use the focused snippets throughout the guides for individual APIs, and use playgrounds to explore complete applications.

## Maintained examples

| Outcome | Workspace path | Run |
| --- | --- | --- |
| Render route-backed pages | `examples/essentials/hello-world` | `pnpm example essentials/hello-world` |
| Query mixed content | `examples/queries/querying` | `pnpm example queries/querying` |
| Render MDC components | `examples/mdc/components` | `pnpm example mdc/components` |
| Custom transformer | `examples/advanced/transformer` | `pnpm example advanced/transformer` |

## Playgrounds

- `playground/ginko-basic` — core page, query, and rendering behavior.
- `playground/ginko-i18n` — locale variants, fallback, and translated routes.
- `playground/ginko-search` — MiniSearch behavior.
- `playground/ginko-search-i18n` — locale-scoped search.
- `playground/ginko-provider-search` — provider-owned search.

Run the default playground from the workspace root:

```bash
pnpm dev
```

Run another playground with its workspace scripts:

```bash
pnpm --dir playground/ginko-i18n dev
```

## Choosing an example

Start with the focused guide snippet for one API. Use a maintained example when you need its complete Nuxt integration boundary. Copying a full playground into an application also copies unrelated decisions and makes debugging harder.

Examples are executable documentation. If an example and a prose page disagree, treat the public types and passing example as evidence and correct the stale page.

## Verify examples

Repository maintainers run:

```bash
pnpm examples:build
```
