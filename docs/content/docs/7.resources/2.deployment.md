title: Deployment
description: Build, preview, and ship a Ginko site to static, Node SSR, serverless, or edge targets, and check the output.
---

Build the site and preview the exact output before you deploy anything:

```bash [terminal]
pnpm build
pnpm preview
```

Click through five things in the preview:

- the home page and one nested content page;
- the 404 response;
- one search result;
- direct-loading a nested route by pasting its URL.

If all five work here, the build is sound. Now pick a target.

## Static generation

```bash [terminal]
pnpm generate
```

Ginko contributes eligible page-collection routes to prerender discovery. Drafts, partials, and sitemap-excluded content stay out of the generated routes.

> **Serve the output over HTTP, never `file://`.** Open a nested route as a local file and asset paths, routing, and content negotiation all break in ways that vanish on a real host. Run any static server against the generated directory instead.

## Node SSR

The active provider runs during each request, so you get request-time reads, provider cache hints, and server middleware such as same-URL Markdown negotiation. Keep provider credentials and clients server-only, out of your page components.

## Serverless

Filesystem content reads prepared artifacts, so there is no runtime content database to warm up. Watch cold starts, request timeouts, and whether generated assets land in the function bundle. External providers need bounded request latency to stay inside those timeouts.

## Edge

Use an edge target only when every dependency supports that runtime: the provider, the Markdown pipeline, and the cache integration. Node-only provider SDKs and request-time filesystem reads do not run at the edge.

## Which search works where

| Target | MiniSearch | Pagefind | Provider search |
| --- | --- | --- | --- |
| Static | Yes | Yes | Only with a reachable runtime API |
| Node SSR | Yes | Generated-site dependent | Yes |
| Serverless | Yes | Generated-site dependent | Yes |
| Edge | Yes when assets are served | Generated-site dependent | Only with an edge-compatible provider |

## Agent-readable output

Static hosts serve the explicit generated Markdown routes: `/raw/**.md`, `/llms.txt`, and `/llms-full.txt`. Those work anywhere the HTML does. Same-URL `Accept: text/markdown` negotiation is different: it needs Nitro middleware, and a static host that returns HTML directly skips it.

## Before you ship

- Confirm content links resolve.
- Confirm drafts and partials are hidden outside development.
- Test locale fallback and alternates when i18n is on.
- Verify sitemap XML through `@nuxtjs/sitemap` when configured.
- Verify MiniSearch or Pagefind assets in the deployed output.
- Test old and new paths when the release includes redirects.
