---
title: Deployment
description: Deploy filesystem or provider-backed content through Nuxt SSR, static generation, serverless, or edge targets with explicit capability checks.
---

Ginko keeps the application content API stable across Nuxt deployment targets. The chosen provider and search engine determine which runtime capabilities the deployment must supply.

## Static generation

Best fit:

- filesystem content;
- Markdown that changes through deployment;
- MiniSearch or Pagefind;
- content routes known at generation time.

Run the application's generation command and deploy the complete output. Confirm nested routes, search assets, agent Markdown, and sitemap files are present.

## Node SSR

Best fit:

- filesystem or external providers;
- request-time content reads;
- provider cache hints and revalidation;
- server middleware such as Markdown content negotiation.

Node SSR can execute Ginko's runtime handlers. Keep credentials and provider clients server-only.

## Serverless

Best fit:

- prepared filesystem artifacts;
- providers with bounded request latency;
- response caching through the platform adapter.

Test cold starts, generated asset inclusion, request timeouts, and invalidation delivery. Ginko's filesystem path does not initialize a runtime content database.

## Edge

Use an edge target only when every dependency in the selected provider, Markdown pipeline, and cache integration supports that runtime. Avoid Node-only provider SDKs and filesystem assumptions at request time.

## Search matrix

| Deployment | MiniSearch | Pagefind | Provider search |
| --- | --- | --- | --- |
| Static | Yes | Yes | Only with reachable runtime API |
| Node SSR | Yes | Generated-site dependent | Yes |
| Serverless | Yes | Generated-site dependent | Yes |
| Edge | Yes when assets are served | Generated-site dependent | Only with edge-compatible provider |

## Agent-readable output

Static hosts serve explicit generated Markdown routes such as `/raw/**.md`, `/llms.txt`, and `/llms-full.txt`. Same-URL `Accept: text/markdown` negotiation requires Nitro middleware and is not guaranteed when a static host serves HTML directly.

## Verify

- Build using the production preset.
- Preview through HTTP.
- Direct-load nested content routes.
- Test search on a cold session.
- Inspect sitemap and agent outputs.
- Test provider failure and cache behavior when applicable.
- Test old and new paths when a release includes redirects.
