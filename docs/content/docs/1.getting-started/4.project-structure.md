With the default filesystem provider, files under `content/` are the source of truth. Collections tell the runtime which parts of that filesystem become a public data model.

## The content directory

All content lives under `content/` by default.

```txt
content/
  index.md
  about.md
  guide/
    index.md
    getting-started.md
    configuration.md
```

If a collection includes these files, they produce these routes:

- `/` from `content/index.md`
- `/about` from `content/about.md`
- `/guide` from `content/guide/index.md`
- `/guide/getting-started` from `content/guide/getting-started.md`

## Routing rules

- File extension is stripped from the path.
- `index.md` maps to the folder's own route.
- Numeric prefixes like `1.` are stripped from the URL but used for ordering.
- Files starting with `_` are partials — parsed and queryable, never routed.
- Files with a `.draft` segment (`post.draft.md`) are drafts — hidden in production, visible in dev.

```txt
content/
  1.guide/
    1.index.md           → /guide
    2.getting-started.md → /guide/getting-started
    _shared-intro.md     → not routed
    future-work.draft.md → hidden in prod
```

## Folder metadata

A folder that has an `index.md` uses that file's frontmatter as folder metadata. This is the preferred pattern.

A folder without an `index.md` can describe itself with `.navigation.yml`:

```yml [content/guide/.navigation.yml]
title: Guide
icon: i-lucide-book-open
order: 1
```

Valid `.navigation.yml` fields:

| Field | Type | Notes |
|---|---|---|
| `title` | string | Display label in navigation |
| `order` | number | Manual ordering when numeric prefixes aren't used |
| `icon` | string | Icon identifier (e.g. Iconify) |
| `hidden` | boolean | Hide from navigation but keep routable |
| `badge` | string or object | Optional badge text or config |
| `navigation` | false \| object | Set to `false` to drop the folder and descendants from nav entirely |

## Document identity

Every document carries system-owned identity fields, prefixed with `_`:

- `_id` — source-prefixed file id
- `_path` — public route path
- `_file` — path relative to `content/`, with extension
- `_locale` — inferred locale when URL includes one
- `_canonicalKey` — locale-agnostic identity used to merge variants
- `_collection` — name of the matching collection

These are available on every query result. Authors don't set them; the system does.

Authors may set `ref` or `id` in frontmatter when a document needs a stable
name for relationships or markdown links:

```md [content/guide/getting-started.md]
---
title: Getting started
ref: docs.getting-started
---
```

Then other markdown documents can link to it without hardcoding the route:

```md
Read [Getting started]($docs.getting-started).
```

Ginko resolves `$docs.getting-started` through the content graph first and uses
the current locale's route when the document is queried and rendered. If the
target translation is missing, the link stays in the requested locale and serves
the fallback document. Use this for cross-document links that should survive
file renames or translated slugs.
