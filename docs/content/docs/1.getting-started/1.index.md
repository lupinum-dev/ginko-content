@lupinum/ginko-content is a filesystem-first, provider-neutral content engine for Nuxt. Files still live naturally in `content/`, but the public runtime contract is explicit: define a collection, query that collection, resolve routes through it.

## The model

The module is designed so there is one public product lane instead of two competing ones.

**Collections define the public surface.** If you want to query or render content through the public APIs, that content belongs to a collection.

**Nuxt pages resolve through `useContentPage()`.** Route-backed pages use the product-level page helper for loading, locale route state, and fallback behavior. Raw document lists use `many(handle, options)`.

**Schemas are optional but encouraged.** A minimal collection can be just a glob. Add Zod when you want guarantees.

That keeps the API coherent:

- no raw path-query API alongside the collection API
- no app-owned sitemap glue for content routes
- no second i18n contract hiding in `content.config.ts`
- no ambiguity about which data model drives rendering

## What you opt into

- **Markdown configuration** — Shiki theme, extra highlight languages, and Comark markdown plugins
- **Typed collections** — Zod-validated schemas with typed query results
- **Cross-document references** — `reference()` helper for schema fields that point at other documents
- **Internationalization** — Locale detection, fallback chains, shared or translated slugs
- **Search** — MiniSearch or Pagefind full-text search built into `@lupinum/ginko-content`
