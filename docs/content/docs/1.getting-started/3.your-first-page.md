title: Your first page
description: Walk through what happens when a Markdown file joins a collection.
---

A Markdown file becomes queryable and routable when it belongs to a collection. This page follows one file from `content/hello.md` to a rendered page at `/hello`.

## The collection

Declare the files that belong to the public `pages` collection:

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@lupinum/ginko-content/config'

export const pages = defineCollection({
  type: 'page',
  source: '**/*.md'
})

export default defineContentConfig({
  collections: { pages }
})
```

## The file

Add a Markdown file that matches the collection glob:

```md [content/hello.md]
---
title: Hello, world
description: A minimal page.
---

# Hello, world

This is a paragraph.
```

Three things happened when you saved it:

1. The file was parsed as Markdown.
2. The frontmatter was extracted into metadata (`title`, `description`).
3. The document became queryable and routable through the `pages` collection at `/hello`.

## The path

The route is derived from the file path relative to the collection source:

- `content/hello.md` → `/hello`
- `content/guide/intro.md` → `/guide/intro`
- `content/index.md` → `/`
- `content/guide/index.md` → `/guide`

Numeric prefixes control order without showing in the URL:

- `content/1.guide/1.intro.md` → `/guide/intro`

Use this to order sidebar navigation without cluttering your URLs.

## The body

The Markdown after the frontmatter becomes `body`. When you render it with `<ContentRenderer>`, headings, paragraphs, lists, code blocks, and MDC components all come through:

```vue [pages/[...slug].vue]
<script setup lang="ts">
import { createError } from '#imports'
import { pages } from '~/content.config'

const { page } = await useContentPage(pages)

if (import.meta.server && !page.value) {
  throw createError({ statusCode: 404, statusMessage: 'Page not found' })
}
</script>

<template>
  <ContentRenderer v-if="page" :value="page" />
</template>
```

`useContentPage()` owns the route lookup, but it does not raise a default 404 — it never throws and has no `notFound` option. The route component checks `page.value` itself and decides what to do, as shown above.

## The frontmatter

Fields you define in frontmatter are accessible on the document:

```md [content/hello.md]
---
title: Hello, world
description: A minimal page.
author: Jane
published: true
---
```

```ts
import { one } from '@lupinum/ginko-content/client'

const page = await one(pages, {
  by: { path: '/hello' }
})
page.title       // "Hello, world"
page.description // "A minimal page."
page.author      // "Jane"
page.published   // true
```

Without a schema, frontmatter fields are typed as `unknown`. With a [typed collection](/docs/collections), they become first-class typed fields.

## The table of contents

Headings produce a table of contents on the parsed body:

```ts
const page = await one(pages, {
  by: { path: '/hello' }
})
page?.body?.toc // { links: [{ id: 'hello-world', text: 'Hello, world', depth: 1 }] }
```
