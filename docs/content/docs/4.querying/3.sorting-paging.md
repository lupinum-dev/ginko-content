---
title: Sorting and Paging
description: Order and page collection results with unified query options.
---

Sorting and paging stay intentionally small:

- `sort: { field: 'asc' | 'desc' }`
- `limit`
- `skip`
- `paginate()` when the UI needs total/page metadata

## Sort descending

`many`, `paginate`, and the other query functions come from `@lupinum/ginko-content/client` (they are not auto-imported):

```ts
import { many } from '@lupinum/ginko-content/client'

await many(articles, {
  sort: { date: 'desc' }
})
```

## Sort with paging

```ts
await many(articles, {
  sort: { date: 'desc' },
  skip: 10,
  limit: 10
})
```

## Page metadata

Use `paginate()` for blog indexes, archive pages, and infinite-list entry points that need total count and previous/next state.

```ts
import { paginate } from '@lupinum/ginko-content/client'

const page = await paginate(articles, {
  sort: { date: 'desc' },
  page: 2,
  limit: 10
})

page.data
page.total
page.pageCount
page.hasNext
page.nextPage
```

In Vue components, pair `paginate()` with `useAsyncData` and a stable, reactive key:

```ts
import { useAsyncData } from '#imports'
import { paginate } from '@lupinum/ginko-content/client'

const route = useRoute()
const currentPage = computed(() => Number(route.query.page || 1))
const { data: result } = await useAsyncData(
  () => `articles-page:${currentPage.value}`,
  () => paginate(articlesCollection, {
    page: currentPage.value,
    limit: 10,
    sort: { date: 'desc' }
  }),
  { watch: [currentPage] }
)

const articles = computed(() => result.value?.data ?? [])
const pageCount = computed(() => result.value?.pageCount ?? 0)
const hasNext = computed(() => result.value?.hasNext ?? false)
const nextPage = computed(() => result.value?.nextPage ?? null)
```

## Multiple sort keys

Pass an ordered sort object:

```ts
await many(articles, {
  sort: {
    featured: 'desc',
    date: 'desc'
  }
})
```

## Locale-aware string ordering

```ts
await many(docs, {
  sort: { title: 'asc' },
  locale: 'de'
})
```
