Install Ginko in a Nuxt 4 application and define one page collection. No content database setup is required.

## Requirements

- Nuxt 4.4.7 through Nuxt 4.x
- Vue 3.5 or later
- Node.js 22 or later
- A package manager supported by Nuxt

## Add the module

```bash
npx nuxi module add @lupinum/ginko-content
```

Or install and register it explicitly:

::code-group
```bash [pnpm]
pnpm add @lupinum/ginko-content zod
```

```bash [npm]
npm install @lupinum/ginko-content zod
```

```bash [yarn]
yarn add @lupinum/ginko-content zod
```
::

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/ginko-content']
})
```

## Define the page collection

Create `content.config.ts` at the application root:

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@lupinum/ginko-content/config'
import { z } from 'zod'

export const pages = defineCollection({
  type: 'page',
  source: '**/*.md',
  schema: z.object({
    title: z.string(),
    description: z.string().optional()
  })
})

export default defineContentConfig({
  collections: { pages }
})
```

The exported `pages` value is a typed collection handle. Page components and queries import it instead of repeating a string collection name.

## Verify preparation

Start Nuxt:

```bash
pnpm dev
```

Ginko prepares generated types and watches the content directory. An empty collection is valid at this point.

If Nuxt cannot find `content.config.ts`, confirm that the file is at the application root and exports `defineContentConfig(...)` as default.
