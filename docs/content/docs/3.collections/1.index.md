Collections turn a directory of files into a typed, validated dataset. You define the shape with a Zod schema; queries then return fully typed results.

## Why

Collections are the runtime contract. They are not the “advanced mode” on top of a separate raw-path API.

They give you guarantees:

- Every article has a `date` that's actually a date
- Every author has an `avatar` field
- Typos in frontmatter fail the build, not a runtime render
- `many(articles)` returns `Article[]`, not `unknown[]`

Collections make those guarantees without changing where your content lives.

## A minimal collection

```ts [content.config.ts]
import { defineContentConfig, defineCollection } from '@lupinum/ginko-content/config'
import { z } from 'zod'

export default defineContentConfig({
  collections: {
    articles: defineCollection({
      type: 'page',
      source: 'articles/**/*.md',
      schema: z.object({
        title: z.string(),
        description: z.string().optional(),
        date: z.coerce.date(),
        tags: z.array(z.string()).default([])
      })
    })
  }
})
```

A file under `content/articles/`:

```md [content/articles/hello.md]
---
title: Hello, world
date: 2026-01-15
tags: [intro]
---

# Hello, world
```

Querying this collection is fully typed:

```ts
const list = await many(articles, {
  sort: { date: 'desc' },
  limit: 10
})

list[0].title // string
list[0].date  // Date
list[0].tags  // string[]
```

If a file in the collection has frontmatter that doesn't match the schema, the build fails with a clear error pointing at the file.

## What a collection defines

A collection has three parts:

**Type** — whether the collection is route-backed page content or data content.
**Source** — which files belong. Relative to `content/`.
**Schema** — a Zod object describing the frontmatter.
**Options** — optional configuration (`strict`, collection-level `i18n`, references).

```ts
defineCollection({
  type: 'page',
  source: 'articles/**/*.md',
  schema,
  strict: true
})
```

## When to use collections

If you want to query or render content through the public APIs, define a collection for it. Start with one broad `pages` collection if you do not need more structure yet.
