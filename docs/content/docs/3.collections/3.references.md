A reference is a pointer from one document to another. Prefer `fields.relation()` for one reference and `fields.relations()` for many references. These helpers keep the Zod validation, and they also give CMS integrations enough metadata to render relation pickers.

## A minimal reference

An article references one author:

```ts [content.config.ts]
import { defineCollection, defineContentConfig, fields } from '@lupinum/ginko-content/config'
import { z } from 'zod'

export const authors = defineCollection({
  type: 'data',
  source: 'authors/**/*.md',
  schema: z.object({
    name: fields.text().required(),
    avatar: fields.object({
      src: fields.image().required(),
      alt: fields.text()
    })
  })
})

export const articles = defineCollection({
  type: 'page',
  source: 'articles/**/*.md',
  schema: z.object({
    title: fields.text().required(),
    author: fields.relation('authors').required()
  })
})

export default defineContentConfig({
  collections: { authors, articles }
})
```

In the Markdown file, the reference is a string:

```md [content/articles/hello.md]
---
title: Hello, world
author: jane-doe
---

# Hello, world
```

At query time the field stays a string:

```ts
const article = await one(articles, {
  by: { path: '/articles/hello' }
})

article.author // "jane-doe"
```

That is intentional. Ginko validates and types the field, but does not silently inline another document into the query result.

## Many-to-many

Tag articles with multiple topics:

```ts
defineCollection({
  type: 'page',
  source: 'articles/**/*.md',
  schema: z.object({
    title: fields.text().required(),
    topics: fields.relations('topics')
  })
})
```

```md [content/articles/hello.md]
---
title: Hello, world
topics: [intro, markdown]
---
```

The stored value is still an array of strings.

## Matching rules

A reference matches in this order:

1. The target's canonical key
2. `ref` frontmatter of a target document
3. The target's path and source-path candidates

Use `ref` when you want a stable alias that survives file renames. (Frontmatter
`id` is reserved by the system and no longer acts as a reference alias — use
`ref` instead.)

```md [content/authors/jane-doe.md]
---
ref: author-jane
name: Jane Doe
---
```

`author-jane` matches from another document.

Markdown body links can use the same identity vocabulary with a `$` prefix:

```md
Read the [intro]($docs.intro#setup).
```

Ginko resolves `$docs.intro` through the content graph when the source document
is queried. In localized collections, the rendered link points at the requested
locale's variant and falls back through the configured locale chain when a
translation is missing. Fallback links keep the requested-locale URL and serve
the fallback document.

## Querying references

Reference fields are plain strings at the storage layer. Query them like any other field:

```ts
const byJane = await many(articles, {
  where: { author: 'jane-doe' }
})

const tagged = await many(articles, {
  where: { topics: { $contains: 'intro' } }
})
```

## Backlinks

Use `backlinks()` when you have a target document and need the source documents that reference it. Typed source handles infer top-level `reference()` fields automatically.

```ts
const postsByJane = await backlinks(authors, {
  by: { ref: 'jane-doe' },
  from: articles,
  sort: { date: 'desc' }
})
```

In Vue components, `useContentBacklinks()` gives the same behavior with reactive options:

```ts
const { data: articles } = await useContentBacklinks(authors, {
  by: { ref: () => route.params.author },
  from: articles
})
```

## Resolving a reference target

When you need the referenced document itself, resolve it explicitly on the server:

```ts [server/api/author.get.ts]
import { one } from '#content/server'
import { articles, authors } from '~/content.config'

export default defineEventHandler(async (event) => {
  const article = await one(event, articles, {
    by: { path: '/articles/hello' }
  })

  if (!article?.author) {
    return null
  }

  return one(event, authors, {
    by: { ref: article.author }
  })
})
```

Reference resolution respects locale fallback when you pass `locale` and `fallback` options.
