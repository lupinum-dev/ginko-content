---
title: defineCollection
description: The signature, options, and schema patterns for declaring a collection.
---

`defineCollection(name, { type, source?, ...options })` declares one named collection handle. Use that handle inside `defineContentConfig({ collections })`.

## Signature

```ts
defineCollection(
  name: string,
  {
    type: 'page' | 'data'
    source?: string | string[] | {
      include: string | string[]
      exclude?: string | string[]
    }
    schema?: ZodType
    strict?: boolean
    i18n?: true | {
      defaultLocale: string
      locales: string[]
    }
    route?: string | Record<string, string>
    translatedSlugs?: boolean
    sitemap?: boolean
  }
)
```

## The source glob

The source glob is resolved relative to the `content/` directory. It is required for filesystem-backed collections and optional when an external provider supplies the collection data.

```ts
defineCollection('articles', { type: 'page', source: 'articles/**/*.md' })   // all articles
defineCollection('docs', { type: 'page', source: 'docs/**/*.md' })           // all docs
defineCollection('authors', { type: 'data', source: 'authors/*.yml' })       // flat data directory
defineCollection('pages', { type: 'page', source: '**/*.md' })               // everything
defineCollection('guides', { type: 'page', source: ['guides/**/*.md', 'guides/**/*.yml'] }) // one collection, multiple globs
```

A file must match at most one collection. Overlapping collection globs are invalid and fail with `CONFLICTING_COLLECTION_MATCH`.

Use `source.exclude` when the include glob needs a local exclusion:

```ts
defineCollection('docs', {
  type: 'page',
  source: {
    include: 'docs/**/*.md',
    exclude: 'docs/private/**'
  }
})
```

## The schema

Schemas use [Zod](https://zod.dev). Prefer Ginko's `fields` helpers for content fields that should also drive CMS editing, relation handling, and richer form controls. Plain Zod remains supported for custom validation and data shapes.

```ts [content.config.ts]
import { defineCollection, defineContentConfig, fields } from '@lupinum/ginko-content/config'
import { z } from 'zod'
```

### Common field patterns

```ts
z.object({
  title: fields.text().required(),
  description: fields.textarea(),
  slug: fields.slug({ from: 'title' }),
  draft: fields.boolean(),
  featured: fields.boolean(),
  date: fields.date().required(),
  updatedAt: fields.datetime(),
  tags: z.array(z.string()).default([]),
  status: fields.select(['draft', 'published', 'archived']),
  author: fields.object({
    name: fields.text().required(),
    avatar: fields.object({
      src: fields.image().required(),
      alt: fields.text()
    })
  })
})
```

### References to other collections

Use `fields.relation()` and `fields.relations()` to declare validated references that CMS providers can render as relation pickers. The lower-level `reference()` helper remains available for plain Zod schemas. See [References](/docs/collections/references) for the full rules.

```ts
import { defineCollection, defineContentConfig, fields } from '@lupinum/ginko-content/config'
import { z } from 'zod'

defineCollection('articles', {
  type: 'page',
  source: 'articles/**/*.md',
  schema: z.object({
    title: fields.text().required(),
    author: fields.relation('authors').required()
  })
})
```

## Strict mode

Schema validation is strict by default in the collection sense. A matched document that does not satisfy declared schema fields fails validation unless you explicitly set collection `strict: false`.

```ts
defineCollection('docs', {
  type: 'page',
  source: 'docs/**/*.md',
  schema: z.object({
    title: z.string(),
    description: z.string().optional()
  })
})
```

Use `strict: false` only when you want schema failures to warn and let the original document through during an incremental migration. Use Zod's `.strict()` on an object schema when unknown frontmatter keys should fail too.

## Collection i18n

Collections can opt into the global i18n config, or provide their own locale set:

```ts
defineCollection('docs', {
  type: 'page',
  source: 'docs/**/*.md',
  i18n: true,
  schema
})
```

Or explicitly scope the collection:

```ts
defineCollection('authors', {
  type: 'data',
  source: 'authors/*.yml',
  i18n: {
    defaultLocale: 'en',
    locales: ['en', 'de']
  }
})
```

## Example

```ts [content.config.ts]
import { defineCollection, defineContentConfig, fields } from '@lupinum/ginko-content/config'
import { z } from 'zod'

const author = z.object({
  name: fields.text().required(),
  avatar: fields.object({
    src: fields.image().required(),
    alt: fields.text()
  }),
  bio: fields.richtext()
})

export const authors = defineCollection('authors', {
  type: 'data',
  source: 'authors/**/*.md',
  i18n: true,
  schema: author
})

export const articles = defineCollection('articles', {
  type: 'page',
  source: 'articles/**/*.md',
  strict: true,
  schema: z.object({
    title: fields.text().required(),
    description: fields.textarea().required(),
    date: fields.date().required(),
    tags: z.array(z.string()).default([]),
    author: fields.relation('authors').required(),
    cover: fields.image()
  })
})

export const pages = defineCollection('pages', {
  type: 'page',
  source: '*.md',
  schema: z.object({
    title: fields.text().required(),
    description: fields.textarea()
  })
})

export default defineContentConfig({
  collections: {
    authors,
    articles,
    pages
  }
})
```
