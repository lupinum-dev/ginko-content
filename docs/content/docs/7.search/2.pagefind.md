---
title: Pagefind
description: Use Pagefind as the static search backend.
---

Pagefind gives generated sites a static search index without running a search server. Ginko writes Pagefind assets during build or generation, and app components search those assets in the browser.

## Enable Pagefind

Install Pagefind in the app that enables it:

```bash
pnpm add -D pagefind
```

Switch the search engine in `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/ginko-content'],
  content: {
    search: {
      engine: 'pagefind'
    }
  }
})
```

Running `nuxt build` or `nuxi generate` produces a `pagefind/` directory in the public output.

## Use the same composable

`useContentSearch()` keeps the same API when the backend changes:

```vue [components/DocsSearch.vue]
<script setup lang="ts">
import { useContentSearch } from '@lupinum/ginko-content/client'

const search = await useContentSearch()
</script>
```

With `engine: 'pagefind'`, the composable imports `/pagefind/pagefind.js`, searches through Pagefind, and normalizes hits to the same result shape as the MiniSearch backend.

## Deploy Pagefind assets

Pagefind indexes are static files. Deploy the generated `pagefind/` directory with the rest of your Nuxt output.

No search server is required. The browser loads the Pagefind module and matching index chunks from your static host.

## Choose between MiniSearch, Pagefind, and external search

Use [Choosing a search backend](/docs/search/choosing-a-search-backend) to decide whether Pagefind fits your site. Pagefind is usually the built-in option to consider when you still want static hosting, but one MiniSearch index is no longer the shape you want.
