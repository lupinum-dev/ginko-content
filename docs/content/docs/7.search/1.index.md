Search lets you add full-text results for your content without wiring your own indexer. Pick the UI surface first, then choose the search backend that matches your site.

## Choose a search surface

Ginko exposes three app-facing helpers:

| You want | Use |
|---|---|
| A Nuxt UI command palette | `useContentSearchData()` with `UContentSearch` |
| A custom combobox, modal, or keyboard-driven palette | `useContentSearch()` |
| A custom search input, modal, or results page | `useContentSearchResults()` |

The UI surface is separate from the backend. `useContentSearch()` and `useContentSearchResults()` work with MiniSearch, Pagefind, and provider-owned search. `useContentSearchData()` prepares `files`, `searchNavigation`, and `searchTerm` for Nuxt UI's `UContentSearch`.

## Nuxt UI ContentSearch

Use `useContentSearchData()` when your app already uses Nuxt UI and you want its native command palette search pattern.

```vue [app.vue]
<script setup lang="ts">
import { useContentSearchData } from '@lupinum/ginko-content/client'

const {
  files,
  searchNavigation,
  searchTerm
} = await useContentSearchData('docs')
</script>

<template>
  <UApp>
    <ClientOnly>
      <UContentSearch
        v-model:search-term="searchTerm"
        :files="files"
        :navigation="searchNavigation"
        shortcut="meta_k"
      />
    </ClientOnly>
  </UApp>
</template>
```

Keep `useContentSearchData()` outside `ClientOnly`. Nuxt can then include the search data in the prerendered payload, while `UContentSearch` still renders only on the client.

For localized content, pass the active locale:

```ts
const {
  files,
  searchNavigation,
  searchTerm
} = await useContentSearchData('docs', {
  locale: locale.value
})
```

## Custom search UI

Use `useContentSearch()` when you want headless state for a combobox, modal, or command palette. It owns the query ref, active result index, movement helpers, and selection without prescribing markup.

```vue [components/DocsSearch.vue]
<script setup lang="ts">
import { useContentSearch } from '@lupinum/ginko-content/client'

const search = await useContentSearch({
  limit: 8,
  locale: computed(() => 'en')
})
</script>

<template>
  <input
    v-model="search.query.value"
    type="search"
    @keydown.down.prevent="search.next()"
    @keydown.up.prevent="search.previous()"
  >

  <ul v-if="search.hasResults.value">
    <li
      v-for="(result, index) in search.results.value"
      :key="`${result.path}:${result.anchor || ''}`"
      :aria-selected="index === search.activeIndex.value"
      @mouseenter="search.setActiveIndex(index)"
    >
      <NuxtLink :to="result.anchor ? `${result.path}#${result.anchor}` : result.path">
        {{ result.title }}
      </NuxtLink>
    </li>
  </ul>
</template>
```

Use `useContentSearchResults()` when you want to own the input, layout, result rendering, or route behavior.

```vue [components/DocsSearch.vue]
<script setup lang="ts">
import { useContentSearchResults } from '@lupinum/ginko-content/client'

const searchTerm = ref('')
const { results, pending, error } = await useContentSearchResults(searchTerm)
</script>

<template>
  <label for="docs-search" class="sr-only">Search docs</label>
  <input
    id="docs-search"
    v-model="searchTerm"
    type="search"
    placeholder="Search docs"
  >

  <p v-if="pending">Searching...</p>
  <p v-else-if="error">Search is unavailable.</p>

  <ul v-else-if="results.length">
    <li v-for="result in results" :key="`${result.path}:${result.anchor || ''}`">
      <NuxtLink :to="result.anchor ? `${result.path}#${result.anchor}` : result.path">
        <span>{{ result.title }}</span>
        <p>{{ result.excerpt }}</p>
      </NuxtLink>
    </li>
  </ul>
</template>
```

`useContentSearchResults()` takes a reactive search term and returns reactive `results`, `pending`, and `error`.

## What works when prerendered

Search works in generated sites when the generated assets are served with the rest of the app.

- `useContentSearchData()` fetches navigation and search sections during rendering, so Nuxt can serialize them into the prerendered payload.
- The MiniSearch backend reads the generated search index.
- The Pagefind backend reads the generated `pagefind/` files.
- The initial Nuxt UI search data does not require a live content API after prerendering.

Run a generated preview when changing search. It catches missing search assets, stale payload data, and locale-specific routing mistakes.

## Configure the backend

Search is configured in `nuxt.config.ts` under `content.search`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/ginko-content'],
  content: {
    search: {
      engine: 'minisearch',
      ignoredTags: ['script', 'style', 'pre'],
      filterQuery: { _draft: false, _partial: false }
    }
  }
})
```

Use the MiniSearch backend for the default static index. Use [Pagefind](/docs/search/pagefind) when you want a static, sharded search index. Use `engine: 'cms'` when the active content provider owns search. Use [Choosing a search backend](/docs/search/choosing-a-search-backend) when you need to decide between MiniSearch, Pagefind, provider-owned search, and an external search service.

## Result shape

Custom search results include the route plus enough metadata to link to a matching heading:

```ts
{
  path: '/docs/collections/references',
  anchor: 'many-to-many',
  title: 'Many-to-many',
  excerpt: 'Tag articles with multiple topics...',
  score: 0.87,
  locale: 'en'
}
```

Route to `path#anchor` when `anchor` is present.

## Scope results to a locale

Pass a locale when your app renders one locale at a time:

```ts
import { useContentSearchResults } from '@lupinum/ginko-content/client'

const searchTerm = ref('')
const locale = computed(() => 'en')
const { results } = await useContentSearchResults(searchTerm, { locale })
```

Locale scoping filters the built-in results. Use `content.search.filterQuery` to shape the indexed content before search runs.
