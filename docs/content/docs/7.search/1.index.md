Search lets you add full-text results for your content without wiring your own indexer. `useContentSearch()` is the single composable behind every search surface — pick the UI pattern that fits your app.

## Choose a search surface

| You want | Use |
|---|---|
| A Nuxt UI command palette | `useContentSearch({ collection })` with `UContentSearch` |
| A custom combobox, modal, or keyboard-driven palette | `useContentSearch()` |
| A custom search input, modal, or results page | `useContentSearch()`, driven by `setQuery()` |

`useContentSearch()` works with MiniSearch, Pagefind, and provider-owned search. Passing `options.collection` additionally loads that collection's `files` and `searchNavigation`, for apps that want Nuxt UI's native command palette pattern.

## Nuxt UI ContentSearch

Pass `collection` when your app already uses Nuxt UI and you want its native command palette search pattern.

```vue [app.vue]
<script setup lang="ts">
import { useContentSearch } from '@lupinum/ginko-content/client'
import { docs } from '~/content.config'

const {
  query,
  files,
  searchNavigation
} = await useContentSearch({ collection: docs })
</script>

<template>
  <UApp>
    <ClientOnly>
      <UContentSearch
        v-model:search-term="query"
        :files="files"
        :navigation="searchNavigation"
        shortcut="meta_k"
      />
    </ClientOnly>
  </UApp>
</template>
```

Keep the `useContentSearch({ collection })` call outside `ClientOnly`. Nuxt can then include the search data in the prerendered payload, while `UContentSearch` still renders only on the client.

For localized content, pass the active locale:

```ts
const {
  query,
  files,
  searchNavigation
} = await useContentSearch({
  collection: docs,
  locale: locale.value
})
```

## Custom search UI

Omit `collection` for headless state over a combobox, modal, or command palette. It owns the query ref, active result index, movement helpers, and selection without prescribing markup.

```vue [components/DocsSearch.vue]
<script setup lang="ts">
import { useContentSearch } from '@lupinum/ginko-content/client'

const search = await useContentSearch({
  limit: 8,
  locale: computed(() => 'en')
})
</script>

<template>
  <input
    v-model="search.query.value"
    type="search"
    @keydown.down.prevent="search.next()"
    @keydown.up.prevent="search.previous()"
  >

  <ul v-if="search.hasResults.value">
    <li
      v-for="(result, index) in search.results.value"
      :key="`${result.path}:${result.anchor || ''}`"
      :aria-selected="index === search.activeIndex.value"
      @mouseenter="search.setActiveIndex(index)"
    >
      <NuxtLink :to="result.anchor ? `${result.path}#${result.anchor}` : result.path">
        {{ result.title }}
      </NuxtLink>
    </li>
  </ul>
</template>
```

For a custom search input, modal, or results page, drive the same composable with `setQuery()` and read `results`/`pending`/`error` directly:

```vue [components/DocsSearch.vue]
<script setup lang="ts">
import { useContentSearch } from '@lupinum/ginko-content/client'

const search = await useContentSearch()
</script>

<template>
  <label for="docs-search" class="sr-only">Search docs</label>
  <input
    id="docs-search"
    :value="search.query.value"
    type="search"
    placeholder="Search docs"
    @input="search.setQuery(($event.target as HTMLInputElement).value)"
  >

  <p v-if="search.pending.value">Searching...</p>
  <p v-else-if="search.error.value">Search is unavailable.</p>

  <ul v-else-if="search.hasResults.value">
    <li v-for="result in search.results.value" :key="`${result.path}:${result.anchor || ''}`">
      <NuxtLink :to="result.anchor ? `${result.path}#${result.anchor}` : result.path">
        <span>{{ result.title }}</span>
        <p>{{ result.excerpt }}</p>
      </NuxtLink>
    </li>
  </ul>
</template>
```

`useContentSearch()` exposes a writable `query` ref and reactive `results`, `pending`, and `error`.

## What works when prerendered

Search works in generated sites when the generated assets are served with the rest of the app.

- `useContentSearch({ collection })` fetches navigation and search sections during rendering, so Nuxt can serialize them into the prerendered payload.
- The MiniSearch backend reads the generated search index.
- The Pagefind backend reads the generated `pagefind/` files.
- The initial Nuxt UI search data does not require a live content API after prerendering.

Run a generated preview when changing search. It catches missing search assets, stale payload data, and locale-specific routing mistakes.

## Configure the backend

Search is configured in `nuxt.config.ts` under `content.search`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/ginko-content'],
  content: {
    search: {
      engine: 'minisearch',
      ignoredTags: ['script', 'style', 'pre'],
      filterQuery: { draft: false, partial: false }
    }
  }
})
```

Use the MiniSearch backend for the default static index. Use [Pagefind](/docs/search/pagefind) when you want a static, sharded search index. Use `engine: 'provider'` when the active content provider owns search. Use [Choosing a search backend](/docs/search/choosing-a-search-backend) when you need to decide between MiniSearch, Pagefind, provider-owned search, and an external search service.

When `content.search.collections` is omitted, Ginko indexes route-backed public collections only. Data-only collections stay out of the public search index unless you list collections explicitly.

## Result shape

Custom search results include the route plus enough metadata to link to a matching heading:

```ts
{
  collection: 'docs',
  path: '/docs/collections/references',
  anchor: 'many-to-many',
  title: 'Many-to-many',
  excerpt: 'Tag articles with multiple topics...',
  score: 0.87,
  locale: 'en'
}
```

Route to `path#anchor` when `anchor` is present.

Use `collection` for app-owned result routing when multiple content collections
share one search UI. Do not infer identity from URL prefixes.

## Scope results to a locale

Pass a locale when your app renders one locale at a time:

```ts
import { useContentSearch } from '@lupinum/ginko-content/client'

const locale = computed(() => 'en')
const search = await useContentSearch({ locale })
```

Locale scoping filters the built-in results. Use `content.search.filterQuery` to shape the indexed content before search runs.
