`content.config.ts` declares the document model. It defines collections, schemas, and typed references; runtime behavior such as markdown plugins and search belongs in `nuxt.config.ts`.

## defineContentConfig

Wrap the root content configuration.

```ts
defineContentConfig(config: ContentConfig): ContentConfig
```

```ts [content.config.ts]
import { defineContentConfig } from '@lupinum/ginko-content/config'

export default defineContentConfig({
  provider: 'filesystem',
  providers: {},
  collections: { /* ... */ }
})
```

`collections` is the main field. `provider` selects the active content backend, and `providers` registers external provider modules. Export each `defineCollection()` result when app or server code needs to import the typed handle for `one(handle)`, `many(handle)`, `useContentPage(handle)`, `useContentOne(handle)`, and server-side collection helpers.

## defineCollection

Declare a typed collection.

```ts
defineCollection(
  name: string,
  {
    type: 'page' | 'data'
    source?: string | string[] | {
      include: string | string[]
      exclude?: string | string[]
    }
    schema?: ZodType
    strict?: boolean
    i18n?: true | {
      defaultLocale: string
      locales: string[]
    }
    route?: string | Record<string, string>
    translatedSlugs?: boolean
    sitemap?: boolean
  }
): Collection
```

```ts
import { defineCollection, fields } from '@lupinum/ginko-content/config'
import { z } from 'zod'

export const articles = defineCollection('articles', {
  type: 'page',
  source: 'articles/**/*.md',
  schema: z.object({
    title: fields.text().required(),
    date: fields.date().required(),
    draft: fields.boolean()
  })
})
```

Use `type: 'page'` for route-backed content and `type: 'data'` for data-only collections. Route-backed page collections are the sitemap/prerender source. Data collections default to `sitemap: false`; if content needs a public URL, model it as `type: 'page'` with a route instead of forcing a data collection into sitemap output.

Schema validation is strict by default in the collection sense: schema failures stop the build. Set collection `strict: false` only when schema failures should warn and let the original document through during a migration. Use Zod's `.strict()` on an object schema when unknown frontmatter keys should fail too.

## fields

Preferred schema helpers for content fields. They return Zod schemas with extra metadata for CMS integrations.

```ts
fields.text()
fields.textarea()
fields.richtext()
fields.slug({ from?: string })
fields.email()
fields.url()
fields.number()
fields.boolean()
fields.date()
fields.datetime()
fields.select(['draft', 'published'])
fields.object({ ...shape })
fields.array(item)
fields.image()
fields.asset()
fields.file()
fields.relation('authors')
fields.relations('topics')
```

Every helper supports:

```ts
fields.text()
  .label('Title')
  .help('Shown in cards and SEO metadata')
  .localized()
  .required()
```

Plain Zod remains supported as a fallback, but `fields.*` is the recommended API when the schema should also drive CMS forms.

## reference

Declare a reference field from one collection to another.

```ts
reference(target?: string): ZodString
```

```ts
import { defineCollection, fields, reference } from '@lupinum/ginko-content/config'
import { z } from 'zod'

defineCollection('articles', {
  type: 'page',
  source: 'articles/**/*.md',
  schema: z.object({
    title: fields.text().required(),
    author: fields.relation('authors').required(),
    topics: fields.relations('topics')
  })
})
```

`reference()` is the lower-level Zod marker used by `fields.relation()` internally. Use it directly only when you need plain Zod without CMS metadata. Resolve the target explicitly when you need the referenced document itself.

## Export map

`@lupinum/ginko-content/config` exports the config helpers and schema metadata helpers used by content packages:

| Export | Use |
|---|---|
| `defineContentConfig` | Wrap the root `content.config.ts` object |
| `defineCollection` | Declare one named collection handle |
| `fields` | Preferred field helper namespace |
| `reference` | Low-level string reference marker |
| `text`, `richtext`, `asset`, `file`, `image`, `relation`, `relations` | Direct field helper aliases |
| `getContentFieldMetadata` | Read CMS/editor metadata from a field schema |
| `isContentFieldSchema` | Detect a schema created by a field helper |
| `slugifyUrlSegment` | Apply the same URL segment slugification used by content paths |

Type exports include `ContentConfig`, `ContentCollectionConfig`, `DefineCollectionObject`, `CollectionSchema`, `ContentFieldSchema`, `ContentFieldMetadata`, CMS field config types, and `SlugifyUrlSegmentOptions`.
