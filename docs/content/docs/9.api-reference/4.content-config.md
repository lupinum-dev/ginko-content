`content.config.ts` declares the document model. It defines collections, schemas, and typed references; runtime behavior such as markdown plugins and search belongs in `nuxt.config.ts`.

## defineContentConfig

Wrap the root content configuration.

```ts
defineContentConfig(config: ContentConfig): ContentConfig
```

```ts [content.config.ts]
import { defineContentConfig } from '@lupinum/ginko-content/config'

export default defineContentConfig({
  collections: { /* ... */ }
})
```

`collections` is the main field. Each key becomes a collection handle used by `one(handle)`, `many(handle)`, `useContentOne(handle)`, and server-side collection helpers.
Export a collection handle when app code imports it. Otherwise a local `const` inside `content.config.ts` is enough.

## defineCollection

Declare a typed collection.

```ts
defineCollection(
  name: string,
  {
    type: 'page' | 'data'
    source: string | string[] | {
      include: string | string[]
      exclude?: string | string[]
    }
    schema?: ZodType
    strict?: boolean
    i18n?: true | {
      defaultLocale: string
      locales: string[]
    }
    sitemap?: boolean
  }
): Collection
```

```ts
import { defineCollection, defineContentConfig, fields } from '@lupinum/ginko-content/config'
import { z } from 'zod'

const articles = defineCollection('articles', {
  type: 'page',
  source: 'articles/**/*.md',
  strict: true,
  schema: z.object({
    title: fields.text().required(),
    date: fields.date().required(),
    draft: fields.boolean()
  })
})

export default defineContentConfig({
  collections: { articles }
})
```

Use `type: 'page'` for route-backed content and `type: 'data'` for data-only collections. Data collections default to `sitemap: false`; set `sitemap: true` only when a data collection should participate in sitemap and prerender route discovery.

## fields

Preferred schema helpers for content fields. They return Zod schemas with extra metadata for CMS integrations.

```ts
fields.text()
fields.textarea()
fields.richtext()
fields.slug({ from?: string })
fields.email()
fields.url()
fields.number()
fields.boolean()
fields.date()
fields.datetime()
fields.select(['draft', 'published'])
fields.object({ ...shape })
fields.array(item)
fields.image()
fields.asset()
fields.file()
fields.relation('authors')
fields.relations('topics')
```

Every helper supports:

```ts
fields.text()
  .label('Title')
  .help('Shown in cards and SEO metadata')
  .localized()
  .required()
```

Plain Zod remains supported as a fallback, but `fields.*` is the recommended API when the schema should also drive CMS forms.

## reference

Declare a reference field from one collection to another.

```ts
reference(target?: string): ZodString
```

```ts
import { defineCollection, defineContentConfig, fields, reference } from '@lupinum/ginko-content/config'
import { z } from 'zod'

const articles = defineCollection('articles', {
  type: 'page',
  source: 'articles/**/*.md',
  schema: z.object({
    title: fields.text().required(),
    author: fields.relation('authors').required(),
    topics: fields.relations('topics')
  })
})

export default defineContentConfig({
  collections: { articles }
})
```

`reference()` is the lower-level Zod marker used by `fields.relation()` internally. Use it directly only when you need plain Zod without CMS metadata. Resolve the target explicitly when you need the referenced document itself.
