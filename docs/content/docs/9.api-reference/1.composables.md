## `useContentPage`

The default Nuxt route-page API. Use it in route components such as `/docs/[...slug].vue`, `/blog/[slug].vue`, and localized landing pages.

```ts
import { docs } from '~/content.config'

const { page, pending } = await useContentPage(docs, {
  locale: 'de',
  fallback: true
})
```

It resolves the current public route, hides stale data during route changes, publishes localized route metadata, raises a default 404, and returns a localized document with `path`, `canonicalPath`, `locale`, `localePaths`, and `resolved` metadata.

Load previous/next links only when the page needs them:

```ts
const { page, previous, next } = await useContentPage(docs, {
  surround: { fields: ['description'] }
})
```

## `useContentOne`

Use `useContentOne()` for explicit single-document reads where the caller owns the selector and missing-state behavior.

Use `useContentResolveOne` when the page owns its missing-state behavior and needs diagnostic metadata:

```ts
const route = useRoute()
const { doc, explain } = await useContentResolveOne(docs, {
  by: { route: route.path },
  locale: 'de',
  fallback: true
})
```

## Unified Query API

The raw typed query API. Use it for dashboards, exact filters, and document access that is not covered by a higher-level helper.

```ts
const page = await one(docs, {
  by: { ref: 'guide.intro' },
  locale: 'de',
  fallback: true
})
```

`by` identifies one document by route path or authored `ref`:

```ts
await one(docs, { locale: 'de', by: { route: '/de/leitfaden' } })
await one(docs, { locale: 'de', by: { path: '/leitfaden' } })
await one(docs, { locale: 'de', by: { ref: 'guide.intro' } })
```

`where` filters result sets:

```ts
const visiblePosts = await many(posts, {
  where: {
    path: { $prefix: '/blog/2026' },
    draft: { $ne: true }
  },
  sort: { date: 'desc' }
})
```

Use `resolveOne()` when debugging route, locale, or fallback behavior:

```ts
const { doc, explain } = await resolveOne(docs, {
  by: { path: route.path },
  locale: 'de',
  fallback: true
})
```

## `useContentMany`

Load a route-safe list for UI pages. It applies the requested locale and adds `path`, `canonicalPath`, `locale`, `defaultLocale`, and `stem` to each item.

```ts
const { locale } = useI18n()
const { data: postList } = await useContentMany(posts, {
  locale,
  where: { draft: { $ne: true } },
  sort: { date: 'desc' }
})
```

`posts` is inferred from the `posts` collection schema in `content.config.ts`. Do not add page-local item interfaces for normal list pages.

Use `item.path` for `<NuxtLink>` and Nuxt UI card links:

```vue
<NuxtLink v-for="post in postList" :key="post.path" :to="post.path">
  {{ post.title }}
</NuxtLink>
```

### Parameters

| Parameter | Type | Purpose |
|---|---|---|
| `collection` | collection handle | Collection to list |
| `options.locale` | `MaybeRefOrGetter<string>` | Required for i18n handles |
| `options.where` | `QueryWhere<T>` | Typed field filter |
| `options.sort` | `SortSpec<T>` | Declarative sort, for example `{ date: 'desc' }` |

## `useContentPagination`

Load one page of a collection plus count and previous/next metadata.

```ts
const route = useRoute()
const {
  data: postList,
  total,
  pageCount,
  hasNext,
  nextPage
} = await useContentPagination(posts, {
  page: () => Number(route.query.page || 1),
  limit: 10,
  sort: { date: 'desc' }
})
```

Use the pure `paginate(handle, options)` helper outside setup code when you do not need `useAsyncData`.

## `useContentBacklinks`

Load documents from source collections that reference a target document.

```ts
const { data: authorPosts } = await useContentBacklinks(authors, {
  by: { ref: 'jane-doe' },
  from: posts,
  sort: { date: 'desc' }
})
```

Typed source handles infer fields declared with `reference()`.

## `useContentLocaleSwitch`

Resolve localized switch paths from the active content document.

```ts
const { switchTo } = await useContentLocaleSwitch(docs, {
  by: { route: route.path },
  locale: 'en',
  fallback: true
})
const germanPath = switchTo('de')
```

## `useContentTree`

Load the module-owned navigation tree for a collection and resolve common app links from it.

```ts
import { docs } from '~/content.config'

const { data: tree } = await useContentTree(docs, {
  locale: computed(() => 'de'),
  fields: ['description']
})
```

### Parameters

| Parameter | Type | Purpose |
|---|---|---|
| `collection` | collection handle or `string` | Collection used for the navigation tree |
| `options.locale` | `MaybeRefOrGetter<string \| undefined>` | Limits navigation to one locale |

### Returns

| Field | Purpose |
|---|---|
| `navigation` | Computed collection navigation tree |
| `home()` / `firstPage()` | First routable page in the collection |
| `section(match)` | Root section resolver by index, path, stem, title, or object match |
| `sections()` | Root section list resolver |
| `item(match)` | Recursive item resolver by index, path, stem, title, or object match |

Node resolvers expose `path()`, `firstPage()`, `firstChild()`, `children()`, and `item()`. List resolvers expose `items()`, `paths()`, `firstPages()`, and `firstChildren()`.

Returned paths are already locale-aware and translated-slug-resolved. Do not pass them through `localePath()`.

## `useContentSearchData`

Prepare Nuxt UI `UContentSearch` props from a content collection.

```ts
import { docs } from '~/content.config'

const {
  files,
  searchNavigation,
  searchTerm
} = await useContentSearchData(docs, {
  locale: computed(() => 'en')
})
```

### Parameters

| Parameter | Type | Purpose |
|---|---|---|
| `collection` | collection handle | Collection used for navigation and search sections |
| `options.locale` | `MaybeRefOrGetter<string \| undefined>` | Limits navigation and files to one locale |

### Returns

| Field | Purpose |
|---|---|
| `files` | Search sections for Nuxt UI `UContentSearch` |
| `searchNavigation` | Navigation formatted for `UContentSearch` |
| `navigation` | Compatibility alias for `searchNavigation` |
| `searchTerm` | Writable search term ref for `v-model:search-term` |

The returned navigation is projected for search. Parent pages with children are added as searchable leaves when needed, and the original navigation tree is not mutated.

## `useContentSearch`

Headless search controller for custom comboboxes, modals, command palettes, and results pages.

```ts
const search = await useContentSearch({
  initialQuery: '',
  limit: 8,
  locale: computed(() => 'en')
})

search.setQuery('routing')
search.next()
search.select()
```

### Returns

| Field | Purpose |
|---|---|
| `query` | Writable search term ref |
| `results` | Limited matching results |
| `pending` | `true` while search is loading |
| `error` | Search failure, Pagefind loading error, or disabled-search error |
| `activeIndex` | Current highlighted result index, or `-1` |
| `activeResult` | Current highlighted result, or `null` |
| `hasQuery` / `hasResults` / `isEmpty` | Derived state for rendering |
| `setQuery(value)` / `reset()` | Query controls |
| `next()` / `previous()` / `setActiveIndex(index)` | Highlight controls |
| `select(index?)` | Return a result without prescribing navigation |

## `useContentSearchResults`

Search through the configured MiniSearch, Pagefind, or provider-owned backend from app components.

```ts
const query = ref('')
const { results, pending, error } = await useContentSearchResults(query, {
  locale: computed(() => 'en')
})
```

### Parameters

| Parameter | Type | Purpose |
|---|---|---|
| `query` | `MaybeRefOrGetter<string>` | Search term. Empty or whitespace-only terms return no results. |
| `options.locale` | `MaybeRefOrGetter<string \| undefined>` | Filters results to one locale. |

### Returns

| Field | Purpose |
|---|---|
| `results` | Matching search results with route, title, excerpt, score, optional anchor, and optional locale |
| `pending` | `true` while the active search request is running |
| `error` | Search failure, Pagefind loading error, or disabled-search error |

With the MiniSearch backend, the composable loads the generated JSON index and searches it in the app. With the Pagefind backend, it imports `/pagefind/pagefind.js`, runs Pagefind in the browser, and normalizes hits to the same result shape. With `engine: 'cms'`, it calls the active content provider's search endpoint.

When `content.search` is disabled, `results` is empty, `pending` is `false`, and `error` contains the disabled-search error.
