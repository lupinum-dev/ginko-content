The app-facing composable surface is exactly two functions: `useContentPage` and `useContentSearch`. Everything else — lists, navigation, pagination, backlinks, single-document reads, previous/next, locale switching — is an ordinary Nuxt composition of the pure query functions from `@lupinum/ginko-content/client` with `useAsyncData`. See [Migrating from deleted composables](#migrating-from-deleted-composables) for the one recipe that covers all of them.

## `useContentPage`

The default Nuxt route-page API. Use it in route components such as `/docs/[...slug].vue`, `/blog/[slug].vue`, and localized landing pages.

```ts
import { docs } from '~/content.config'

const { page, pending } = await useContentPage(docs, {
  locale: 'de',
  fallback: true
})
```

It resolves the handle against the current public route, keeps the returned document stable across SSR/hydration, and suppresses stale-page flashes during route changes (the previous page's data is not shown once the route has moved past it). It returns a `LocalizedContentDocument` carrying `route` and `resolution` — see [the document envelope](#the-document-envelope) below.

`useContentPage` deliberately does **not**:

- throw a default 404 (there is no `notFound` option) — check `page.value` yourself and decide;
- mutate `<head>` — call `useSeoMeta()`/`useHead()` yourself from the resolved document;
- perform redirects — compare `page.value.route.requestedPath` and `page.value.route.resolvedPath` and call `navigateTo()` yourself if you want the URL corrected.

```ts
import { createError, navigateTo, useContentPage, useSeoMeta } from '#imports'
import { docs } from '~/content.config'

const { page } = await useContentPage(docs, { fallback: true })

if (import.meta.server && !page.value) {
  throw createError({ statusCode: 404, statusMessage: 'Document not found' })
}

if (page.value?.route.requestedPath && page.value.route.requestedPath !== page.value.route.resolvedPath) {
  await navigateTo(page.value.route.resolvedPath, { redirectCode: 301 })
}

useSeoMeta({
  title: page.value?.title,
  description: page.value?.description
})
```

Load previous/next links only when the page needs them — this performs one documented extra request:

```ts
const { page, previous, next } = await useContentPage(docs, {
  surround: true
})
```

Pass a `surround` options object instead of `true` to choose a `select` projection:

```ts
const { page, previous, next } = await useContentPage(docs, {
  surround: { select: ['title', 'description'] }
})
```

### Returns

| Field | Purpose |
|---|---|
| `page` | The resolved document, or `undefined` while unresolved/not matching the current route |
| `previous` / `next` | Neighbor entries, only populated when `surround` is set |
| `status` / `error` | Nuxt async data state |
| `refresh()` | Re-run the underlying query |

## The document envelope

Every document a query returns — from `useContentPage`, `one`, `many`, `navigation`, `surround`, `backlinks`, and so on — carries a `route` and a `resolution` in place of the old `path`/`localePaths`/`variants` fields:

```ts
interface ContentDocumentRoute {
  requestedPath?: string
  resolvedPath: string
  alternates: Array<
    | { locale: string, path: string, source: 'variant' }
    | { locale: string, path: string, source: 'fallback', resolvedLocale: string }
  >
}

interface ContentDocumentResolution {
  requested: { locale?: string }
  resolved: { locale: string }
  usedFallback: boolean
}
```

- `route.requestedPath` — the selector the app queried with, when there was one.
- `route.resolvedPath` — the document's canonical public path. Use this for `<NuxtLink>`/`navigateTo`.
- `route.alternates` — labeled locale alternates. A `source: 'variant'` entry is a concrete translation; a `source: 'fallback'` entry means that locale falls back to `resolvedLocale`. This is the full replacement for the old `localePaths`/`useContentSwitchLocalePath` — build a locale switcher directly from it:

```vue
<NuxtLink
  v-for="alt in page.route.alternates"
  :key="alt.locale"
  :to="alt.path"
>
  {{ alt.locale }}
</NuxtLink>
```

- `resolution.requested.locale` / `resolution.resolved.locale` / `resolution.usedFallback` — the locale that was asked for versus the locale actually served.

## `useContentSearch`

The sole search composable. It is headless state for a combobox, modal, or command palette, and — when you pass `options.collection` — it also loads that collection's search sections and search-navigation tree (what used to be the separate `useContentSearchData`).

```ts
const search = await useContentSearch({
  initialQuery: '',
  limit: 8,
  locale: computed(() => 'en')
})

search.setQuery('routing')
search.next()
search.select()
```

```ts
import { docs } from '~/content.config'

const {
  files,
  searchNavigation,
  setQuery
} = await useContentSearch({
  collection: docs,
  locale: computed(() => 'en')
})
```

Keep the `collection` call outside `ClientOnly` when a UI (such as Nuxt UI's `UContentSearch`) needs `files`/`searchNavigation` in the prerendered payload.

### Options

| Option | Type | Purpose |
|---|---|---|
| `initialQuery` | `MaybeRefOrGetter<string \| undefined>` | Initial value for the writable `query` ref |
| `limit` | `MaybeRefOrGetter<number \| undefined>` | Caps the exposed `results` array |
| `locale` | `MaybeRefOrGetter<string \| undefined>` | Filters results (and, with `collection`, navigation/files) to one locale |
| `collection` | collection handle or dynamic string name | Also loads this collection's search sections and `searchNavigation`. Omit to use only query-driven `results` — `files`/`searchNavigation` stay empty and no extra request is issued |

### Returns

| Field | Purpose |
|---|---|
| `query` | Writable search term ref |
| `results` | Limited matching results (MiniSearch, Pagefind, or provider-owned search, depending on `content.search.engine`) |
| `pending` | `true` while search is loading |
| `error` | Search failure, Pagefind loading error, or disabled-search error |
| `activeIndex` | Current highlighted result index, or `-1` |
| `activeResult` | Current highlighted result, or `null` |
| `hasQuery` / `hasResults` / `isEmpty` | Derived state for rendering |
| `setQuery(value)` / `reset()` | Query controls |
| `next()` / `previous()` / `setActiveIndex(index)` | Highlight controls |
| `select(index?)` | Return a result without prescribing navigation |
| `files` | This collection's search sections (empty unless `options.collection` is set) |
| `searchNavigation` | This collection's navigation tree, shaped for search UI — the sole name for this data; there is no `navigation` alias |

Each result includes `collection`, so custom result routing can branch on identity instead of URL prefixes:

```ts
const selected = search.results.value[0]

if (selected?.collection === 'docs') {
  await navigateTo(selected.path)
}
```

## Migrating from deleted composables

`useContentOne`, `useContentMany`, `useContentPagination`, `useContentBacklinks`, `useContentResolveOne`, `useContentVariants`, `useContentTree`, `useContentNavigation`, `useContentNeighbors`, `useContentSwitchLocalePath`, `useContentSearchData`, `useContentSearchResults`, `useContentHead`, and `useContentToc` are gone — hard-cut deletions, not deprecated aliases. Each one is a pure query function from `@lupinum/ginko-content/client` paired with `useAsyncData`, using an explicit, stable key and a `watch` array for any reactive input. This is the one recipe; apply it consistently:

```ts
import { useAsyncData } from '#imports'
import { many } from '@lupinum/ginko-content/client'
import { posts } from '~/content.config'

const { locale } = useI18n()

const { data: postList } = await useAsyncData(
  () => `posts:${locale.value}`,
  () => many(posts, { locale: locale.value, sort: { date: 'desc' } }),
  { watch: [locale] }
)
```

| Deleted composable | Replacement |
|---|---|
| `useContentOne(handle, options)` | `one(handle, options)` + `useAsyncData` |
| `useContentMany(handle, options)` | `many(handle, options)` + `useAsyncData` |
| `useContentResolveOne(handle, options)` | `resolveOne(handle, options)` + `useAsyncData` |
| `useContentPagination(handle, options)` | `paginate(handle, options)` + `useAsyncData` |
| `useContentBacklinks(handle, options)` | `backlinks(handle, options)` + `useAsyncData` |
| `useContentNavigation(handle, options)` / `useContentTree(handle, options)` | `navigation(handle, options)` + `useAsyncData` |
| `useContentNeighbors(handle, options)` | `surround(handle, options)` + `useAsyncData`, or `useContentPage(handle, { surround: true })` on a route page |
| `useContentVariants(handle, options)` | not a separate query — read `route.alternates` off any resolved document |
| `useContentSwitchLocalePath()` | `route.alternates` off any resolved document (see [the document envelope](#the-document-envelope)) |
| `useContentSearchData(handle, options)` | `useContentSearch({ collection: handle, ...options })` |
| `useContentSearchResults(query, options)` | `useContentSearch(options)` (drive it with `search.setQuery(...)`) |
| `useContentHead(page)` | call `useSeoMeta()`/`useHead()` yourself from the resolved document's fields |
| `useContentToc(...)` | `extractContentToc(...)` — a pure function, not a composable |

Full examples:

```ts
// useContentResolveOne -> resolveOne + useAsyncData
import { resolveOne } from '@lupinum/ginko-content/client'

const route = useRoute()
const { data } = await useAsyncData(
  () => `resolve-one:${route.path}`,
  () => resolveOne(docs, { by: { route: route.path }, locale: 'de', fallback: true }),
  { watch: [() => route.path] }
)
```

```ts
// useContentPagination -> paginate + useAsyncData
import { paginate } from '@lupinum/ginko-content/client'

const route = useRoute()
const page = computed(() => Number(route.query.page || 1))
const { data } = await useAsyncData(
  () => `posts-page:${page.value}`,
  () => paginate(posts, { page: page.value, limit: 10, sort: { date: 'desc' } }),
  { watch: [page] }
)
```

```ts
// useContentBacklinks -> backlinks + useAsyncData
import { backlinks } from '@lupinum/ginko-content/client'

const { data: authorPosts } = await useAsyncData(
  'author-posts:jane-doe',
  () => backlinks(authors, { by: { ref: 'jane-doe' }, from: posts, sort: { date: 'desc' } })
)
```

```ts
// useContentNavigation / useContentTree -> navigation + useAsyncData
import { navigation } from '@lupinum/ginko-content/client'

const { data: tree } = await useAsyncData(
  'docs-navigation:de',
  () => navigation(docs, { locale: 'de', fields: ['description', 'icon', 'badge'] })
)
```

## Unified Query API

The raw typed query API. Use it for dashboards, exact filters, and document access that is not covered by `useContentPage`/`useContentSearch`. `one`, `many`, `paginate`, `resolveOne`, `surround`, `backlinks`, and `navigation` come from `@lupinum/ginko-content/client` — they are not auto-imported (only `useContentPage` and `useContentSearch` are).

```ts
import { one } from '@lupinum/ginko-content/client'

const page = await one(docs, {
  by: { ref: 'guide.intro' },
  locale: 'de',
  fallback: true
})
```

`by` identifies one document by route path or authored `ref`:

```ts
await one(docs, { locale: 'de', by: { route: '/de/leitfaden' } })
await one(docs, { locale: 'de', by: { path: '/leitfaden' } })
await one(docs, { locale: 'de', by: { ref: 'guide.intro' } })
```

`where` filters result sets:

```ts
import { many } from '@lupinum/ginko-content/client'

const visiblePosts = await many(posts, {
  where: {
    path: { $prefix: '/blog/2026' },
    draft: { $ne: true }
  },
  sort: { date: 'desc' }
})
```

Use `resolveOne()` when debugging route, locale, or fallback behavior:

```ts
import { resolveOne } from '@lupinum/ginko-content/client'

const { doc, explain } = await resolveOne(docs, {
  by: { path: route.path },
  locale: 'de',
  fallback: true
})
```
