---
title: Nuxt app migration recipe
description: A complete Nuxt Content v3 to Ginko migration shape for route pages, lists, search, rendering, and sitemap.
---

Use this recipe when a Nuxt Content v3 app has docs, posts, changelog entries, navigation, search, and public sitemap output. The names are examples; keep your own collection names when they already describe the domain.

## Target state

After migration, the app should follow these rules:

- `@nuxt/content` is not a direct dependency and is not listed in `modules`.
- `content.config.ts` imports helpers from `@lupinum/ginko-content/config`.
- route-backed pages use `useContentPage()`.
- list pages use `useContentMany()`.
- list links use `useContentMany().data[*].path`.
- `<ContentRenderer>` receives the full document.
- layout navigation comes from `useContentNavigation()`.
- search navigation comes from `useContentSearchData().searchNavigation`.
- sitemap output is generated by `@nuxtjs/sitemap` and checked in production builds.

## Dependencies

Install Ginko and keep `zod` as the schema source:

```bash
pnpm remove @nuxt/content
pnpm add @lupinum/ginko-content zod
pnpm add @nuxtjs/sitemap
```

If old packages still appear in the lockfile, check whether they are direct or transitive:

```bash
pnpm why @nuxt/content better-sqlite3 @standard-schema/spec
```

Transitive entries from other Nuxt modules are not migration failures.

## Nuxt config

Use Ginko as the content module and Nuxt Sitemap as the public sitemap writer:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
    '@lupinum/ginko-content',
    '@nuxtjs/sitemap'
  ],
  site: {
    url: 'https://example.com'
  },
  content: {
    sitemap: {
      assert: {
        enabled: true,
        mode: 'both',
        minUrlsPerSitemap: 1,
        requiredCollections: ['docs', 'posts', 'changelog']
      }
    }
  }
})
```

Replace `site.url` with the production domain before release. Raise `minUrlsPerSitemap` once you know the expected route count.

## Content config

Name the Ginko collections, export their handles, and remove Nuxt Studio-only Zod helpers:

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@lupinum/ginko-content/config'
import { z } from 'zod'

export const docs = defineCollection('docs', {
  type: 'page',
  source: 'docs/**/*.md',
  schema: z.object({
    title: z.string(),
    description: z.string().optional()
  })
})

export const posts = defineCollection('posts', {
  type: 'page',
  source: 'blog/**/*.md',
  schema: z.object({
    title: z.string(),
    description: z.string().optional(),
    date: z.string()
  })
})

export const changelog = defineCollection('changelog', {
  type: 'page',
  source: 'changelog/**/*.md',
  schema: z.object({
    title: z.string(),
    description: z.string().optional(),
    date: z.string()
  })
})

export default defineContentConfig({
  collections: { docs, posts, changelog }
})
```

`defineCollection('docs')` is still the collection identity source. Key-derived
identity from the `collections` map is a later cleanup, not part of this
migration.

Plain `zod` does not provide `.editor(...)`. Remove those calls or move editor metadata outside the runtime schema.

## App navigation and search

Keep layout navigation and search navigation separate:

```vue [app.vue]
<script setup lang="ts">
import {
  useContentNavigation,
  useContentSearchData
} from '@lupinum/ginko-content/client'

const { data: docsLayoutNavigation } = await useContentNavigation('docs')
const {
  files,
  searchNavigation,
  searchTerm
} = await useContentSearchData('docs')

provide('navigation', docsLayoutNavigation)
</script>

<template>
  <UApp>
    <NuxtLayout>
      <NuxtPage />
    </NuxtLayout>

    <ClientOnly>
      <LazyUContentSearch
        v-model:search-term="searchTerm"
        :files="files"
        :navigation="searchNavigation"
      />
    </ClientOnly>
  </UApp>
</template>
```

`searchNavigation` is projected for search. Do not provide it to docs layouts.

## Catch-all route pages

Use this shape for route-backed docs pages:

```vue [pages/docs/[...slug\\].vue]
<script setup lang="ts">
import { useContentPage } from '@lupinum/ginko-content/client'
const { page, previous, next } = await useContentPage('docs', {
  surround: { fields: ['description'] }
})

const surround = computed(() => [previous.value, next.value])
</script>

<template>
  <main v-if="page">
    <ContentRenderer :value="page" />
    <UContentSurround :surround="surround" />
  </main>
</template>
```

`useContentPage()` owns route lookup, async data, stale-route hiding, not-found handling, locale route state, and opt-in neighbor data.

## Single-slug route pages

Use the same page API for posts, versions, and other one-segment routes:

```vue [pages/blog/[slug\\].vue]
<script setup lang="ts">
import { useContentPage } from '@lupinum/ginko-content/client'

const { page: post, previous, next } = await useContentPage('posts', {
  surround: {
    fields: ['description']
  },
  notFound: () => ({
    statusCode: 404,
    statusMessage: 'Post not found',
    fatal: true
  })
})

const surround = computed(() => [previous.value, next.value])
</script>

<template>
  <article v-if="post">
    <ContentRenderer :value="post" />
    <UContentSurround :surround="surround" />
  </article>
</template>
```

If sitemap or navigation includes `/changelog/:slug`, the app needs a matching `pages/changelog/[slug].vue` route using the same pattern.

## List and index pages

Use `useContentMany()` for list pages. It scopes the query to the active locale and returns route-safe `path` values for UI links:

```vue [pages/blog/index.vue]
<script setup lang="ts">
import { posts } from '~/content.config'

const { locale } = useI18n()
const { data: postList } = await useContentMany(posts, {
  locale,
  sort: { date: 'desc' }
})
</script>

<template>
  <ul>
    <li v-for="post in postList" :key="post.path">
      <NuxtLink :to="post.path">
        {{ post.title }}
      </NuxtLink>
    </li>
  </ul>
</template>
```

Use `useContentPage()` for route-backed index content and `useContentMany()` for repeated list items. Do not pass `page.body` to `<ContentRenderer>`.

## Final scan

Run the doctor first:

```bash
npx ginko-content doctor
```

Then search for stale Nuxt Content APIs:

```bash
rg "@nuxt/content|queryCollectionItemSurroundings|useContentTree|content\\.database|content\\.preview|content\\.build" app content content.config.ts nuxt.config.ts package.json
```

Expected result:

```txt
no matches
```

## Release verification

Run the app's real release gates:

```bash
pnpm lint
pnpm typecheck
pnpm build
```

The build should print the Ginko sitemap assertion pass message when assertions are enabled. Single-sitemap apps usually emit `.output/public/sitemap.xml`; Nuxt Sitemap i18n multi-sitemap output emits `.output/public/sitemap_index.xml` plus child files under `.output/public/__sitemap__/`. For static hosting, submit `/sitemap_index.xml` directly or configure the host to redirect `/sitemap.xml` to `/sitemap_index.xml`; do not copy the index file to `sitemap.xml`.

Check expected route files and sitemap entries from `.output/public`:

```bash
node - <<'NODE'
const { existsSync, readFileSync } = require('node:fs')

const expected = [
  '/',
  '/docs/getting-started',
  '/blog',
  '/blog/hello-world'
]

const sitemapFiles = [
  '.output/public/sitemap.xml',
  '.output/public/sitemap_index.xml',
  ...(existsSync('.output/public/__sitemap__')
    ? require('node:fs').readdirSync('.output/public/__sitemap__')
        .filter(file => file.endsWith('.xml'))
        .map(file => `.output/public/__sitemap__/${file}`)
    : [])
].filter(existsSync)

const urls = sitemapFiles.flatMap(file => [...readFileSync(file, 'utf8').matchAll(/<loc>(.*?)<\/loc>/g)])
  .map(match => new URL(match[1]).pathname)

const outputFileFor = route =>
  route === '/'
    ? '.output/public/index.html'
    : `.output/public${route}/index.html`

console.log(JSON.stringify({
  sitemapUrls: urls.length,
  expectedRoutes: expected.length,
  missingFromOutput: expected.filter(route => !existsSync(outputFileFor(route))),
  missingFromSitemap: expected.filter(route => !urls.includes(route)),
  extraSitemap: urls.filter(route => !expected.includes(route))
}, null, 2))
NODE
```

Replace `expected` with the route list for your app.
