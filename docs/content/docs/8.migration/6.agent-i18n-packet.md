description: A terse operating manual for agents migrating localized Nuxt Content v3 apps to Ginko.

Use this packet when the app has translated routes, translated content files, search, and sitemap output.

## Required end state

- `@nuxtjs/i18n`, `@lupinum/ginko-content`, and `@nuxtjs/sitemap` are direct dependencies.
- `@nuxt/content` is not a direct dependency and is not listed in `modules`.
- `nuxt.config.ts` has both `i18n` and `content.i18n`.
- localized collections have `i18n: true`.
- content exists under every `content/<locale>/` folder.
- route pages use `useContentPage()`.
- list pages use `useContentMany()` and `item.path`.
- route links do not manually prepend `/de`, `/fr`, or another locale.
- search uses `useContentSearchData().searchNavigation`.
- sitemap uses Nuxt Sitemap's default i18n index at `/sitemap_index.xml`.
- sitemap has one non-empty child XML file per locale under `/__sitemap__/`.
- search index has records for every locale.

## Before and after map

| If you see | Replace with |
|---|---|
| `@nuxt/content` module | `@lupinum/ginko-content` |
| `@nuxt/content` config imports | `@lupinum/ginko-content/config` |
| `queryCollection(...).path(route.path).first()` (old Nuxt Content v3 API) | `useContentPage('docs')` |
| `queryCollectionItemSurroundings()` | `useContentPage('docs', { surround: true })` |
| `useContentTree()` | `useContentNavigation('docs')` |
| `useContentSearchData()` | `useContentSearchData('docs')` |
| `navigation` from search data | `searchNavigation` |
| raw list `item.path` | `item.path` from `useContentMany()` |
| `<ContentRenderer :value="page.body" />` | `<ContentRenderer :value="page" />` |
| manual `/${locale}${item._path}` | `item.path` from `useContentMany()` |
| `content/en/docs/**/*.md` collection source | `docs/**/*.md` with `i18n: true` |

## Nuxt config

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
    '@nuxtjs/i18n',
    '@lupinum/ginko-content',
    '@nuxtjs/sitemap'
  ],
  site: {
    url: 'https://example.com'
  },
  i18n: {
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    locales: [
      {
        code: 'en',
        language: 'en-US',
        name: 'English'
      },
      {
        code: 'de',
        language: 'de-DE',
        name: 'Deutsch'
      }
    ]
  },
  content: {
    i18n: {
      defaultLocale: 'en',
      locales: ['en', 'de'],
      fallback: {
        de: ['en']
      }
    },
    sitemap: {
      assert: {
        enabled: true,
        mode: 'both',
        minUrlsPerSitemap: 1,
        requiredCollections: ['docs', 'posts', 'versions']
      }
    }
  }
})
```

Decision table:

| Question | Answer |
|---|---|
| Does `i18n.locales[].code` equal `content.i18n.locales[]`? | It must. |
| Does the default locale get a URL prefix? | Only if the Nuxt I18n strategy says so. |
| Should `_path` include the active locale? | No. |
| Should collection sources include `en/` or `de/`? | No. |
| Should every collection be i18n-aware? | Yes, when that collection has translated files. |
| Should `sitemap.xml` be forced with route rules? | No. Validate `/sitemap_index.xml` and child sitemaps. |

## Content config

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@lupinum/ginko-content/config'
import { z } from 'zod'

export const docs = defineCollection('docs', {
  type: 'page',
  source: 'docs/**/*.md',
  i18n: true,
  schema: z.object({
    title: z.string(),
    description: z.string().optional()
  })
})

export const posts = defineCollection('posts', {
  type: 'page',
  source: 'posts/**/*.md',
  i18n: true,
  schema: z.object({
    title: z.string(),
    description: z.string().optional(),
    date: z.string()
  })
})

export const versions = defineCollection('versions', {
  type: 'page',
  source: 'versions/**/*.md',
  i18n: true,
  schema: z.object({
    title: z.string(),
    description: z.string().optional(),
    date: z.string()
  })
})

export default defineContentConfig({
  collections: { docs, posts, versions }
})
```

Keep `defineCollection('docs')` as the current collection identity source.
Key-derived identity from the `collections` map is parked for later.

## App search and navigation

```vue [app.vue]
<script setup lang="ts">
import {
  useContentNavigation,
  useContentSearchData
} from '@lupinum/ginko-content/client'

const { locale } = useI18n()

const { data: layoutNavigation } = await useContentNavigation('docs', {
  locale
})
const {
  files,
  searchNavigation,
  searchTerm
} = await useContentSearchData('docs', {
  locale
})

provide('navigation', layoutNavigation)
</script>

<template>
  <NuxtLayout>
    <NuxtPage />
  </NuxtLayout>

  <ClientOnly>
    <LazyUContentSearch
      v-model:search-term="searchTerm"
      :files="files"
      :navigation="searchNavigation"
    />
  </ClientOnly>
</template>
```

## Route page

```vue [pages/docs/[...slug\\].vue]
<script setup lang="ts">
import { useContentPage } from '@lupinum/ginko-content/client'
const { page, surround } = await useContentPage('docs', {
  surround: { fields: ['description'] }
})
</script>

<template>
  <main v-if="page">
    <ContentRenderer :value="page" />
    <UContentSurround :surround="surround" />
  </main>
</template>
```

## List page

```vue [pages/posts/index.vue]
<script setup lang="ts">
import { posts } from '~/content.config'

const { locale } = useI18n()
const { data: postList } = await useContentMany(posts, {
  locale,
  sort: { date: 'desc' }
})
</script>

<template>
  <NuxtLink
    v-for="post in postList"
    :key="post.path"
    :to="post.path"
  >
    {{ post.title }}
  </NuxtLink>
</template>
```

## Doctor

Run after the app builds:

```bash
pnpm build
npx ginko-content doctor --i18n
```

Expected clean output:

```txt
Ginko Content doctor: ok
Root: /absolute/project/path

Info (1)
- .output/public/sitemap_index.xml: Sitemap mode: Nuxt Sitemap i18n multi-sitemap (2 child sitemaps, 20 URLs).
  Check: Submit "/sitemap_index.xml". Child sitemaps: __sitemap__/de-DE.xml (10 URLs), __sitemap__/en-US.xml (10 URLs).
```

Blocking findings include:

| Finding | Fix |
|---|---|
| `content.i18n runtime config is missing` | Add `content.i18n` in `nuxt.config.ts` |
| `Collection "docs" is not marked as i18n-aware` | Add `i18n: true` to the collection |
| `Content locale folder "de" is missing` | Add `content/de/...` translated files |
| `Repeated locale prefix "/de/de/" found` | Stop manually prefixing `_path` |
| `Generated sitemap is missing non-empty locale sitemap` | Fix Nuxt Sitemap/i18n config and rebuild |
| `Search index has no records for locale "de"` | Ensure search data is generated from i18n collections |

## Artifact verification

Use this when the doctor reports output issues or before release:

```bash
node <<'EOF'
const { existsSync, readFileSync, readdirSync } = require('node:fs')
const locales = ['en', 'de']

const sitemapDir = '.output/public/__sitemap__'
const sitemapFiles = existsSync(sitemapDir)
  ? readdirSync(sitemapDir).filter(file => file.endsWith('.xml'))
  : []

const searchFile = '.output/public/api/_content/search/index.json'
const rawSearch = existsSync(searchFile)
  ? JSON.parse(readFileSync(searchFile, 'utf8'))
  : []
const records = Array.isArray(rawSearch) ? rawSearch : rawSearch.records || []

const report = {
  sitemaps: Object.fromEntries(locales.map(locale => [
    locale,
    sitemapFiles.some(file => file.startsWith(locale))
  ])),
  search: Object.fromEntries(locales.map(locale => [
    locale,
    records.filter(record => record.locale === locale || record._locale === locale).length
  ]))
}

console.log(JSON.stringify(report, null, 2))
EOF
```

Expected shape:

```json
{
  "sitemaps": {
    "en": true,
    "de": true
  },
  "search": {
    "en": 10,
    "de": 10
  }
}
```

The numbers are app-specific. Each locale count must be greater than zero.

Nuxt Sitemap's default i18n output is a sitemap index, not a single root XML file:

```txt
.output/public/sitemap_index.xml
.output/public/__sitemap__/en-US.xml
.output/public/__sitemap__/de-DE.xml
```

If `.output/public/sitemap.xml/` exists as a generated redirect directory, ignore that artifact and submit `/sitemap_index.xml`. Do not add `routeRules`, `nitro.prerender.ignore`, or `sitemap.autoI18n: false` unless the app has a hosting-specific requirement that rejects sitemap indexes.
