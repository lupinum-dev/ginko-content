Use this packet when you need to migrate with the least possible guessing.

## Required end state

- no direct `@nuxt/content` dependency
- no `@nuxt/content` entry in `nuxt.config.ts`
- route pages use `useContentPage()`
- list pages pair `many()` with `useAsyncData`
- list links use `item.route.resolvedPath` from `many()`
- `<ContentRenderer>` receives the full document
- app navigation pairs `navigation()` with `useAsyncData`
- search UI navigation uses `useContentSearch({ collection }).searchNavigation`
- production build and sitemap verification pass

## Replacement map

| If you see | Replace with |
|---|---|
| `@nuxt/content` in `modules` | `@lupinum/ginko-content` |
| `@nuxt/content` config imports | `@lupinum/ginko-content/config` |
| `@nuxt/content/server` | `@lupinum/ginko-content/server` |
| `queryCollection(...).path(route.path).first()` (old Nuxt Content v3 API) | `useContentPage(docs)` |
| `queryCollectionItemSurroundings()` | `useContentPage(docs, { surround: true })` |
| `useContentTree()` / `useContentNavigation()` | `navigation(docs)` paired with `useAsyncData` |
| `useContentSearchData()` | `useContentSearch({ collection: docs })` |
| `post.path` from raw list queries | `post.route.resolvedPath` from `many()` |
| `page.seo?.title` | `page.title`, or custom schema field |
| `<ContentRenderer :value="page.body" />` | `<ContentRenderer :value="page" />` |
| `z.string().editor(...)` | `z.string()` plus external editor metadata |

## Package and module

```bash
pnpm remove @nuxt/content
pnpm add @lupinum/ginko-content zod
pnpm add @nuxtjs/sitemap
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
    '@lupinum/ginko-content',
    '@nuxtjs/sitemap'
  ],
  site: {
    url: process.env.NUXT_PUBLIC_SITE_URL || 'https://docs.ginko-content.dev'
  },
  content: {
    sitemap: {
      assert: {
        enabled: true,
        mode: 'both',
        requiredCollections: ['docs', 'posts']
      }
    }
  }
})
```

## Content config

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@lupinum/ginko-content/config'
import { z } from 'zod'

export const docs = defineCollection({
  type: 'page',
  source: 'docs/**/*.md',
  schema: z.object({
    title: z.string(),
    description: z.string().optional()
  })
})

export const posts = defineCollection({
  type: 'page',
  source: 'blog/**/*.md',
  schema: z.object({
    title: z.string(),
    description: z.string().optional(),
    date: z.string()
  })
})

export default defineContentConfig({
  collections: { docs, posts }
})
```

Use the `collections` map key as the collection identity. Do not repeat the
collection name in `defineCollection()` unless preserving old code temporarily.

Keep `type: 'data'` for data collections. Data collections do not produce sitemap routes by default.

## App search and navigation

```vue [app.vue]
<script setup lang="ts">
import { useAsyncData } from '#imports'
import { navigation, useContentSearch } from '@lupinum/ginko-content/client'
import { docs } from '~/content.config'

const { data: docsLayoutNavigation } = await useAsyncData('docs-navigation', () => navigation(docs))
const {
  query,
  files,
  searchNavigation
} = await useContentSearch({ collection: docs })

provide('navigation', docsLayoutNavigation)
</script>

<template>
  <NuxtLayout>
    <NuxtPage />
  </NuxtLayout>

  <ClientOnly>
    <LazyUContentSearch
      v-model:search-term="query"
      :files="files"
      :navigation="searchNavigation"
    />
  </ClientOnly>
</template>
```

Do not pass `searchNavigation` to docs layouts. It is projected for search.

## Route page

```vue [pages/docs/[...slug].vue]
<script setup lang="ts">
import { createError, useContentPage } from '#imports'
import { docs } from '~/content.config'

const { page, previous, next } = await useContentPage(docs, {
  surround: { select: ['description'] }
})

if (import.meta.server && !page.value) {
  throw createError({ statusCode: 404, statusMessage: 'Page not found' })
}
</script>

<template>
  <main v-if="page">
    <ContentRenderer :value="page" />
    <UContentSurround :surround="[previous, next]" />
  </main>
</template>
```

Use the same shape for `pages/blog/[slug].vue`, `pages/changelog/[slug].vue`, and other route-backed content pages. Add the page component when sitemap contains the route. `useContentPage()` never raises a default 404 — check `page.value` yourself, as shown above.

## List page

```vue [pages/blog/index.vue]
<script setup lang="ts">
import { useAsyncData } from '#imports'
import { many } from '@lupinum/ginko-content/client'
import { posts } from '~/content.config'

const { locale } = useI18n()
const { data: postList } = await useAsyncData(
  () => `posts:${locale.value}`,
  () => many(posts, { locale: locale.value, sort: { date: 'desc' } }),
  { watch: [locale] }
)
</script>

<template>
  <NuxtLink
    v-for="post in postList"
    :key="post.route.resolvedPath"
    :to="post.route.resolvedPath"
  >
    {{ post.title }}
  </NuxtLink>
</template>
```

## Validation

Run the built-in validator:

```bash
npx ginko-content doctor
```

Expected clean output:

```txt
Ginko Content doctor: ok
```

Run the stale API scan:

```bash
rg "@nuxt/content|queryCollectionItemSurroundings|useContentOne|useContentMany|useContentHead|useContentTree|useContentNavigation|useContentNeighbors|useContentSwitchLocalePath|useContentSearchData|useContentSearchResults|useContentVariants|content\\.database|content\\.preview|content\\.build" app content content.config.ts nuxt.config.ts package.json
```

Expected result:

```txt
no matches
```

If the lockfile still mentions old packages, check provenance:

```bash
pnpm why @nuxt/content better-sqlite3 @standard-schema/spec
```

Lockfile-only transitive packages are acceptable.

## Release gates

```bash
pnpm lint
pnpm typecheck
pnpm build
```

Expected build signals:

```txt
Content sitemap assertion passed
Prerendered ... routes
/sitemap.xml
Build complete
```

If any content route 404s during prerender, add the matching Nuxt page route or fix the collection source.
