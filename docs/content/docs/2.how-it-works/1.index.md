---
title: How Ginko Works
description: Ginko normalizes content behind collection handles, then derives routes, rendering, navigation, search, and SEO from the same document model.
---

Ginko has one content flow. A file or external provider produces a normalized document, and every public surface reads from that model.

```txt
content files or provider
          │
          ▼
      collection
          │
          ▼
parse → transform → validate → normalize
          │
          ├── resolve pages and locale variants
          ├── run typed queries
          ├── build navigation and surroundings
          ├── produce search records
          └── produce sitemap and prerender routes
```

The flow prevents each feature from inventing its own interpretation of a document or route.

## The five concepts

1. **A collection owns documents.** It defines source, schema, route mount, localization policy, and provider context.
2. **A normalized document is the shared result.** Application code receives the same envelope regardless of provider.
3. **Canonical identity joins locale variants.** Public paths can change by locale without losing document identity.
4. **Queries use one vocabulary.** Client and server code use the same collection-first verbs.
5. **Discovery output is derived.** Navigation, search, sitemap, and prerender routes do not become new content authorities.
