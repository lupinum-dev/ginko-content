---
title: Localization Model
description: Ginko resolves locale variants, fallback, translated slugs, and language-switching routes through canonical document identity.
---

Localization is part of Ginko's content model, not a query convention implemented independently by each page.

## Locale ownership

When `@nuxtjs/i18n` is installed, Nuxt I18n owns the active application locale and URL strategy. Ginko owns content-specific behavior:

- which collections are localized;
- how locale variants share identity;
- which fallback chain applies;
- whether slugs are shared or translated;
- how content routes map into the active Nuxt locale strategy.

## Requested and resolved locale

A page request has a requested locale. The resolved document may come from that locale or from an allowed fallback.

The document envelope records both facts in `resolution`. This lets the UI distinguish an exact translation from fallback content without inventing another lookup.

## Single documents and lists

Single-document resolution uses fallback by default because a page can sensibly show an available translation.

List queries do not mix fallback locales by default. Mixing languages in a blog index or navigation tree is usually surprising, so lists remain scoped to the requested locale unless the query explicitly chooses another behavior.

## Shared and translated slugs

Shared-slug mode keeps the same content path across locales. Translated-slug mode derives identity from numeric prefix chains while allowing each locale to name folders and files differently.

Both modes use the same canonical variant resolver. Language switching is an identity lookup, not a string replacement.

## Route-less server contexts

Server jobs and background code do not have a hidden ambient locale. Pass `locale` explicitly when no request route can provide it.

This makes server results reproducible and prevents the default locale from leaking into provider behavior.

## Invariant

One locale source and one canonical identity must govern page resolution, navigation, search scoping, and sitemap alternates.
