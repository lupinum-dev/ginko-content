---
title: Content Lifecycle
description: Ginko parses, transforms, validates, and normalizes content before any page, query, or derived surface consumes it.
---

The content lifecycle has one direction: source input becomes a normalized document, then public features consume that document.

## 1. Discover source input

The filesystem provider matches files against collection sources. Supported authored formats include Markdown, MDC, YAML, JSON, and CSV.

An external provider starts later in the flow. It returns raw documents through the provider contract instead of asking Ginko to scan its storage.

## 2. Parse

Ginko parses frontmatter and body content. Markdown and MDC become a renderable syntax tree. Structured files become data documents.

Parsing answers what the source contains. It does not decide the final public route or active locale.

## 3. Transform

Configured Markdown plugins and transformers modify the parsed document. This is the place for syntax-level behavior such as highlighting, table-of-contents extraction, or project-specific AST transforms.

Transformers must remain deterministic. Rebuilding the same source and configuration should produce the same document.

## 4. Validate

Collection schemas validate authored fields. Strict validation can reject unknown or invalid frontmatter rather than allowing malformed content to reach page components.

Validation belongs at ingestion because every later surface should consume the same accepted shape.

## 5. Normalize

Ginko adds the document envelope and route facts used by public APIs. Normalization establishes collection ownership, canonical identity, locale, public path, resolution metadata, and available route variants.

Providers return source facts; Ginko derives public route policy. A provider should not duplicate application-specific locale prefixes or sitemap projection.

## 6. Consume

Normalized documents feed:

- `useContentPage` and `<ContentRenderer>`;
- `one`, `many`, and `paginate`;
- navigation and surroundings;
- MiniSearch, Pagefind, or provider-owned search;
- sitemap entries and prerender route discovery;
- agent-readable Markdown output.

## Invariant

No public surface should reinterpret the original file independently. If navigation and a page disagree about a route, the fix belongs in normalization or route projection, not in frontend glue.
