---
title: Documents, Routes, and Identity
description: Ginko separates a document's stable canonical identity from its locale-specific content path and public route.
---

A content file, normalized document, canonical identity, content path, and public route are related values, but they are not interchangeable.

## The terms

| Term | Meaning |
| --- | --- |
| Source file | Authored filesystem input such as `content/en/docs/1.introduction.md` |
| Document | The normalized result returned by Ginko |
| `canonicalKey` | Stable, locale-agnostic join key shared by document variants |
| `contentPath` | Locale-specific content route before the Nuxt locale prefix |
| `path` | Public path for the resolved document variant |
| `ref` | Optional human-authored stable reference alias |
| Route variant | One locale-specific path for the same canonical document |

## Canonical identity

Locale variants of one conceptual page share `canonicalKey`. Ginko uses that key to:

- resolve locale fallback;
- switch to the equivalent page in another locale;
- merge localized navigation;
- produce reciprocal sitemap alternates.

`canonicalKey` is public but opaque. Do not parse it or render it as a URL. Use `page.path` for links.

## Shared slugs

Shared-slug mode is the default. Locale variants use the same locale-agnostic content path:

```txt
content/en/docs/getting-started.md
content/de/docs/getting-started.md
```

Both variants represent the same canonical document.

## Translated slugs

Translated-slug mode uses numeric prefix chains to preserve identity while names change:

```txt
content/en/1.docs/1.getting-started.md
content/de/1.dokumentation/1.erste-schritte.md
```

Both files share the numeric identity `1/1`. Changing a numeric prefix changes identity; changing the translated name does not.

## Authored references

Use `ref` frontmatter when content needs a stable human-readable alias independent from route names:

```md
---
title: Getting started
ref: guide:getting-started
---
```

Authors do not write `canonicalKey` values. Ginko maps paths and `ref` aliases to canonical identity at the boundary.

## Invariant

Never implement language switching by replacing a locale prefix in the current URL. Resolve the target route through the page's variants or Ginko's locale-aware helpers.
