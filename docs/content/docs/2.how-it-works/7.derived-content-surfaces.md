---
title: Derived Content Surfaces
description: Navigation, search, sitemap, prerender routes, and caches are rebuildable views of canonical content rather than independent content stores.
---

Ginko derives discovery and deployment output from normalized content. These surfaces may cache results, but they do not become new authorities.

## Navigation

Navigation uses collection route facts, titles, ordering prefixes, folder metadata, and visibility rules. It does not scan public page components for links.

## Surroundings

Previous and next entries use the same collection ordering and route projection as list queries. Surroundings should never return a path that the page resolver would interpret differently.

## Search

MiniSearch records and Pagefind assets derive from rendered or parsed content. Provider-owned search returns normalized search hits with route facts so Ginko can apply public URL policy.

Deleting a search index must not delete content. Rebuilding content must be sufficient to rebuild the index.

## Sitemap

Ginko supplies content-backed sitemap entries. `@nuxtjs/sitemap` owns XML generation, sitemap indexes, and robots integration.

Localized sitemap alternates come from the same canonical variant graph used by page resolution and language switching.

## Prerender routes

Page collections contribute eligible public routes. Drafts, partials, excluded collections, and route policy are applied before the final route list reaches Nitro.

## Caches

Filesystem parse caches and provider response caches may improve work, but cache state is derived. Providers can attach dependency hints; cache adapters apply response policy and invalidation.

## Rebuild test

A derived surface is valid when these statements are true:

1. It can be discarded without losing authored content.
2. Its inputs are documented.
3. Rebuilding from canonical state produces the expected result.
4. Tests protect the relationship between source and derivative.
