title: From Nuxt Content v2
description: Move from v2-style APIs to the Ginko collection-first surface.
---

Ginko keeps filesystem-first authoring, but the public runtime surface is stricter. Most migrations replace implicit page/query behavior with collection-first APIs.

## The hard cuts

- `content.config.ts` defines collections and schema through `defineContentConfig(...)`
- `nuxt.config.ts` owns runtime markdown, i18n, search, and sitemap behavior
- `useContentPage(collection)` is the default route-backed page API
- `many(collection, options)` is the list query API
- legacy fetch/render components are gone in favor of explicit queries plus `<ContentRenderer>`

When you are done, route-backed pages should load through `useContentPage()`, lists should query with `many()` paired with `useAsyncData`, and content shape should live in `content.config.ts`.

## Query migration

Ginko queries take a single options object rather than a chainable builder. There is no `.where()`/`.sort()`/`.select()`/`.find()` chain to port to — replace the whole call with `one(collection, options)` or `many(collection, options)`:

| Older shape | Ginko shape |
|---|---|
| `.where({ _path: path })` | `useContentPage(collection)` for route pages or `one(collection, { by: { path } })` for raw reads |
| `.where({ published: true })` | `many(collection, { where: { published: true } })` |
| `.sort({ date: -1 })` | `many(collection, { sort: { date: 'desc' } })` |
| `.only(['title'])` | `many(collection, { select: ['title'] })` |
| `.find()` | `await many(collection, options)` — already returns the array |
| `.findOne()` | `await one(collection, options)` — already returns the document or `null` |

See [Query API](/docs/reference/query-api) for the full `where`/`sort`/`select` shape.

## Rendering migration

Before:

```vue
<script setup lang="ts">
const route = useRoute()
</script>

<template>
  <ContentDoc collection="docs" />
</template>
```

After:

```vue
<script setup lang="ts">
import { docs } from '~/content.config'

const { page } = await useContentPage(docs)
</script>

<template>
  <ContentRenderer v-if="page" :value="page" />
</template>
```
