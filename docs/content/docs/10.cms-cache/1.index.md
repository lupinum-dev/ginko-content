---
title: CMS Cache and Invalidation
description: Build provider-neutral response caching and precise CMS invalidation with cache hints, tags, paths, and adapters.
---

Ginko treats CMS caching as a contract between three owners:

```txt
provider owns content truth and dependency hints
Ginko collects hints during a request
cache adapter applies response caching and purges host caches
CMS publish sends exact tags and paths to invalidate
```

The core rule is conservative: stale published content is worse than extra purges. Over-invalidate aggregate routes first, then tighten dependency tracking when the provider has enough data.

## The moving parts

| Part | Owner | Job |
|---|---|---|
| Provider | CMS/source package | Return content plus cache hints with `withContentCache()` |
| Request collector | Ginko runtime | Merge all hints produced while rendering one response |
| Cache adapter | App/platform integration | Apply headers/runtime cache behavior and purge host caches |
| Revalidation endpoint | Ginko runtime | Accept authenticated `{ tags, paths }` payloads |
| CMS publish flow | CMS/source package | Compute changed tags and affected paths |

## Configure a cache-aware app

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/ginko-content'],
  content: {
    provider: 'custom-cms',
    providers: {
      'custom-cms': '~/server/cms-provider'
    },
    cache: '~/server/content-cache',
    revalidate: {
      token: process.env.GINKO_CONTENT_REVALIDATE_TOKEN!
    }
  }
})
```

`content.revalidate.token` is required before Ginko registers the built-in revalidation endpoint. The token is the shared signing secret for production publish delivery.

Production revalidation is signed by default. Send:

```txt
x-ginko-revalidation-event: <event id>
x-ginko-signature-timestamp: <unix milliseconds>
x-ginko-signature: sha256=<hmac hex>
```

The signature input is:

```txt
<timestamp>.<event id>.<raw request body>
```

using HMAC-SHA256 with `content.revalidate.token` as the secret. The token is
not sent as a header for signed delivery.

Token-only revalidation is only for local or explicitly trusted development
setups. Enable it with `content.revalidate.allowUnsigned: true`, then send the
token as either `x-ginko-revalidate-token: <token>` or
`authorization: Bearer <token>`.

## Return cache hints from a provider

Use `withContentCache(data, hint)` from `#content/server`. The wrapper is explicit so content fields named `data` or `cache` cannot be confused with provider metadata.

```ts [server/cms-provider.ts]
import { withContentCache, type ContentProvider } from '#content/server'

export default {
  name: 'cms',
  capabilities: {
    query: {
      operators: ['$eq'],
      pagination: ['offset']
    }
  },
  async query(event, query) {
    const response = await executeCmsQuery(query)

    return withContentCache(response, {
      tags: [
        `collection:${query.collection}`
      ],
      maxAge: 300,
      swr: 60
    })
  }
} satisfies ContentProvider
```

Cache hints merge across every content read in the request:

- tags and paths dedupe and accumulate
- `maxAge` and `swr` use the safest shortest value
- newest `lastModified` wins
- last `etag` wins
- `cache: false` opts the whole response out of public caching
- preview requests never produce public cache hints

## Standard tags

Use stable tags so providers, CMS publish hooks, and adapters can reason about the same dependency graph:

| Tag | Meaning |
|---|---|
| `entry:{collection}:{id}` | One content entry |
| `collection:{collection}` | Any list or query over a collection |
| `route:{path}` | One rendered public route |
| `nav:{collection}:{locale}` | Navigation tree |
| `search:{locale}` | Provider-owned search result/index |
| `sitemap` | Sitemap output |
| `site-data:{key}:{locale}` | Shared site data |

When a page renders referenced content, include both the page and referenced entry tags.

The `id` segment should be a public dependency key. Prefer a stable CMS ID or
authored ref; use a database entry ID only as a fallback. Do not use title,
slug, or translated route path as the entry identity.

```txt
/blog/post-1
  entry:blog:post-1
  entry:authors:alice
  collection:blog
  route:/blog/post-1
```

If `authors/alice` changes, every route that rendered `entry:authors:alice` must be invalidated.

## Implement a cache adapter

The adapter is app/platform code. It can translate hints into headers, runtime cache storage, CDN tags, Vercel ISR calls, or a no-op in development.

```ts [server/content-cache.ts]
import { setHeader } from 'h3'
import {
  contentCacheHeaders,
  type ContentCacheAdapter
} from '#content/server'

export default {
  name: 'example-cache',
  apply(event, hint) {
    const headers = contentCacheHeaders(hint)
    for (const [name, value] of headers) {
      setHeader(event, name, value)
    }
    if (hint.tags?.length) {
      setHeader(event, 'Cache-Tag', hint.tags.join(','))
    }
  },
  async invalidate(input) {
    await purgeCache(input)
  }
} satisfies ContentCacheAdapter
```

Path-only platforms such as Vercel ISR need explicit paths. Resolve tags to paths before calling a path-only adapter.

## Revalidate after publish

The CMS should emit what changed, not “clear everything”.
For path-only platforms, the CMS/provider must expand dependencies before
delivery and include every affected public path. When a publish changes a
route, send both the old public path and the new public path.

```ts
await fetch('https://site.example.com/api/_content/revalidate', {
  method: 'POST',
  headers: {
    'content-type': 'application/json',
    'x-ginko-revalidation-event': eventId,
    'x-ginko-signature-timestamp': timestamp,
    'x-ginko-signature': `sha256=${signature}`
  },
  body: JSON.stringify({
    eventId,
    idempotencyKey,
    reason: 'publish',
    tags: [
      'entry:authors:alice',
      'collection:authors',
      'search:en'
    ],
    paths: [
      '/authors/alice',
      '/blog/post-1',
      '/blog/post-2',
      '/blog'
    ]
  })
})
```

The endpoint:

- is not registered without `content.revalidate.token`
- requires signed delivery by default
- accepts token-only delivery only when `allowUnsigned: true`
- rejects invalid tokens/signatures before reading provider/cache state
- normalizes paths to leading-slash form
- calls the configured Content cache adapter exactly once
- calls the configured cache adapter `invalidate(input)` when configured
- fails when neither provider nor adapter handled invalidation
- clears the built-in search-record cache after successful invalidation

## Provider contract tests

CMS providers should run the official provider contract helper in their own test
suite:

```ts
import {
  createDefaultProviderFixture,
  createProviderFixtureEvent
} from '@lupinum/ginko-content/testing/provider-fixture'
import {
  runProviderContractSuite
} from '@lupinum/ginko-content/testing/provider-contract'
import { toContentProviderQuery } from '@lupinum/ginko-content/provider'

const fixture = createDefaultProviderFixture()
const provider = createCmsProviderForFixture(fixture)

// Every advertised operator and pagination mode needs an executable probe.
runProviderContractSuite({
  name: 'cms-provider',
  expectedProviderName: 'cms',
  loadProvider: async () => provider,
  createEvent: () => createProviderFixtureEvent({ fixture, provider }),
  expectedCapabilities: provider.capabilities,
  operatorProbes: {
    $eq: {
      positive: toContentProviderQuery({
        collection: 'docs',
        where: { title: { $eq: 'Intro' } }
      })
    }
  },
  paginationProbes: {}
})
```

The contract fixture covers query behavior, raw route facts, optional operation
presence, cache hints, and failure paths.

## Vercel ISR

Vercel ISR is application integration, not a built-in Ginko adapter. Implement
`ContentCacheAdapter` in the application and translate invalidated public paths
to the deployment's revalidation API. Tag-only invalidation must first be
resolved to paths by the provider or application dependency graph.

Configure Nitro ISR route rules separately:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/blog/**': {
      isr: {
        expiration: 300,
        allowQuery: [],
        passQuery: false
      }
    }
  },
  nitro: {
    preset: 'vercel',
    vercel: {
      config: {
        bypassToken: process.env.VERCEL_BYPASS_TOKEN
      }
    }
  }
})
```

## Author dependency example

Fixture:

```txt
authors/alice
blog/post-1..post-5 reference alice
blog/post-6 references bob
```

When `authors/alice.name` changes:

```txt
invalidate /authors/alice
invalidate /blog/post-1..post-5
invalidate /blog if it renders author names
do not invalidate /blog/post-6
```

This is the behavior demonstrated in `examples/advanced/cms-cache-contract`.

## Production checklist

- Configure a revalidation token; never expose it through public runtime config.
- Use shared provider/cache storage for multi-instance deployments.
- Treat in-memory provider state as development-only.
- Include dependency tags for referenced entries.
- Resolve tag-only changes to paths before using path-only platforms.
- Test failed refresh, concurrent reads, stale-while-revalidate, and unrelated-route purges.
- Keep a small hosted smoke app per platform adapter.
