Every `.md` file under `content/` is parsed with a GitHub-Flavored Markdown pipeline plus [MDC](/docs/essentials/mdc). This page covers the plain-Markdown surface; MDC is covered separately.

## Frontmatter

YAML frontmatter sits at the top between `---` fences:

```md [content/articles/hello.md]
---
title: Hello, world
description: A minimal article.
date: 2026-01-15
tags: [intro, markdown]
draft: false
---

# Hello, world
```

Every field becomes available on the document:

```ts
import { one } from '@lupinum/ginko-content/client'

const article = await one(articles, {
  by: { path: '/articles/hello' }
})

article.title       // "Hello, world"
article.description // "A minimal article."
article.date        // "2026-01-15"
article.tags        // ["intro", "markdown"]
```

Without a schema, fields are typed as `unknown`. With a [typed collection](/docs/collections), they become first-class typed fields validated by Zod at build time.

## Headings

Every heading gets an auto-generated `id` from its text. The TOC is built from `h2`–`h4` by default:

```md
# Page title            → not included in TOC
## Section              → id="section"
### Subsection          → id="subsection"
#### Finer subsection   → id="finer-subsection"
```

Access the TOC on the document:

```ts
const page = await one(docs, {
  by: { path: '/docs/intro' }
})
page.body.toc.links // [{ id, text, depth, children }]
```

Tune depth globally in `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    markdown: {
      plugins: [
        ['toc', { depth: 3, searchDepth: 3 }]
      ]
    }
  }
})
```

## Code blocks

Fenced code blocks are highlighted with [Shiki](https://shiki.style):

````md
```ts
export function greet(name: string) {
  return `Hello, ${name}`
}
```
````

### Filenames

Add a filename in square brackets after the language. It renders as a label above the block:

````md
```ts [utils/greet.ts]
export function greet(name: string) {
  return `Hello, ${name}`
}
```
````

### Highlighted lines

Use `{}` after the language to highlight specific lines:

````md
```ts {2,4-6}
export function greet(name: string) {
  if (!name) return 'Hello, stranger'
  return `Hello, ${name}`
}
```
````

### Themes and languages

Configure Shiki in `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    markdown: {
      plugins: [
        ['highlight', {
          theme: {
            default: 'github-light',
            dark: 'github-dark'
          },
          langs: ['bash', 'ts', 'vue', 'json', 'yaml', 'md']
        }]
      ]
    }
  }
})
```

Only languages listed here are bundled. Keep the list tight to minimise bundle size.

## Links

Concrete Markdown links work like any other Markdown renderer:

```md
See the [introduction](/docs/getting-started).
Link to a heading: [Code blocks](#code-blocks).
```

For stable cross-document links, use a `$` reference link and give the target
document a `ref` or `id`:

```md [content/guide/getting-started.md]
---
title: Getting started
ref: docs.getting-started
---
```

```md
Read [Getting started]($docs.getting-started).
Jump to [installation]($docs.getting-started#installation).
```

Ginko resolves `$docs.getting-started` through the content graph when the
document is queried, then `<ContentRenderer>` renders the locale-correct route.
In an i18n site, the same markdown can resolve to `/guide/getting-started` in
English and `/de/leitfaden/einstieg` in German.

`$` links match the same identities as query references: canonical key, `ref`,
and path/source-path candidates. Prefer `ref` for author-written links because
it is short, stable, and independent of translated slugs.

Use configured quick links for app routes that are not content documents:
Content document identities win if a `$` link matches both a document and a
configured quick link.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  i18n: {
    customRoutes: 'config',
    pages: {
      pricing: {
        en: '/pricing',
        de: '/preise'
      }
    }
  },
  content: {
    links: {
      main: {
        pricing: { route: 'pricing' }
      }
    }
  }
})
```

```md
Compare plans on [Pricing]($main.pricing).
```

Ginko passes `pricing` to Nuxt I18n's route resolver at render time, so the
link follows the active locale and the configured i18n routing strategy.

## Images

Standard Markdown image syntax resolves relative to the public directory:

```md
![Architecture](/images/architecture.png)
```

Files placed under `public/images/` are served at `/images/`.

Images render through `ProseImg`. By default, Ginko uses `<NuxtImg>` when Nuxt Image is available and falls back to native `<img>` otherwise. Set `content.markdown.image` to `'img'` or `'nuxt-image'` when you want to force one renderer.

## Runtime AST

Parsed Markdown is stored as one object-shaped AST:

```ts
type MarkdownRoot = {
  type: 'root'
  children: MarkdownNode[]
  toc?: Toc
}
```

Element nodes use `{ type: 'element', tag, props, children }`; text nodes use `{ type: 'text', value }`.

Markdown plugins run through Comark during parsing, but the stored runtime payload is the object AST above. Unified, Remark, and Rehype plugins are not directly compatible unless adapted to this plugin boundary.

## Tables

GFM tables are supported:

```md
| Field     | Type    | Required |
|-----------|---------|----------|
| `title`   | string  | yes      |
| `draft`   | boolean | no       |
```
