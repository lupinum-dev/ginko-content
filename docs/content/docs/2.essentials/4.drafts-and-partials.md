Two conventions let you keep files in `content/` without routing them: drafts (hidden in production) and partials (never routed).

## Drafts

A draft is a page that exists in `content/` but is hidden from production. It's visible in development so authors can preview it.

Two ways to mark a file as a draft:

**Frontmatter flag:**

```md [content/articles/future-work.md]
---
title: Future work
draft: true
---

# Future work
```

**Filename suffix:**

```txt
content/articles/future-work.draft.md
```

Query-time filtering happens automatically: in production, drafts are excluded from `many(handle)` results and from navigation. In development, they're included and rendered with a `draft` badge if your layout opts in.

You can inspect the flag manually:

```ts
const { page } = await useContentPage(articles, {
  fallback: true
})

if (page.value?._draft) {
  // Render a "Draft" indicator
}
```

### Production previews

Production public queries exclude drafts unless the request is in preview mode. Configure a preview token on the server:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    preview: {
      token: process.env.GINKO_CONTENT_PREVIEW_TOKEN
    }
  }
})
```

For app pages and composables, store the matching token in the `previewToken` cookie before refreshing content data:

```ts
const previewToken = useCookie<string | null>('previewToken')

previewToken.value = token
await refreshNuxtData()
```

Ginko forwards that cookie as the `x-nuxt-content-preview` header on content API requests. Direct content API calls may also send the matching `previewToken` query value or `x-nuxt-content-preview` header.

```ts
const draft = await one(articles, {
  by: { path: route.path }
})
```

Do not try to opt drafts back in with `where: { _draft: true }` on public routes. In production, the runtime appends the draft exclusion filter unless preview is enabled.

## Partials

A partial is a file that's parsed but never routed. Production public queries exclude partials, so treat them as internal authoring/support files rather than public page fragments. Two conventions trigger it:

**Underscore-prefixed filename:**

```txt
content/docs/
  _shared-intro.md      → partial
  getting-started.md    → /docs/getting-started
```

**Underscore-prefixed folder** — everything inside becomes a partial:

```txt
content/
  _snippets/
    install.md          → partial
    config.md           → partial
```

Use cases:

- Authoring notes or source fragments that should stay out of routes, navigation, search, and sitemap output
- Preview-only snippets that an authenticated tool can inspect
- Internal files that should travel with content but never publish as pages

### Inspecting a partial

Underscore prefixes are stripped from the generated content path. In development or preview mode, you can inspect a partial with its stripped path:

```ts
const intro = await one(docs, {
  by: { path: '/docs/shared-intro' }
})
```

Do not rely on this as a production public read. In production without preview mode, the runtime excludes `_partial` documents from public queries.

Render a partial only in contexts where you intentionally allow partial reads, such as development tooling or authenticated preview:

```vue
<template>
  <ContentRenderer v-if="intro" :value="intro" />
</template>
```

### Partial metadata

Partials can still carry frontmatter. Use it to parameterise the fragment:

```md [content/_snippets/install.md]
---
command: npx nuxi module add @lupinum/ginko-content
---

Run the following in your project:

`{{ $doc.command }}`
```
