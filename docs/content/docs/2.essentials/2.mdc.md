---
title: MDC
description: Embed Vue components inside Markdown with block and inline syntax.
---

MDC (Markdown Components) lets you render Vue components inside Markdown using a compact, readable syntax. Any component registered under `components/content/` is available.

## Block components

Use `::component-name` for block-level components. The block ends at `::`.

```md
::callout
This is a callout. The body is parsed as Markdown.
::
```

### Props

Pass props on the opening line or as a YAML block:

```md
::callout{tone="warning" icon="i-lucide-flame"}
This uses the `warning` color.
::
```

```md
::callout
---
tone: warning
icon: i-lucide-flame
---
This form is tidier for many props.
::
```

### Named slots

Components with named slots use `#slot-name`:

```md
::card
#title
A callout with a title

#description
Body content goes in the default slot.

A longer paragraph can follow.
::
```

### Nesting

Block components nest with extra colons. Use `:::` for a component inside another block:

```md
::steps
:::step{title="Install"}
```bash
npx nuxi module add @lupinum/ginko-content
```
:::

:::step{title="Use"}
```ts
import { one } from '@lupinum/ginko-content/client'

const page = await one(pages, {
  by: { path: '/' }
})
```
:::
::
```

Each additional nesting level adds one colon.

## Inline components

Use `:component-name` for inline components that live within a paragraph:

```md
Read the :badge[migration guide]{to="/docs/migration"} for details.
```

Inline components do not have slots — their bracketed text is the default slot.

## Component libraries

Ginko itself does not ship a catalog of MDC components. The docs site uses extra components from its app layer, so patterns like callouts or tab groups only work when your app provides matching components.

For example, this docs site renders callouts through its own component stack:

```md
::tip
If you name a file `_shared.md`, it's parsed and queryable but never routed.
::
```

If you want code groups, tabs, or collapsibles, add those components in `components/content/` or bring them in from your UI library.

Code group example with an app-provided component:

````md
::code-group
```bash [pnpm]
pnpm add @lupinum/ginko-content
```

```bash [npm]
npm install @lupinum/ginko-content
```
::
````

## Custom components

Drop a Vue component into `components/content/`:

```vue [components/content/YearInReview.vue]
<script setup lang="ts">
defineProps<{ year: number }>()
</script>

<template>
  <section class="rounded-lg border p-4">
    <h3>{{ year }} in review</h3>
    <slot />
  </section>
</template>
```

Use it in any Markdown file:

```md
::year-in-review{year="2026"}
A recap of the things that shipped.
::
```

Component names are kebab-cased in MDC. `YearInReview.vue` becomes `::year-in-review`.

## Prose overrides

The built-in Prose components — `<ProseH2>`, `<ProseCode>`, `<ProseTable>`, etc. — render plain Markdown. Override any of them by creating a component with the same name in `components/content/`:

```vue [components/content/ProseA.vue]
<script setup lang="ts">
defineProps<{ href: string }>()
</script>

<template>
  <NuxtLink :to="href" class="underline-offset-4 underline">
    <slot />
  </NuxtLink>
</template>
```

Every Markdown link now uses `NuxtLink`.
