title: Navigation
description: Turn a folder tree into ordered navigation without boilerplate.
---

Navigation is derived from the filesystem. Folder names become labels, numeric prefixes set order, and `index.md` (or `.navigation.yml`) describes each folder.

## The basics

Given this tree:

```txt
content/
  docs/
    1.getting-started/
      1.index.md
      2.installation.md
    2.essentials/
      1.markdown.md
      2.mdc.md
```

The content navigation endpoint returns:

```ts
[
  {
    title: 'Getting Started',
    _path: '/docs/getting-started',
    children: [
      { title: 'Introduction', _path: '/docs/getting-started' },
      { title: 'Installation', _path: '/docs/getting-started/installation' }
    ]
  },
  {
    title: 'Essentials',
    _path: '/docs/essentials',
    children: [
      { title: 'Markdown', _path: '/docs/essentials/markdown' },
      { title: 'MDC', _path: '/docs/essentials/mdc' }
    ]
  }
]
```

The returned array is already unwrapped for app use. Ginko does not expose a synthetic top-level `Docs` collection container by default.

Use it in any component through Nuxt data fetching:

```vue [components/DocsSidebar.vue]
<script setup lang="ts">
const { data: nav } = await useAsyncData('docs-nav', () =>
  $fetch('/api/_content/navigation', {
    query: { collection: 'docs' }
  })
)
</script>

<template>
  <ul v-if="nav?.length" class="space-y-1">
    <li v-for="item in nav" :key="item.path">
      <NuxtLink :to="item.path">{{ item.title }}</NuxtLink>
    </li>
  </ul>
</template>
```

## Ordering

Numeric prefixes on files and folders control order without appearing in the URL:

```txt
content/docs/
  1.getting-started/   → first
  2.essentials/        → second
  3.collections/       → third
```

The prefix is stripped from both `_path` and the navigation label. When you don't use prefixes, set `order` in `.navigation.yml` or in the folder's `index.md` frontmatter.

## Folder metadata

A folder describes itself in one of two ways, in this order of preference:

**`index.md` frontmatter** (preferred):

```md [content/docs/collections/index.md]
---
title: Collections
description: Typed content with Zod schemas.
icon: i-lucide-layers
---

# Collections
```

**`.navigation.yml`** (when the folder has no `index.md`):

```yml [content/docs/api-reference/.navigation.yml]
title: API Reference
icon: i-lucide-code
order: 9
```

Valid fields in either source:

| Field | Type | Purpose |
|---|---|---|
| `title` | string | Display label |
| `order` | number | Manual ordering |
| `icon` | string | Iconify icon identifier |
| `hidden` | boolean | Hide from nav, keep routable |
| `badge` | string or object | Label or `{ label, color }` |
| `navigation` | `false` or object | Set to `false` to drop folder from nav |

## Multiple navigations

Load several collection navigations in parallel when your app has multiple content lanes:

```ts
const { data: docsNav } = await useAsyncData('docs-nav',
  () => $fetch('/api/_content/navigation', { query: { collection: 'docs' } })
)

const { data: changelogNav } = await useAsyncData('changelog-nav',
  () => $fetch('/api/_content/navigation', { query: { collection: 'changelog' } })
)
```

## Hiding entries

Three ways to keep a file out of navigation:

**Draft** — `draft: true` in frontmatter hides in production, shows in dev:

```md
---
title: Upcoming feature
draft: true
---
```

**Navigation: false** — keep the page routable, drop it from nav:

```md
---
title: Deep link
navigation: false
---
```

**Partial** — file starts with `_` (e.g. `_shared.md`). Parsed and queryable, but never routed and never in nav. See [Drafts and partials](/docs/essentials/drafts-and-partials).

## Surround Navigation

Use `useContentPage()` for previous/next data when the current route renders a content page:

```vue [pages/docs/[...slug\\].vue]
<script setup lang="ts">
const { previous, next } = await useContentPage('docs', {
  surround: { fields: ['description'] }
})
</script>

<template>
  <nav class="grid gap-4 sm:grid-cols-2">
    <NuxtLink v-if="previous" :to="previous.path">
      {{ previous.title }}
    </NuxtLink>

    <NuxtLink v-if="next" :to="next.path" class="sm:text-right">
      {{ next.title }}
    </NuxtLink>
  </nav>
</template>
```

It returns semantic `previous` and `next` entries with app-ready localized `path` values.
