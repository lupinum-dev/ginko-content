title: Navigation
description: Turn a folder tree into ordered navigation without boilerplate.
---

Navigation is derived from the filesystem. Folder names become labels, numeric prefixes set order, and `index.md` (or `.navigation.yml`) describes each folder.

## The basics

Given this tree:

```txt
content/
  docs/
    1.getting-started/
      1.index.md
      2.installation.md
    2.essentials/
      1.markdown.md
      2.mdc.md
```

The content navigation endpoint returns:

```ts
[
  {
    title: 'Getting Started',
    path: '/docs/getting-started',
    canonicalPath: '/docs/getting-started',
    children: [
      { title: 'Introduction', path: '/docs/getting-started', canonicalPath: '/docs/getting-started' },
      { title: 'Installation', path: '/docs/getting-started/installation', canonicalPath: '/docs/getting-started/installation' }
    ]
  },
  {
    title: 'Essentials',
    path: '/docs/essentials',
    canonicalPath: '/docs/essentials',
    children: [
      { title: 'Markdown', path: '/docs/essentials/markdown', canonicalPath: '/docs/essentials/markdown' },
      { title: 'MDC', path: '/docs/essentials/mdc', canonicalPath: '/docs/essentials/mdc' }
    ]
  }
]
```

The returned array is already unwrapped for app use. Use `path` for links; `_path` is canonical content metadata for debugging and low-level queries. Ginko does not expose a synthetic top-level `Docs` collection container by default.

Use it in app components through `useContentTree()`:

```vue [components/DocsSidebar.vue]
<script setup lang="ts">
import { docs } from '~/content.config'

const { locale } = useI18n()
const { data: nav } = await useContentTree(docs, {
  locale
})
</script>

<template>
  <ul v-if="nav?.length" class="space-y-1">
    <li v-for="item in nav" :key="item.path">
      <NuxtLink :to="item.path">{{ item.title }}</NuxtLink>
    </li>
  </ul>
</template>
```

## Ordering

Numeric prefixes on files and folders control order without appearing in the URL:

```txt
content/docs/
  1.getting-started/   → first
  2.essentials/        → second
  3.collections/       → third
```

The prefix is stripped from both `path` and the navigation label. Navigation ordering is filename/path based today; use numeric prefixes when sibling order matters.

## Folder metadata

A folder describes itself in one of two ways, in this order of preference:

**`index.md` frontmatter** (preferred):

```md [content/docs/collections/index.md]
---
title: Collections
description: Typed content with Zod schemas.
navigation:
  icon: i-lucide-layers
---

# Collections
```

**`.navigation.yml`** (when the folder has no `index.md`):

```yml [content/docs/api-reference/.navigation.yml]
title: API Reference
navigation:
  icon: i-lucide-code
```

Navigation-specific fields in either source:

| Field | Type | Purpose |
|---|---|---|
| `title` | string | Display label |
| `navigation` | `false` or object | Set to `false` to drop the folder from nav, or use an object for nav-only metadata such as `icon` and `badge` |

Top-level metadata fields such as `icon`, `badge`, or `description` are app-owned. Expose them on nav items with `content.navigation.fields`, or put nav-only metadata inside the `navigation` object as shown above. Ginko does not sort navigation by an `order` field; use numeric filename and folder prefixes for ordering.

## Multiple navigations

Load several collection navigations in parallel when your app has multiple content lanes:

```ts
const { data: docsNav } = await useContentTree(docs)

const { data: changelogNav } = await useContentTree(changelog)
```

Use the raw `/api/_content/navigation` endpoint only for advanced integrations. Pass the collection and locale explicitly:

```ts
const nav = await $fetch('/api/_content/navigation', {
  query: {
    collection: 'docs',
    locale: locale.value
  }
})
```

## Hiding entries

Three ways to keep a file out of navigation:

**Draft** — `draft: true` in frontmatter hides in production, shows in dev:

```md
---
title: Upcoming feature
draft: true
---
```

**Navigation: false** — keep the page routable, drop it from nav:

```md
---
title: Deep link
navigation: false
---
```

**Partial** — file starts with `_` (e.g. `_shared.md`). Parsed, never routed, never in nav, and excluded from production public queries. See [Drafts and partials](/docs/essentials/drafts-and-partials).

## Surrounding navigation

Use `useContentNeighbors()` for surround data when the current route renders a content page:

```vue [pages/docs/[...slug\\].vue]
<script setup lang="ts">
import { docs } from '~/content.config'

const route = useRoute()
const { data: surround } = await useContentNeighbors(docs, {
  by: { route: route.path },
  fallback: true
})
</script>

<template>
  <nav class="grid gap-4 sm:grid-cols-2">
    <NuxtLink v-if="surround?.prev" :to="surround.prev.path">
      {{ surround.prev.title }}
    </NuxtLink>

    <NuxtLink v-if="surround?.next" :to="surround.next.path" class="sm:text-right">
      {{ surround.next.title }}
    </NuxtLink>
  </nav>
</template>
```

It returns the neighbours in navigation order with app-ready localized `path` values.
