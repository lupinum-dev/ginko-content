title: Strategies
description: Shared locale folders vs translated slugs.
---

Two common ways to organize multilingual content: shared locale folders, or translated folder and file names backed by numeric prefixes.

## Shared locale folders

Group content under a top-level locale folder. Every locale has the same tree beneath it:

```txt
content/
  en/
    docs/
      getting-started.md
      installation.md
  fr/
    docs/
      getting-started.md
      installation.md
```

- URLs keep the same slug across locales.
- Translators work in one folder per locale.
- This is the lowest-configuration shape when your information architecture is identical everywhere.

Configure it by declaring global i18n:

```ts [content.config.ts]
defineContentConfig({
  i18n: {
    defaultLocale: 'en',
    locales: ['en', 'fr', 'de']
  }
})
```

## Translated slugs

When folder or file names differ per locale, keep numeric prefixes aligned and explicitly enable `translatedSlugs`:

```txt
content/
  en/
    1.guide/
      1.getting-started.md
  de/
    1.leitfaden/
      1.erste-schritte.md
```

```ts [content.config.ts]
defineContentConfig({
  i18n: {
    defaultLocale: 'en',
    locales: ['en', 'de'],
    translatedSlugs: true
  }
})
```

This lets each locale use its own path while still sharing one `_canonicalKey`.

## Collection scope

Collections can opt into the global locale set, or provide their own:

```ts [content.config.ts]
defineContentConfig({
  i18n: {
    defaultLocale: 'en',
    locales: ['en', 'fr']
  },

  collections: {
    docs: defineCollection({
      type: 'page',
      source: 'docs/**/*.md',
      i18n: true
    }),
    authors: defineCollection({
      type: 'data',
      source: 'authors/*.yml',
      i18n: {
        defaultLocale: 'en',
        locales: ['en', 'de']
      }
    })
  }
})
```
