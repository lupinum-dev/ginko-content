---
title: Sitemap and prerender
description: Keep localized static pages, content routes, sitemap entries, and prerender output on one source of truth each.
---

Localized Nuxt apps usually have two kinds of routes:

- Nuxt app pages, such as pricing, privacy, terms, or about pages
- content-backed pages, such as docs and blog articles

Do not put both route types into one app-owned URL table. Let each system own the
routes it can derive correctly.

## Ownership

| Route type | Source of truth | Sitemap source | Prerender source |
|---|---|---|---|
| Static Nuxt pages | `@nuxtjs/i18n` `i18n.pages` | Nuxt Sitemap app/i18n source | Nitro crawler or small app seed routes |
| Content pages | Ginko collection route config and content files | Ginko content sitemap source | Ginko `prerender:routes` integration |

Ginko owns concrete content URLs because it has the content graph, locale
variants, translated slugs, draft state, and `localePaths`.

Nuxt I18n owns static app page paths because those pages are Nuxt route
components. Nuxt Sitemap can reuse that route metadata when static slugs are
translated.

## Recommended setup

Use config-owned custom routes for Nuxt app pages:

```ts [nuxt.config.ts]
import { i18nPages } from './i18n/routes'

export default defineNuxtConfig({
  modules: [
    '@nuxtjs/i18n',
    '@nuxtjs/sitemap',
    '@lupinum/ginko-content'
  ],
  i18n: {
    defaultLocale: 'de',
    strategy: 'prefix_except_default',
    detectBrowserLanguage: false,
    customRoutes: 'config',
    pages: i18nPages,
    locales: [
      { code: 'de', language: 'de-DE', name: 'Deutsch' },
      { code: 'en', language: 'en-US', name: 'English' }
    ]
  },
  content: {
    i18n: {
      defaultLocale: 'de',
      locales: ['de', 'en'],
      fallback: {
        en: ['de']
      },
      translatedSlugs: true
    },
    sitemap: true
  }
})
```

```ts [i18n/routes.ts]
export const i18nPages = {
  index: {
    de: '/',
    en: '/'
  },
  pricing: {
    de: '/preise',
    en: '/pricing'
  },
  privacy: {
    de: '/datenschutz',
    en: '/privacy'
  },
  docs: {
    de: '/dokumentation',
    en: '/docs'
  },
  'docs-slug': {
    de: '/dokumentation/[...slug]',
    en: '/docs/[...slug]'
  },
  blog: {
    de: '/blog',
    en: '/blog'
  },
  'blog-slug': {
    de: '/blog/[slug]',
    en: '/blog/[slug]'
  }
}
```

The docs and blog route component patterns can be listed in `i18n.pages` so
Nuxt I18n can match localized route templates. Do not list every content
document there. Ginko derives concrete docs and blog URLs from content files.

Use `@nuxtjs/sitemap >= 8.0.15 < 9` when you rely on translated static app page
slugs from `i18n.pages`. Older versions may include the pages but fail to attach
cross-locale alternates for pairs such as `/preise` and `/en/pricing`.

## Content config

Keep content route bases in the collection config:

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@lupinum/ginko-content/config'

export const docs = defineCollection({
  type: 'page',
  source: '1.docs/**/*.md',
  i18n: true,
  route: {
    de: '/dokumentation',
    en: '/docs'
  }
})

export const blog = defineCollection({
  type: 'page',
  source: '2.blog/**/*.md',
  i18n: true,
  route: {
    de: '/blog',
    en: '/blog'
  }
})

export default defineContentConfig({
  collections: { docs, blog }
})
```

Page components should load content through Ginko:

```vue [app/pages/docs/[...slug].vue]
<script setup lang="ts">
definePageMeta({ layout: 'docs' })

const { page } = await useContentPage(docs, {
  fallback: true
})
</script>
```

Use content-provided paths for content links:

```vue
<NuxtLink :to="post.path">
  {{ post.title }}
</NuxtLink>
```

Use Nuxt I18n helpers for static app links:

```vue
<NuxtLinkLocale to="pricing">
  Pricing
</NuxtLinkLocale>
```

## Anti-patterns

Do not add app-owned URL arrays for generated content:

```ts
// Avoid this.
const staticRoutes = [
  '/dokumentation',
  '/dokumentation/erste-schritte',
  '/en/docs',
  '/en/docs/getting-started',
  '/blog',
  '/en/blog'
]
```

Do not use `sitemap.urls` as a second static page route table when Nuxt I18n can
describe the route:

```ts
// Avoid this.
sitemap: {
  urls: ['/preise', '/en/pricing', '/datenschutz', '/en/privacy']
}
```

Do not mix route path sources for the same page. If `customRoutes: 'config'` is
enabled, keep translated app paths in `i18n.pages` instead of page-local
`defineI18nRoute()` or `definePageMeta({ i18n })` paths.

## Verification

Run both build modes when the app supports both deployment targets:

```bash
pnpm nuxt build
pnpm nuxt generate
npx ginko-content doctor --i18n
```

Then inspect the generated sitemap XML:

```bash
node - <<'NODE'
const fs = require('node:fs')

const de = fs.readFileSync('.output/public/__sitemap__/de-DE.xml', 'utf8')
const en = fs.readFileSync('.output/public/__sitemap__/en-US.xml', 'utf8')

const checks = [
  [de, '<loc>http://127.0.0.1:3000/preise</loc>', 'href="http://127.0.0.1:3000/en/pricing"'],
  [en, '<loc>http://127.0.0.1:3000/en/pricing</loc>', 'href="http://127.0.0.1:3000/preise"'],
  [de, '<loc>http://127.0.0.1:3000/dokumentation/erste-schritte/installation</loc>', 'href="http://127.0.0.1:3000/en/docs/getting-started/installation"'],
  [en, '<loc>http://127.0.0.1:3000/en/blog/static-docs-pipeline</loc>', 'href="http://127.0.0.1:3000/blog/statische-docs-pipeline"']
]

for (const [xml, loc, alternate] of checks) {
  if (!xml.includes(loc) || !xml.includes(alternate)) {
    throw new Error(`Missing sitemap alternate for ${loc}`)
  }
}
NODE
```

The exact origin depends on `site.url` and the environment used during the
build. The important invariant is that each localized `<loc>` includes
alternates for its translated siblings.

## Troubleshooting

If static app pages appear in the sitemap but translated alternates are
self-only, check these first:

- `@nuxtjs/sitemap` is `8.0.15` or newer
- `i18n.customRoutes` is `'config'`
- translated static paths are in `i18n.pages`
- `sitemap.autoI18n` is not disabled
- Ginko is not setting `sitemap.excludeAppSources = true`

If docs or blog content URLs are missing, fix Ginko content route discovery or
collection configuration. Do not patch the app with hardcoded content route
arrays.
