---
title: Fallbacks
description: Serve a different locale when a translation is missing.
---

A locale rarely has 100% coverage. The fallback chain decides what to serve when a document does not exist in the requested locale.

## The fallback chain

Configure `fallback` as an object keyed by requested locale:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    i18n: {
      defaultLocale: 'en',
      locales: ['en', 'fr', 'de', 'pt-br'],
      fallback: {
        'pt-br': ['pt', 'en'],
        fr: ['en']
      }
    }
  }
})
```

When `/pt-br/docs/advanced` is requested:

1. The module looks for the `pt-br` document.
2. If missing, it tries `pt`.
3. If still missing, it tries `en`.
4. If nothing matches, it returns a 404.

The default locale is still part of the chain when appropriate.

## Inspecting the active locale

Localized documents carry public resolution metadata on `resolved`:

```ts
import { docs } from '~/content.config'

const { page } = await useContentPage(docs, {
  fallback: true
})

page.value?.resolved.requestedLocale
page.value?.resolved.locale
page.value?.resolved.fallback
page.value?.resolved.fallbackLocale
```

That lets you show a fallback notice:

```vue
<script setup lang="ts">
import { docs } from '~/content.config'

const { page } = await useContentPage(docs, {
  fallback: true
})

const isFallback = computed(() => Boolean(page.value?.resolved.fallback))
</script>

<template>
  <UAlert v-if="isFallback" color="warning">
    This page is not available in your locale yet. Showing a fallback.
  </UAlert>

  <ContentRenderer v-if="page" :value="page" />
</template>
```

## Querying without fallback

Pass `fallback: false` to a query to see only documents actually in the locale:

```ts
import { many } from '@lupinum/ginko-content/client'

const french = await many(articles, {
  locale: 'fr',
  fallback: false
})
```

Useful for audits, locale-specific sitemaps, and translator dashboards.
