# I18n

Use this when the Nuxt app serves localized content routes through `@nuxtjs/i18n`
(the recommended setup for route strategy, language switching, and translated
page titles). Content-only localization — declaring locales and fallback purely
through `content.i18n`, without installing `@nuxtjs/i18n` — is also supported;
see ADR-0007. This page covers the `@nuxtjs/i18n`-integrated shape.

## Required shape

- `@nuxtjs/i18n` is installed and registered.
- Nuxt I18n declares `defaultLocale` and `locales`; `content.i18n` may add
  fallback and translated-slug policy.
- Localized collections use `i18n: true`.
- Files live under `content/<locale>/...`.
- List links use `item.route.resolvedPath` from `many()`.
- Raw query filters use `path`.
- Route/page/navigation/search payloads carry a `route` (`requestedPath`, `resolvedPath`, `alternates`) and a `resolution` (`requested.locale`, `resolved.locale`, `usedFallback`), not a bare `path`.
- Build locale-switcher links from `route.alternates`, not manual prefixing.
- Nuxt Sitemap output is validated through the sitemap mode Nuxt actually emits.

## Nuxt config

```ts
export default defineNuxtConfig({
  modules: [
    '@nuxtjs/i18n',
    '@lupinum/ginko-content'
  ],
  i18n: {
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    locales: [
      { code: 'en', language: 'en-US', name: 'English' },
      { code: 'de', language: 'de-DE', name: 'Deutsch' }
    ]
  },
  content: {
    i18n: {
      fallback: {
        de: ['en']
      }
    }
  }
})
```

Do not repeat `locales` or `defaultLocale` in `content.i18n` when Nuxt I18n is
installed. Ginko rejects duplicate locale authority during setup.

## Content config

```ts
import { defineCollection, defineContentConfig } from '@lupinum/ginko-content/config'
import { z } from 'zod'

export const docs = defineCollection({
  type: 'page',
  source: 'docs/**/*.md',
  i18n: true,
  schema: z.object({
    title: z.string(),
    description: z.string().optional()
  })
})

export default defineContentConfig({
  collections: { docs }
})
```

Do not include locale folders in `source`.

## Content tree

```txt
content/
  en/
    docs/
      index.md
      getting-started.md
  de/
    docs/
      index.md
      getting-started.md
```

## Common failure

Do not build links like this:

```ts
`/${locale}${post.unprefixedPath}`
```

Use `many()` and bind `post.route.resolvedPath`:

```vue
<NuxtLink :to="post.route.resolvedPath">
  {{ post.title }}
</NuxtLink>
```

For a locale switcher on a resolved page, read the alternates directly instead of constructing paths:

```vue
<NuxtLink
  v-for="alt in page.route.alternates"
  :key="alt.locale"
  :to="alt.path"
>
  {{ alt.locale }}
</NuxtLink>
```

## Validation

```bash
pnpm build
npx ginko-content doctor --i18n
rg "/de/de/|/fr/fr/" .output/public
```

Nuxt Sitemap can emit a single root sitemap or a sitemap index with children:

```txt
.output/public/sitemap.xml
.output/public/sitemap_index.xml
.output/public/__sitemap__/en-US.xml
.output/public/__sitemap__/de-DE.xml
```

Submit the sitemap URL generated by the configured mode. Do not add route rules,
prerender ignores, or `sitemap.autoI18n: false` only to force a physical sitemap
shape.
